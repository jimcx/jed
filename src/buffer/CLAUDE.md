# buffer

The only place that knows ropey's line model, and the only place text is mutated.

- `pos.rs` — `ByteIdx`, `DisplayCol` and every conversion. `LINE_TYPE = LineType::LF_CR`: LF, CRLF *and lone CR* are line breaks; always pass it to ropey's line APIs (or better, call the helpers here). `line_end` is before the line break; `line_text` excludes it. `display_grapheme` decides how a grapheme is drawn (tab → spaces to the next stop, controls as `^X` width 2, zero-width as `·`); rendering and column maths both use it, so keep them in step. Word movement/`word_range` use three classes (space, word = `is_word_char`: alphanumeric or `_`, punctuation) as VS Code does; `search`'s whole-word check uses `is_word_char` too. `word_at(rope, pos)` is the word run under `pos`, else the one ending at it, else `None` (Cmd+D's word). `each_line(rope, line, backward, f)` visits line contents (no break) with their start, borrowing the chunk when a line sits in one (else a reused scratch string) — the way to scan text without copying the rope. Backward it steps by line index: ropey 2 beta's `Lines::prev()` repeats a line when a line break ends a chunk, so don't use it. `line_bounds(rope, line)` = (start, content end, next line start) in one lookup. `Line` holds one line's bounds and text for many column conversions (`col`, `byte_at_col`, `byte_near_col` — nearest boundary, VS Code's `columnFromVisibleColumn`, for column select); `Line::text()` is its content; `LineWalker` hands out `Line`s in increasing order (`line(index)`, `line_at(pos)`) by stepping ropey's line iterator, seeking only backwards or far ahead — the way to visit the lines of 60k sorted selections. Column maths has a printable-ASCII fast path (columns = byte offsets). `Peek` reads the char after / before positions (`after`, `before`), keeping the last chunk so increasing positions (a sorted selection list) rarely search the rope: auto-close's checks at 63k cursors; `blank_line_start(pos)` (the line start if only spaces / tabs precede `pos`, looking back over those only) and `line_indent(pos, limit)` (the line's leading blanks, `None` if its start is over `limit` bytes back) answer auto-indent's outdent without a line lookup. For LSP: `PosEncoding` (`Utf8`, `Utf16` = the default), `LspPos { line, character }` (`u32`s), `LspWalker` (`pos(p)` for many positions, cheapest increasing: no line lookup on the last one's line, UTF-16 counted only since the last position — document sync's conversions), `lsp_pos(rope, pos, enc)` (one-off), `LspReader` (`byte(p)`: `from_lsp_pos` for many positions through a `LineWalker`, cheapest in increasing line order — diagnostics) and `from_lsp_pos(rope, p, enc)` (clamped: a line past the end → the text's end, a column past the content → its end, inside a char → its start); lines are `LINE_TYPE`'s (LSP's LF / CRLF / CR), UTF-16 counts the line's chars up to the position. For tree-sitter: `ts_point(rope, pos)` (row = LFs before `pos` via `LineType::LF` — ropey's `metric_lines_lf` feature is on for this alone — column = bytes since the last LF) and `chunk_from(rope, at)` (the bytes from `at` to the end of its chunk: how parses read the rope); `bytes_in(rope, start, end)` iterates the chunks of a byte range (query predicates read node text with it); `bytes_in_rev` the same from the end back (bracket matching's backward scan).
- `change.rs` — `ChangeSet`: sorted, non-overlapping changes, **all in pre-edit coordinates** (`debug_assert`ed; empty changes are dropped). Build one with `with_capacity` + `push(start, end, &str)`; all the new text lives in one string inside the set (no allocation per change, cheap clones). `Change { start, end, text }` + `ChangeSet::new` is the owned form tests use. `apply` returns the inverse set. `inserts_line_break()` (any new text with LF/CR: auto-closed pairs stop there). `iter()` gives each change as (start, end, new text length), `changes()` as (start, end, new text); `extent()` = first start, last end, total length change (LSP coalescing). A position on a char boundary maps to one (changes sit on boundaries and insert whole strings), so mapped positions need no rope lookup. `map(pos, Assoc)` moves a pre-edit position through the set (O(changes), tests only); `mapper()` precomputes deltas and maps each position by binary search, stepping forward from the last hit when positions come in order — use it for many positions. A position at the end of a replaced range lands after the new text. From `REBUILD_AT` (256) changes `apply` rebuilds the rope in one pass (`RopeBuilder` + a chunk `Walk` that also collects the removed text) instead of a tree edit per change. Other views use `Assoc::Before`; whole-line paste maps its kept cursors with `After`.
- `undo.rs` — `History` of `Step`s, each a list of `(forward, inverse)` change sets plus `sel_before`/`sel_after`. `record` joins a step when it isn't sealed, the kind matches and isn't `Other`, it's within `GROUP_PAUSE` (1 s) and `sel_before` equals the step's `sel_after`. `undo`/`redo` return the selections to restore and the change sets to apply, in order (the `Buffer` applies them). `state_id()` (0 = as loaded) is what dirtiness compares against.
- `mod.rs` — `Buffer`:
  - `edit(changes, before, after, kind)` applies, records undo, and pushes onto `applied`; `undo`/`redo` push too. All three apply through the private `apply`, which hands `syntax` (`crate::syntax::Syntax`: language + parse tree) each change set with the rope from before it (a cheap clone, only while there is a tree or a parse running), and `syntax.map_highlights`, `diagnostics.map` and `quick_diff.map` every change set (the kept highlight spans and the diagnostics' marks follow the text; `buf.diagnostics` is a `diagnostics::Marks`, set by `lsp::Manager::publish`; `buf.quick_diff` is the gutter's git markers, a `crate::quick_diff::QuickDiff`). Change sets are `Arc`s shared between `applied` and the `History`, never copied. `take_applied()` is drained by `App::sync_views` — every mutation must go through these three methods. Each bumps `revision()` (what the find widget's match cache is keyed on; an undo step applying several sets bumps it once); `sets_applied()` counts every change set applied (completion anchors use it to skip sets their snapshot already has). `track_changes(on)` (set by `lsp::documents` while a server has the document open) makes `apply` also record each set as a `Tracked { before (the rope before it, a cheap clone), changes }`, drained by `take_tracked()` once per loop turn.
  - Dirty = `has_edits()` (`history.state_id() != saved_state`) `|| deleted`. Saving: `begin_save()` seals undo and returns a `SaveJob` (rope clone is cheap, `expected` = `disk()`); `SaveJob::write()` blocks: `Err(SaveError::Conflict)` without writing when the file holds neither `expected` nor the bytes to write (a missing file is recreated), else the atomic write → the written `Stamp` and bytes (file history snapshots them); `finish_save(state, written)` records the state that was written (and `disk`, clearing `deleted` / `disk_conflict`), so edits made during the save stay dirty. `save_epoch()` changes at both ends of a save (disk checks overlapping one are redone).
  - On disk: `disk()` is the file's `Stamp` as last known (`None`: no file); `disk_conflict` the newer version the banner is about; `keep_mine()` accepts it as known and sets `saved_state` to a state no history has (dirty until saved, even if undone); `reload(changes, before, after, DiskMeta)` applies `changes` as one sealed `EditKind::Other` step through `edit`, then marks that state saved and takes the file's stamp, BOM, EOL and read-only state (undo brings the old text back, dirty).
  - `read_only: Option<String>` holds the reason (invalid UTF-8); `deleted` means the file is gone and a save recreates it.
  - `Buffers`: `HashMap<BufferId(u64), Buffer>`; ids are never reused. `dirty()` returns sorted ids.
- `file.rs` — `Stamp` (`of(bytes)`: length + SHA-256, BOM included; `Loaded::stamp`, `None` for a missing file), `read(path)` (`None` = missing), `DiskMeta` (stamp, BOM, EOL, read-only: what a reload sets; `Loaded::meta`), `load`/`decode`: a NUL in the first 8000 bytes (`looks_binary`, which workspace search uses too) → `LoadError::Binary`; BOM stripped and remembered; invalid UTF-8 is decoded lossily and marked read-only; a missing file loads empty. The rope keeps the file's bytes exactly (mixed line endings included); `eol` is only what Enter and paste insert. `encode` = BOM + rope bytes. `atomic_write`: temp file `.{name}.red-{pid}.tmp` in the same dir, fsync, keep permissions, rename, fsync dir; writes through symlinks (canonicalizes the target).

Tests here use `Buffer::from_str` (path `/test.txt`) and `tempfile` for the atomic write.
