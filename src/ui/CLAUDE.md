# ui

Drawing only — but `render` is not pure: it takes `&mut App` and writes back state that input handling relies on.

- `mod.rs::render` computes `layout::compute` regions, draws activity bar → side panel → each group (tab bar, the changed-on-disk banner when its active buffer — or the open buffer of its active diff tab's file — has a `disk_conflict` (`banner::render` on the editor's first row; the editor gets the rest, `GroupHit::banner`), editor or diff view (`diff::render`, `GroupHit::diff`), a text or diff tab's scroll bar in the editor's last column (`scrollbar::render`, `GroupHit::scrollbar`; the editor / diff, `GroupHit::editor` and the find widget get the rest)) from `groups.tree.layout` → dividers → the bottom panel (`regions.panel`, when `ui.panel_visible`) → status bar → find widget (over the active group's editor) → the gutter's peek (`quick_diff::render`; `hits.quick_diff`) → hover popup (`hover::render`, over its group's editor; `hits.hover`) → completion list (`completion::render`; `hits.completion`) → palette → dialog (last, on top). It builds a fresh `HitMap` and stores it in `app.hits`; mouse handling uses the *previous* frame's map. Below 30×4 it draws nothing.
- Each widget's `render` returns what it drew for hit-testing (`activity` → icon rows, `side` → `SideHits` (explorer row area, the Search view's `SearchHit`, the Source Control view's `ScmHit`), `tabs` → `Vec<TabHit>`, `editor` → text rect without the gutter); add new clickable things the same way (a `Hit` variant in `layout.rs`, filled here).
- `editor::render` mutates the `View`: sets `height`/`width` (used by page movement), re-anchors `set_top_line` (the buffer may have changed), and applies `reveal_range` (`reveal_in_center`, Cmd+D), else `reveal_pos` (`scroll_to`, minimal scroll to a position: add cursor above/below, box select), else `reveal_cursor` via `scroll_to_cursor`, clearing them. Commands that move cursors set `view.reveal_cursor = true` and let the next frame scroll.
- `editor::render` takes an `Overlay { focused, find, whitespace }`: `find` is the find widget only for the active group, when its cache `is_current` for this buffer and revision. Find matches on screen come from `FindWidget::matches_in(viewport)` (never a search per frame) and are walked with one index like selections: others `editor.findMatchHighlight`, then the selection, then the match that is the primary selection `editor.findMatch`.
- `find::render` draws the open find widget at the top right of the active editor (≤ 64 wide): the find input (scrolled to its cursor, placeholder when empty, `editor.selection` when all selected), toggles `Aa ab .*` (`find.option` / `find.option.active`), the count; the replace input row; an invalid regex's message (`dialog.error`) on the last row. Terminal cursor in the focused input when `Focus::Find`. Returns `FindHit` (box, replace row, toggle rects) for `hits.find`.
- `side::render` colours explorer rows by git status (`app.git.status`'s `decoration(path)`: the theme key patched over the row style, selected rows too; a changed file's `letter()` at the right edge, folders tinted only) and sets `explorer.height` (used for page up/down) and clamps `explorer.scroll` to the row count; for `SidePanel::Search` it draws the title and hands the rest to `search::render`, returning its `SearchHit` for `hits.search` (`SourceControl`: `scm::render`, its `ScmHit` for `hits.scm`).
- `search::render` draws the Search view: the query input (`find::draw_field`, `dialog.input`), toggles `Aa .*` and the details button `…` (`find.option` / `find.option.active`; `…` lit while the details show or `hidden_filter()`), while `details` the "files to include" / "files to exclude" inputs (full width, one row each), the regex / glob error (`search.error`), a summary (`sideBar.dim`: "1,234 results in 56 files", "Searching…" while running or debouncing, "No results found"), the truncated note (`search.warning`), then the visible rows from `search_view::rows`: file rows (name `search.fileName`, dimmed folder, count `search.count` at the right) and indented lines from `search_view::preview` (matches `search.match`, "…" where cut); the selected row filled with `list.active` while the list has the keys, else `list.inactive` (text keeps its colours, matches and counts their own backgrounds). Sets `search_view.list.height` and re-clamps its scroll. Terminal cursor in the focused input (`search_view.input`) when the side panel has focus and the list doesn't. `draw_line(out, x, y, width, line_match, (base, dim, matched))` is shared with the panel's Locations list. Its `SearchHit` holds the toggles, the `…` button (`details`), the inputs' rects (`inputs`: query, include, exclude; empty while hidden), the list rect and each visible row's `RowKey` (clicks map by key, not row number).
- Text is drawn grapheme by grapheme through `pos::display_grapheme` — the same function column maths uses, so cursor placement and drawing never disagree. Don't measure buffer text any other way (labels in tabs/status/dialogs use `unicode_width` directly).
- Syntax colours: `buf.syntax.spans(rope, top..last+1)` (the editor takes `&mut Buffer` for this cache; no query unless the tree changed or the view left the cached lines) walked with one index like selections; a token's style (`theme.get(KEYS[i])`, a table built once per frame) patches the row style's foreground first, then find-match / selection backgrounds and cursors go over it (VS Code: selection background, token foreground). No tree yet (first parse, too large, plain text) → plain text; while a re-parse runs, the last spans.
- Matched brackets (`Settings::match_brackets`): the heads of the selections on screen go to `view.brackets.get(rope, &syntax, revision, heads)` (cached, see `brackets::Matches`); the sorted positions are walked with one index and patched with `editor.bracketMatch` over the token colour, under find-match / selection backgrounds and cursors.
- Diagnostics: `buf.diagnostics.overlapping(viewport)` flattened by `diagnostics::runs` (the most severe wins; an empty range covers the grapheme there, the one before at a line end, or the cell past an empty line's end), walked with one index; the severity's key (`editorError.foreground`, … : underline + `underline_color`) is patched over the token colour, before find-match / selection backgrounds (which don't touch the underline).
- Rendered whitespace (`Overlay::whitespace`, `App::render_whitespace()`): per visible grapheme, `shows_whitespace` (VS Code's modes; only U+0020 and tab — NBSP and other Unicode spaces draw as themselves; `whitespace_bounds` trims each visible line once for `boundary` / `trailing`, `boundary` looks at the neighbouring bytes, `selection` uses the selection walk) replaces the drawn text with `·`, or a tab's `→` in its first cell and blanks after (same width: columns never change), and patches `editorWhitespace.foreground` over the token colour, under find-match / selection backgrounds; not at a drawn cursor (a secondary, whose reversed cell would take the dim colour as its background, or the primary while `focused`). Control chars keep `editor.whitespace.control`.
- Selections: only `selections.overlapping(viewport)` are looked at (there can be 60k); one index walks that sorted slice while bytes are visited in order; a selection over a line break paints one cell past the line end. Secondary cursors are reversed cells (`editor.cursor.secondary`); the terminal cursor marks the primary, only in the focused group with no prompt or palette open.
- Styles: start from the widget's base key (`editor`, `sideBar`, `dialog`, `statusBar`) and `patch` modifier keys on top (`editor.selection`, `gutter.active`, …). Every key comes from `Theme::dark_plus`; never construct `Color`s here.
- Inline blame (`Overlay::blame` = `app.blame.on`): on the primary cursor's line only, unless the primary selection spans lines, `buf.blame.line(rope, line)` (one binary search per frame) → `blame::label` (the time from `history::now_ms`) drawn `blame::GAP` (3) cells after the line's end in `git.blame.editorDecorationForeground` over the row's style, cut by `blame::fit` with "…" at the text area's right edge (the scroll bar column is outside it); nothing when the line reaches the edge, fewer than `blame::MIN_WIDTH` cells are left, or the label's start is scrolled off to the left. Text never moves.
- Quick diff's markers: `buf.quick_diff.visible(rope, top, last)` (by line, walked with one index) draw in the gutter's last column (the space between the number and the text, `text.x - 1`): `Marker::glyph` (`▎` added / modified, `▁` / `▔` deleted) in its `theme_key`'s foreground on the row's background.
- `quick_diff.rs` — the gutter's peek (`app.quick_diff.peek`, when its group shows its buffer and the change's last line is on screen): below the change (above its first line when there's no room), as wide as the text area ≤ 100; `popup::frame` in the hover's colours, a title row (" 1 line changed to 2", " n lines added / deleted" in `quickDiff.title`; ` Stage Change ` in `quickDiff.action`, ` × `), then `-` removed lines (`diffEditor.removedLineBackground`) and `+` the buffer's lines (`diffEditor.insertedLineBackground`), ≤ 12 rows, "…" in the bottom border when cut. Returns `QuickDiffHit` (box, buttons).
- `palette::render` draws the open palette (top centre: input, optional hint, up to 14 rows with fuzzy-match highlights and right-aligned bindings), sets `palette.height`, clamps `palette.scroll`, puts the terminal cursor in its input and returns `PaletteHit` (box + rows) for `hits.palette`. The editor and explorer show no focus/cursor while it's open.
- `popup.rs` — popups anchored at a buffer position (the hover, the completion list): `cell_of(rope, view, text_rect, pos, tab_width)` (the anchor's screen cell from the view's scroll; `None` off screen, a column scrolled off pulled to the edge), `place(area, anchor, width, height, Side::{Above, Below})` (the preferred side of the anchor's row if it fits, else the other, else the roomier one cut to it; left edge at the anchor, moved left to stay in `area` — the group's editor area), `frame(out, rect, fill, border)` (resets the cells — styles only patch, so the text's squiggles would show through — then fill + box border; returns the inside). The caller returns the rect for the `HitMap` (`Hit` checks it first, so events on it don't fall through).
- `hover.rs` — the hover popup (`app.hover.popup`): only when its group's active tab still shows its buffer and the anchor (the range's start) is on screen; width = widest line ≤ `hover::MAX_WIDTH` and the editor's width − 4 (border + a column of padding each side), rows = `hover::wrap` ≤ `MAX_HEIGHT`, `place`d above (else below); `editorHoverWidget.background` + `.foreground`, border `.border`, headings `.heading`, code blocks and inline code `textPreformat.foreground`, rules a line in the border colour; writes back `popup.rows` / `shown` and clamps `top` (the wheel scrolls); "…" in the bottom / top border when rows are cut below / above.
- `completion.rs` — the completion list (`app.completion.popup`, when it has rows, its group's tab shows its buffer and the word's start is on screen): `place`d below the word (else above), the labels lined up under it (border and icon column to its left), ≤ `completion::MAX_ROWS` rows, as wide as the widest label (+ the widest detail ≤ 30) ≤ `completion::MAX_WIDTH`; each row the kind's icon (`completion::icon`: a letter in `symbolIcon.*Foreground`), the label with the chars the word matched (`Filter::score` against the label) in `editorSuggestWidget.highlightForeground`; the selected row in `.selectedBackground` with the item's detail right-aligned (`.detail`); "…" in the border where rows are cut. Writes back `popup.rows` (the page size) and clamps `top` (no reveal: the wheel may scroll the selection out). Returns `CompletionHit` (box, rows, top) for `hits.completion` (`Hit::Completion`, checked before everything).
- `panel::render` draws the bottom panel: a `─` top border (`panel.border`; `Hit::PanelBorder` drags it), the tab strip (each `PanelTab::ALL`'s title, `panelTitle.active` / `.inactive`, with its total in `panel.badge`; Locations only while `app.locations` is set, its `title` dimmed after the tabs when shown; then a tab per task run, oldest first: its name, `task_mark` (`●` `task.running`, `✓` `task.succeeded`, `✗ 2` / `✗ killed` / `✗` `task.failed`) and a dimmed `×` close button; tabs past the right edge aren't drawn), then the shown tab's content — a task tab: `task::render`; Locations (`locations`): the same file rows, then each place's preview through `search::draw_line` (the place in `search.match`; "Ln x, Col y" dimmed until the file is read), "No locations." without a list; or the Problems list from `problems::files`: only `grouped::rows` for the visible rows, each file's problems fetched once per frame (`FileProblems::problems(from, n)`); file rows (name `panel.fileName`, the folder relative to the root dimmed, the count right-aligned in `panel.badge`), problem rows indented (icon in `Severity::icon_key`'s colour, the message's first line (control chars as spaces), then dimmed `source(code) [Ln x, Col y]` — the message is cut with "…" first, the tail dropped when there's no room); the selected row `list.active` while `Focus::Panel`, else `list.inactive`; "No problems have been detected in the workspace." when empty. Sets the list's `height` and re-clamps its scroll. Returns `PanelHits`: the tab rects, the task tabs' close buttons (`hits.panel_closes`) and a `ListHit` (rows by `RowKey`) for `hits.panel_list`.
- `task.rs` — a task tab's terminal in `layout::task_area(panel)` (below the tab strip, a column of padding): resizes every running run's PTY to it and sets `app.tasks.size` (render-time state); fills the area with `terminal.background`, draws the run's `vt100` screen with `tui-term`'s `PseudoTerminal` (its drawn cursor off) through `Shifted` (a screen taller than the area — an ended run that started bigger — drawn from `top_row`, keeping its last non-blank line and the cursor in view), then every cell through `Theme::terminal_cell` (no `Color` here); the rest of the tab strip's row shows "n lines back (Shift+PageDown, Ctrl+End)" while scrolled back, else the command (and its folder when not the root), dimmed; the terminal cursor at the screen's cursor while the tab has the keys, the run runs, it isn't scrolled back and the task didn't hide it.
- `status.rs`: the git branch (` ⎇ main*+ `: `Status::label`, only with a repository) after the Restricted badge, then the file name, then problem counts for the workspace (`⊗ n  ⚠ m`, `app.lsp.diagnostics.counts()`, shown once a server runs or anything was published; `render` returns their rect for `hits.status_problems`), then a language server's work in progress (`app.lsp.progress()`: ` rust-analyzer: Indexing 40% `, `statusBar` style), then the message: `app.message` (a notification) if set, else the cursor line's diagnostic (`Marks::for_line`: icon + message on one line, `statusBar` style); right side `Ln x, Col y` for one selection, `N selections` for several (as VS Code), then indent (`Settings::for_language`: a Makefile shows `Tab Size`), encoding, line ending and the language mode (`Language::name()`).
- `banner.rs` — the changed-on-disk banner (`banner`, its `⚠` in `banner.icon`): the message (cut first; "…and you have unsaved changes", or "…and wasn't reloaded" for a binary / non-UTF-8 file on a clean buffer), then a button per `disk::BannerAction::ALL` (` Reload ` / ` Keep Mine ` / ` Show Diff `, `banner.action`). Returns `BannerHit` (row, buttons).
- `tabs.rs`: a deleted file's tab reads `name (deleted)`, struck through (`tab.deleted`); a diff tab reads `DiffTab::title()` (`name (Working Tree)`, `name (History: 3 min ago)`), never dirty.
- `diff.rs` — a diff tab: `set_layout` (inline below `diff_view::SIDE_BY_SIDE_MIN` columns) and `scroll_to_cursor` first; a header row (`diffEditor.header`: the sides' titles over their columns, "n changes" — or the last load's error — at the right), then only the visible rows of `Doc::aligned(inline)`: side by side each half its line number (`gutter`, the current row's `gutter.active`) and text from `left_col` through `pos::display_grapheme`; removed lines on `diffEditor.removedLineBackground`, inserted on `insertedLineBackground`, a changed pair's `changed_parts` on `removedTextBackground` / `insertedTextBackground`, the missing side `╱` in `diffEditor.diagonalFill`, unchanged rows plain (the current one `editor.lineHighlight`), a `│` between; inline: both numbers, `-` / `+`, the text. Plain text: no syntax colours. Each hunk's first row ends with ` Stage ` / ` Unstage ` (`quickDiff.action`) when the pair stages; an unstaged pair (Index ↔ Working Tree) also gets ` Revert ` (`diffEditor.revertAction`, red) at the right end of the left column (inline: left of Stage), dropped when it doesn't fit (`DiffHit::reverts`). The terminal cursor on the current row's text when focused. "Loading…", the error, "Binary file: the diff isn't shown", "Both sides are empty" otherwise. Returns `DiffHit` (rows rect, buttons by hunk).
- `scm.rs` — the Source Control view (`SidePanel::SourceControl`, below the title): the branch line (` ⎇ main*+`, `Status::label`, `sideBar.header`), then `ScmView::rows` from its clamped scroll (sets `scm.height`): headers (` ▾ Staged Changes` / `▸` collapsed, `sideBar.header`, the count in `scm.count` at the right) and files (indented name in its change's `Decoration::theme_key` colour, `scm.deleted` struck through when deleted, the folder dimmed, the letter at the right edge in the same colour); the selected row `list.active` while focused, else `list.inactive`; the selected and the hovered (`scm.hover`) row show their button left of the letter / badge (`+` stage in Changes, `−` unstage in Staged, `scm.action`; none on an empty header). No status: "Reading the git status…" while the first read runs, else "The folder currently open doesn't have a git repository." (wrapped, dimmed; no `ScmHit`); nothing changed: "No changes in the working tree.". Returns `ScmHit` (list rect, each drawn row's `RowKey`, buttons with their key and side).
- `splash.rs` — what a group with no tabs shows: the "Jed" logo (`splash.logo`) centred in the editor area, "Jim's Editor" (`splash.subtitle`) under its "ed"; only the subtitle when the logo doesn't fit, nothing when neither does.
- `dialog.rs` draws the prompts (`RestoreBackups`: the files from `app.backups.offered`, relative to the root, with `history::ago` of each backup; [R]estore [D]iscard [L]ater); an `Input`'s text is drawn in `editor.selection` over `dialog.input` while `field.all_selected` (F2's prefilled name: typing replaces it).
- `scrollbar.rs` — vertical scroll bars: `take_column(&mut area)` (the area's last column, always reserved so nothing reflows; `None` below 2 columns), `look(app, target)` (dragged / hovered / normal), `render(out, track, scroll, look, base, theme)` (the track on `base` — `editor`, `sideBar`, `panel` — and the thumb). An editor group's: the track (one column, `editor`; a diff tab's starts below its header row, whose cell takes `diffEditor.header`) and the thumb (`scrollbar::Scroll::thumb`: from the line count, `view.height` and the top line — a diff's rows, `height`, `top` — no per-line work) in `scrollbarSlider.background`, `.hoverBackground` (`ui.scrollbar_hover`) or `.activeBackground` (`App::scrollbar_dragged`, drawn even when the drag reaches the top of a short text). Returns `ScrollBarHit` (track, thumb). Lists: the explorer's rows, the Search view's results (not its query / toggles / summary), the Source Control list (not its branch line), the Problems / Locations lists (not the tab strip; no bar for "No problems…" / "No locations." / "No changes…" or a task tab) each give their last column to a bar (`Scroll::rows` from the list's `Scrollable`, after its own clamp); counts, git letters and the `+` / `−` buttons sit left of it, one blank column between. `SideHits::scrollbar` / `PanelHits::scrollbar` → `hits.side_scrollbar` / `hits.panel_scrollbar`.
