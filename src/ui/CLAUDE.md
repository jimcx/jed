# ui

Drawing only — but `render` is not pure: it takes `&mut App` and writes back state that input handling relies on.

- `mod.rs::render` computes `layout::compute` regions, draws activity bar → side panel → each group (tab bar + editor) from `groups.tree.layout` → dividers → the bottom panel (`regions.panel`, when `ui.panel_visible`) → status bar → find widget (over the active group's editor) → hover popup (`hover::render`, over its group's editor; `hits.hover`) → completion list (`completion::render`; `hits.completion`) → palette → dialog (last, on top). It builds a fresh `HitMap` and stores it in `app.hits`; mouse handling uses the *previous* frame's map. Below 30×4 it draws nothing.
- Each widget's `render` returns what it drew for hit-testing (`activity` → icon rows, `side` → explorer row area and the Search view's `SearchHit`, `tabs` → `Vec<TabHit>`, `editor` → text rect without the gutter); add new clickable things the same way (a `Hit` variant in `layout.rs`, filled here).
- `editor::render` mutates the `View`: sets `height`/`width` (used by page movement), re-anchors `set_top_line` (the buffer may have changed), and applies `reveal_range` (`reveal_in_center`, Cmd+D), else `reveal_pos` (`scroll_to`, minimal scroll to a position: add cursor above/below, box select), else `reveal_cursor` via `scroll_to_cursor`, clearing them. Commands that move cursors set `view.reveal_cursor = true` and let the next frame scroll.
- `editor::render` takes an `Overlay { focused, find }`: `find` is the find widget only for the active group, when its cache `is_current` for this buffer and revision. Find matches on screen come from `FindWidget::matches_in(viewport)` (never a search per frame) and are walked with one index like selections: others `editor.findMatchHighlight`, then the selection, then the match that is the primary selection `editor.findMatch`.
- `find::render` draws the open find widget at the top right of the active editor (≤ 64 wide): the find input (scrolled to its cursor, placeholder when empty, `editor.selection` when all selected), toggles `Aa ab .*` (`find.option` / `find.option.active`), the count; the replace input row; an invalid regex's message (`dialog.error`) on the last row. Terminal cursor in the focused input when `Focus::Find`. Returns `FindHit` (box, replace row, toggle rects) for `hits.find`.
- `side::render` sets `explorer.height` (used for page up/down) and clamps `explorer.scroll` to the row count; for `SidePanel::Search` it draws the title and hands the rest to `search::render`, returning its `SearchHit` for `hits.search`.
- `search::render` draws the Search view: the query input (`find::draw_field`, `dialog.input`), toggles `Aa .*` (`find.option` / `find.option.active`), the regex error (`search.error`), a summary (`sideBar.dim`: "1,234 results in 56 files", "Searching…" while running or debouncing, "No results found"), the truncated note (`search.warning`), then the visible rows from `search_view::rows`: file rows (name `search.fileName`, dimmed folder, count `search.count` at the right) and indented lines from `search_view::preview` (matches `search.match`, "…" where cut); the selected row filled with `list.active` while the list has the keys, else `list.inactive` (text keeps its colours, matches and counts their own backgrounds). Sets `search_view.list.height` and re-clamps its scroll. Terminal cursor in the query when the side panel has focus and the list doesn't. `draw_line(out, x, y, width, line_match, (base, dim, matched))` is shared with the panel's Locations list. Its `SearchHit` holds the toggles, the list rect and each visible row's `RowKey` (clicks map by key, not row number).
- Text is drawn grapheme by grapheme through `pos::display_grapheme` — the same function column maths uses, so cursor placement and drawing never disagree. Don't measure buffer text any other way (labels in tabs/status/dialogs use `unicode_width` directly).
- Syntax colours: `buf.syntax.spans(rope, top..last+1)` (the editor takes `&mut Buffer` for this cache; no query unless the tree changed or the view left the cached lines) walked with one index like selections; a token's style (`theme.get(KEYS[i])`, a table built once per frame) patches the row style's foreground first, then find-match / selection backgrounds and cursors go over it (VS Code: selection background, token foreground). No tree yet (first parse, too large, plain text) → plain text; while a re-parse runs, the last spans.
- Matched brackets (`Settings::match_brackets`): the heads of the selections on screen go to `view.brackets.get(rope, &syntax, revision, heads)` (cached, see `brackets::Matches`); the sorted positions are walked with one index and patched with `editor.bracketMatch` over the token colour, under find-match / selection backgrounds and cursors.
- Diagnostics: `buf.diagnostics.overlapping(viewport)` flattened by `diagnostics::runs` (the most severe wins; an empty range covers the grapheme there, the one before at a line end, or the cell past an empty line's end), walked with one index; the severity's key (`editorError.foreground`, … : underline + `underline_color`) is patched over the token colour, before find-match / selection backgrounds (which don't touch the underline).
- Selections: only `selections.overlapping(viewport)` are looked at (there can be 60k); one index walks that sorted slice while bytes are visited in order; a selection over a line break paints one cell past the line end. Secondary cursors are reversed cells (`editor.cursor.secondary`); the terminal cursor marks the primary, only in the focused group with no prompt or palette open.
- Styles: start from the widget's base key (`editor`, `sideBar`, `dialog`, `statusBar`) and `patch` modifier keys on top (`editor.selection`, `gutter.active`, …). Every key comes from `Theme::dark_plus`; never construct `Color`s here.
- `palette::render` draws the open palette (top centre: input, optional hint, up to 14 rows with fuzzy-match highlights and right-aligned bindings), sets `palette.height`, clamps `palette.scroll`, puts the terminal cursor in its input and returns `PaletteHit` (box + rows) for `hits.palette`. The editor and explorer show no focus/cursor while it's open.
- `popup.rs` — popups anchored at a buffer position (the hover, the completion list): `cell_of(rope, view, text_rect, pos, tab_width)` (the anchor's screen cell from the view's scroll; `None` off screen, a column scrolled off pulled to the edge), `place(area, anchor, width, height, Side::{Above, Below})` (the preferred side of the anchor's row if it fits, else the other, else the roomier one cut to it; left edge at the anchor, moved left to stay in `area` — the group's editor area), `frame(out, rect, fill, border)` (fill + box border, returns the inside). The caller returns the rect for the `HitMap` (`Hit` checks it first, so events on it don't fall through).
- `hover.rs` — the hover popup (`app.hover.popup`): only when its group's active tab still shows its buffer and the anchor (the range's start) is on screen; width = widest line ≤ `hover::MAX_WIDTH` and the editor's width − 4 (border + a column of padding each side), rows = `hover::wrap` ≤ `MAX_HEIGHT`, `place`d above (else below); `editorHoverWidget.background` + `.foreground`, border `.border`, headings `.heading`, code blocks and inline code `textPreformat.foreground`, rules a line in the border colour; writes back `popup.rows` / `shown` and clamps `top` (the wheel scrolls); "…" in the bottom / top border when rows are cut below / above.
- `completion.rs` — the completion list (`app.completion.popup`, when it has rows, its group's tab shows its buffer and the word's start is on screen): `place`d below the word (else above), the labels lined up under it (border and icon column to its left), ≤ `completion::MAX_ROWS` rows, as wide as the widest label (+ the widest detail ≤ 30) ≤ `completion::MAX_WIDTH`; each row the kind's icon (`completion::icon`: a letter in `symbolIcon.*Foreground`), the label with the chars the word matched (`Filter::score` against the label) in `editorSuggestWidget.highlightForeground`; the selected row in `.selectedBackground` with the item's detail right-aligned (`.detail`); "…" in the border where rows are cut. Writes back `popup.rows` (the page size) and clamps `top` (no reveal: the wheel may scroll the selection out). Returns `CompletionHit` (box, rows, top) for `hits.completion` (`Hit::Completion`, checked before everything).
- `panel::render` draws the bottom panel: a `─` top border (`panel.border`; `Hit::PanelBorder` drags it), the tab strip (each `PanelTab::ALL`'s title, `panelTitle.active` / `.inactive`, with its total in `panel.badge`; Locations only while `app.locations` is set, its `title` dimmed after the tabs when shown), then the shown tab's list — Locations (`locations`): the same file rows, then each place's preview through `search::draw_line` (the place in `search.match`; "Ln x, Col y" dimmed until the file is read), "No locations." without a list; or the Problems list from `problems::files`: only `grouped::rows` for the visible rows, each file's problems fetched once per frame (`FileProblems::problems(from, n)`); file rows (name `panel.fileName`, the folder relative to the root dimmed, the count right-aligned in `panel.badge`), problem rows indented (icon in `Severity::icon_key`'s colour, the message's first line (control chars as spaces), then dimmed `source(code) [Ln x, Col y]` — the message is cut with "…" first, the tail dropped when there's no room); the selected row `list.active` while `Focus::Panel`, else `list.inactive`; "No problems have been detected in the workspace." when empty. Sets the list's `height` and re-clamps its scroll. Returns the tab rects and a `ListHit` (rows by `RowKey`) for `hits.panel_list`.
- `status.rs`: the file name, then problem counts for the workspace (`⊗ n  ⚠ m`, `app.lsp.diagnostics.counts()`, shown once a server runs or anything was published; `render` returns their rect for `hits.status_problems`), then the message: `app.message` (a notification) if set, else the cursor line's diagnostic (`Marks::for_line`: icon + message on one line, `statusBar` style); right side `Ln x, Col y` for one selection, `N selections` for several (as VS Code), then indent (`Settings::for_language`: a Makefile shows `Tab Size`), encoding, line ending and the language mode (`Language::name()`).
- `side.rs` shows a placeholder for `SidePanel::SourceControl` (not built yet).
