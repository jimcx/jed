# app

`App` (in `mod.rs`) owns all state; submodules are `impl App` blocks split by area, with `pub(super)` methods:

- `mod.rs` — struct, `new`/`start`/`run`, `handle_event`, `execute`, `sync_views`, copy/paste (paste looks up `clipboard.copied(text)` for the whole-line flag and per-selection pieces), `handle_app_event`, crash snapshots, and the `#[cfg(test)]` driving helpers (`test_start`, `test_open` (a buffer in a new tab), `press`, `type_text`, `mouse`, `mouse_with`, `handle_test_event`, `settle`, `pump` (queued `AppEvent`s, no waiting, then `sync_syntax`), `test_search_batch`, `test_lsp_event` (a language server event handled before the turn's `sync_servers`), `quitting`, the `last_command` field).
- `files.rs` — open (off-thread `Buffer::open` → `AppEvent::Opened { path, result }`, the buffer boxed; `open_file(path, focus, goto)` opens in the active group, or applies `goto` at once when the buffer is already loaded; the in-flight `opening` map holds each path's `OpenRequest { focus, goto }`, a repeat request replacing its `goto` (the last F4 wins) and adding focus, and `opened` takes it back), `Goto` (`Cursor(line, col)`: 1-based line and display column — `file:line:col`, `InitialFile`; `Match { line, range }`: a search result, 0-based line + byte offsets, selected anchor→head and centred via `reveal_range`, clamped to the line count, the line's end and char boundaries since the text may have changed; `Problem { place, select }`: a `problems::Place` — byte range in the open buffer (clamped) or LSP positions read with `pos::from_lsp_pos` — selected, or a cursor at its start, centred via `reveal_range`), `apply_goto`, `add_buffer`, `place_cursor` (1-based line/column, clamped), tab activation/cycling, `focus_group`, `split`, `close_tab`/`discard_tab`, save/`save_done`, quit.
- `prompt.rs` — `Prompt` (modal: `SaveBeforeClose`, `SaveAllBeforeQuit`, `Trust`, `Input`, `ConfirmDelete`), `Input` (a `field::TextField` plus what the name is for), `handle_prompt_key`, trust decisions (the `Trust` dialog also shows the current decision when reopened by "Manage Workspace Trust").
- `side.rs` — explorer commands, directory listings, file ops (`FileOp` → `AppEvent::FileOpDone`), fs-change batching (`flush_fs_changes`), `.workspace` reload (`config_loaded`: `self.settings = self.workspace.settings()`, so the user's `settings.toml` stays layered underneath).
- `palette.rs` — `open_palette(picker, text)` / `close_palette`, `palette_command` (`PaletteCommand`), `palette_key` / `palette_paste` (input → `refresh_palette`), `accept_palette` (run a command, open a file at `file:line:col`, go to line, set a log level), `palette_mouse`; quick open's walk (`start_file_walk`, once per opening, into `FileMatcher`) and `files_matched` / `files_walked`; the palette-only commands: `manage_trust`, `open_log_file` (→ `AppEvent::LogFileFound`), `open_user_settings` (`config::settings::create_if_missing` off-thread → `AppEvent::UserSettingsReady` → opens it), `set_log_filter`.
- `cursors.rs` — `match_command` (Cmd+D / Cmd+Shift+L / Cmd+Alt+D through `multicursor`, keeping the `MatchSession` with the view — group, tab, buffer — it belongs to), `cursor_undo` (Cmd+U: pops `view.cursor_history`, restores selections and scroll), `note_pre_event` (start of `handle_event`: scroll before the event, for the Cmd+U entry) and `track_selections` (end of `sync_views`; also `view.auto_closed.validate`, so auto-closed pairs end once the cursors leave them, as VS Code checks on every selection change).
- `find.rs` — the find / replace widget (`app.find`, a `find::FindWidget`): `open_find(replace)` (seeds from a one-line selection or the word under an empty cursor, escaped when regex is on, selects the query, selects its match; with replace and a query the replace input gets the cursor), `close_find`, `find_command` (`FindCommand`), `find_key` / `find_paste` (edits the focused input; edits to the query `research`: re-search and select the first match from the primary's start), `refresh_find` (after every event: re-searches only when buffer/revision/query/options changed; closes the widget when there's no tab), next / previous via `Matcher::find_next` / `find_prev` with wrap, toggles (flip `find_options`, end a non-word-mode Cmd+D session via `find_options_changed`, say so in the status bar when the widget is closed), Alt+Enter (every match a selection, focus to the editor), replace one (`EditKind::Other`, then next) and replace all (one `ChangeSet` built with `push` — straight from the cached matches when the replacement names no group — one `Buffer::edit`, selections mapped through it), `find_mouse` (clicks on toggles / inputs, from `hits.find`).
- `workspace_search.rs` — the Search view (`app.search_view`, a `search_view::SearchView`): `search_focused` (focus `SidePanel` with `ui.side_panel == Search`: the query or the results list has the keys), `find_in_files` (Cmd+Shift+F: show the view, seed from a non-empty one-line primary selection, regex-escaped when its regex is on, select the query, search at once), `search_command` (`SearchCommand`: toggles flip the view's own options and search at once; `Refresh` (Enter) searches now; `FocusEditor` (Esc) back to the editor when there's a tab, results kept), `search_key` / `search_paste` (edits schedule a debounced restart; emptying the query searches — i.e. clears — at once), `search_tick(now)` (the event loop's deadline branch and `settle`: runs a due restart), `run_search` (the view's query → `start_search`, error into `search_view.error`), `search_click(m, count)` (toggle buttons from `hits.search`; a result row by its key: the list takes the keys and selects it, a match row opens with the focus staying in the list, a double click (also on a file row: its first match) opens and focuses the editor; else the input takes the keys), `search_scroll` (wheel). The results list (`search_view.list_focused`, `Context::SearchResults`): `FocusResults` (Down in the query: the list, keeping its selection or selecting the first row), `Up`/`Down`/`PageUp`/`PageDown`/`First`/`Last` (Up from the first row hands the keys back to the query), `Open` (Enter: the selected match, or a file row's first, opened via `open_result` with the editor focused); `NextResult`/`PreviousResult` (F4 / Shift+F4, global: `SearchView::step`, opened without moving the focus; nothing without results). In the list a typed character goes back to the query and types there (paste too); other unbound keys do nothing. `open_result(target, focus)` joins the root and opens with `Goto::Match` in the active group — the last focused one while the side panel has the keys. Also `start_search(Query)` (drops the running search's `Handle`, which cancels it; bumps `search_generation`; collects rope snapshots of dirty buffers inside the root; empty pattern → finished empty `Results` without spawning; invalid regex → `search = None` and the `SearchError`) and `search_results(batch)` (`AppEvent::SearchResults`: `Results::add` drops stale generations; the handle is released when done). `app.search` is what `ui::search` draws.
- `syntax.rs` — language detection for buffers (`detect_language`: associations / name / first line; `add_buffer` sets it, `redetect_languages` after an explorer rename or a `.workspace` change to `[files] associations`, `load_associations` compiles them in `new` and on reload, reporting bad entries) and `sync_syntax` (every buffer's `Syntax::update` with `settings.syntax_max_bytes`; spawns the `ParseJob` it returns → `AppEvent::Parsed { buffer, parsed }` → `parsed`). `sync_syntax` runs once per event-loop turn before drawing, in `start`, and in the test helpers `pump`/`settle`; without a tokio runtime it does nothing.
- `lsp.rs` — `sync_servers` (each loop turn, `start`, `pump` / `settle`; nothing before `lsp.started()`; when `servers_dirty` — set by `add_buffer`, `redetect_languages`, `decide_trust`, `config_loaded` — hands the open buffers' languages, `.workspace` and `trust` to `lsp::Manager::sync`; then always `lsp.sync_documents(&mut buffers)`: opens / closes / updates documents, so renames, language changes and closed tabs need no hook), `save_done` calls `lsp.saved(buffers, id)` (`didSave`), `lsp_event` (`AppEvent::Lsp`: `Event::Diagnostics` → `Manager::publish` (into the store and the file's buffer); anything else → `Manager::handle` → `notify`; then, as after `sync_servers`, `drop_cleared_diagnostics`: marks of servers the manager dropped are cleared from every buffer), `add_buffer` places stored diagnostics (`lsp.load_diagnostics`), `shutdown_servers` (async; `run` awaits it on quit, tests after `Quit`).
- `problems.rs` — the bottom panel and its Problems list (`app.problems`, a `problems::ProblemsView`; drawn by `ui::panel`): `toggle_panel` (Cmd+J: show + focus, or hide — the editor, else the side panel, gets the keys back if the panel had them), `toggle_problems` (Cmd+Shift+M: show + focus the list, or hide when it has the keys), `problem_counts_clicked` (status bar counts: show + focus, or hide when it shows Problems, focused or not), `focus_panel(tab)` (selects the first row when nothing is), `problems_command` (`ProblemsCommand`: Up/Down/PageUp/PageDown/First/Last move the selection (Up at the top stays), `Open` (Enter: `ProblemsView::target`, opened selected with the editor focused), `FocusEditor` (Esc, when there's a tab), `Next`/`Previous` → `step_problem`), `open_problem(target, select, focus)` (`open_file` with `Goto::Problem` in the active group), `step_problem` (F8 / Shift+F8, global: `problems::step` from the active view's primary selection start, with `last_problem` (path, index, cursor position) so problems at one place go one by one; cursor at the start, focus unchanged, the list's selection follows, the message (icon, one line, `source(code)`, "(k of n)") set as `app.message` without logging; VS Code shows a peek instead), `problems_click(m, count)` (as `search_click`: a problem row opens keeping the list focused, a double click — also a file row's — focuses the editor), `problems_scroll` (wheel). `problems::files` is rebuilt per use (cheap: per file, not per problem).
- `mouse.rs` — clicks via `HitMap` from the last frame, `ClickTracker` (double/triple), `Drag` (side border, panel border (`ui.panel_height` = rows from the pointer to the status bar; `layout::compute` clamps), split divider, text, `AddedText`, `Column`), wheel scrolls the group under the pointer without focusing it (over the Search view, its results; over the bottom panel, its list). Panel clicks: its tab → `focus_panel`, its body → `problems_click`, the status bar's counts → `problem_counts_clicked`. Clicks in the Search view go to `search_click`. Alt+Click (`alt_click`, VS Code): with several selections, clicking on/in one removes it, else adds a cursor (newest; Alt+drag extends it; double/triple Alt+Click makes it the word/line). Shift+Alt+click/drag box-selects from the view's box corner or the primary's anchor to the cell under the pointer (`text_cell`: line + display column, past the line end too) via `column::select`.

Things to know before editing:

- **Background work pattern:** clone `self.tx`, `tokio::task::spawn_blocking`, send an `AppEvent` variant, handle it in `handle_app_event`. In-flight sets (`listing`, the `opening` map) dedupe requests. Restartable work (quick open's walk, workspace search) carries a generation number so results of a replaced run are dropped, and a cancel flag (`Arc<AtomicBool>`; workspace search's `Handle` sets it on drop). Saves report `state` back so `finish_save` marks the right history state.
- `App::lsp` gets its event sink in `start()`; no server is spawned before that (`add_buffer` only marks `servers_dirty`).
- `App::new` must start no background work (it once crashed by spawning before the runtime existed); put it in `start()`.
- `Focus` is `Editor`, `SidePanel`, `Find` (the find widget's input; `find.field` picks `Context::Find` or `Context::Replace`) or `Panel` (the bottom panel; `ui.panel_tab` picks the context: `Problems`; unbound keys and paste do nothing there); `context()` maps it to the keymap `Context` (`SidePanel` is `Explorer`, or `Search` / `SearchResults` (by `search_view.list_focused`) when the side panel shows the Search view: unbound keys and paste then edit its query, never the buffer; `focus_side` gives the query the keys) (`Palette` whenever `app.palette` is open; the palette doesn't change `Focus`). The find widget stays shown when focus leaves it (an editor click sets `Focus::Editor`); Esc in the editor then closes it before dropping cursors. Starting with no file, or closing the last tab while the side panel is visible, focuses the side panel.
- The palette (`app.palette`) is not a `Prompt`: its keys go through the keymap's `Palette` context, unbound keys edit its `TextField`, and while it's open it takes every mouse event (click outside closes it). A prompt opened on top of it gets keys first. `execute` closes it before running any other command.
- Quick open: `FileMatcher`'s notify callback sends `AppEvent::FilesMatched` at most once until handled (`files_pending`); handling it calls `tick()` (never waits) and rebuilds rows. `FilesWalked { generation }` marks the walk done unless a newer walk started.
- `set_keymap(keymap, errors)` (from `main`) replaces the keymap and shows the first load error (`report_errors`: `settings.toml`'s and `keybindings.toml`'s, `(and N more)`); `log` (reload handle, `None` if logging is off) and `log_dir` are set by `main` / tests; `config_dir` (`paths::config_dir()`, where "Open User Settings" looks) by tests.
- A prompt swallows all keys and mouse events; `close_prompt()` re-opens a pending trust prompt (`trust_pending`). Esc/Enter/letter handling per prompt is in `handle_prompt_key`; unrecognised keys put the prompt back.
- Leaving a tab/group (`activate_tab`, `cycle_tab`, `focus_group`, `split`, editor click) calls `buf.seal_undo()` first.
- Closing: the save prompt appears only when the tab is the last one (in any group) showing a dirty buffer (`groups.tabs_showing`). `discard_tab` drops the buffer when no tab shows it and closes an empty group (never the last). `AfterSave::{Quit, Close}` continues a close/quit once saves finish.
- `sync_views` runs after every input event: the editing tab only re-anchors its viewport; every other view on the buffer runs `View::map_through`. Then `track_selections`: if the active view's buffer changed its Cmd+U history is reset, else a selection change pushes the previous list; any selection change not made by a match command (`session_changed`), or focus leaving the editor (palette, prompt, side panel, find widget), ends the Cmd+D session (VS Code's rule; word mode resets with it). Only input events are tracked, so selections set by background results are recorded at the next key.
- `find_options` (`search::Options`: case / whole word / regex) belongs to the find widget's toggles and is what Cmd+D uses for selected text (case and whole word only); toggling ends a Cmd+D session that uses them (not word mode).
- The bottom panel: `ui.panel_visible`, `ui.panel_height` (`PANEL_HEIGHT` = 10 until dragged; border and tab strip included), `ui.panel_tab` (`PanelTab::Problems`; M12's task tabs go there: a `PanelTab` variant, its context in `context()`, its drawing in `ui::panel`). Cmd+B only moves the focus to the editor when the side panel had it.
- `update_crash_snapshot` runs every loop turn so the panic hook can back up dirty buffers.
- Messages: `notify(Level, text)` sets the status-bar message and logs it; any key press clears it.
- Timers: `next_timer()` sleeps until the earliest of `fs_deadline` and `search_view.deadline()` (forever when neither is set; the future borrows nothing) and `on_timer` runs it (`flush_fs_changes` / `search_tick`). `run`'s `select!` and `settle` both use this pair, so a new deadline goes there, not in a new `select!` branch.
- The Search view's query is debounced (`search_view::DEBOUNCE`, 150 ms) via `search_view.deadline()`; starting a search drops the running one's `Handle`.
- File system events are debounced (`FS_DEBOUNCE`, 100 ms) via `fs_deadline`; explorer renames/deletes update open buffers' `path`/`deleted`.
