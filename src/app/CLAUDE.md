# app

`App` (in `mod.rs`) owns all state; submodules are `impl App` blocks split by area, with `pub(super)` methods:

- `mod.rs` — struct, `new`/`start`/`run`, `handle_event`, `execute`, `sync_views`, copy/paste (paste looks up `clipboard.copied(text)` for the whole-line flag and per-selection pieces), `handle_app_event`, crash snapshots, and the `#[cfg(test)]` driving helpers (`test_start`, `test_plain_whitespace` (whitespace drawn as blanks via the session toggle, for tests reading drawn text with spaces), `test_open` (a buffer in a new tab), `test_execute(cmd)` (a command as its key would run it), `press`, `type_text`, `mouse`, `mouse_with`, `handle_test_event`, `settle`, `pump` (queued `AppEvent`s, no waiting, then `sync_syntax`), `test_search_batch`, `test_lsp_event` (a language server event handled before the turn's `sync_servers`), `test_hover_tick(now)` (the hover rest timer), `test_completion_tick(now)` (the quick-suggestion timer), `test_backup_tick(after)` (the backup timer `after` from now, after a `sync_backups`), `test_panic_backup()` (the panic hook's backup of the crash snapshot), `test_locations_read(generation, files)` (an `AppEvent::LocationsRead` as the background read sends it), `test_git_history_page(path, skip, generation, result)` (a page of a file's commits as `AppEvent::GitHistory` sends it), `pending_requests()` (kind, position), `quitting`, the `last_command` field). `sync_views` = `follow_edits` (every other view on an edited buffer maps through its applied sets; also called directly after edits made by background results) + `track_selections`. `render_whitespace()`: the `render_whitespace` setting, or after "View: Toggle Render Whitespace" (`ui.whitespace_toggled`, session-only, never written to a file, kept across `.workspace` reloads) `none` — or the setting again (`all` when it is `none`); `ui::render` passes it to the editor in `Overlay::whitespace`.
- `files.rs` — open (off-thread `Buffer::open` → `AppEvent::Opened { path, result }`, the buffer boxed; `open_file(path, focus, goto)` (sets `nav_jump`) opens in the active group, or applies `goto` at once when the buffer is already loaded; the in-flight `opening` map holds each path's `OpenRequest { focus, goto, background, edits, restore, backup }`, a repeat request replacing its `goto` (the last F4 wins), adding focus and clearing `background`, and `opened` takes it back (a path loaded meanwhile — a session's restore — keeps that buffer: the loaded one is dropped and the request goes to `open_file`): a `background` one (a rename's file) goes in a tab beside the active one (`Group::open_background`), then its `edits` are applied (`apply_pending_edits`), then a `restore` (a file history entry: `restore_history`), then a `backup` (a crash backup: `restore_backup`; a failed load keeps it: `backup_not_opened`); a failed load with edits says "Rename not applied to …"), `Goto` (`Cursor(line, col)`: 1-based line and display column — `file:line:col`, `InitialFile`; `Match { line, range }`: a search result, 0-based line + byte offsets, selected anchor→head and centred via `reveal_range`, clamped to the line count, the line's end and char boundaries since the text may have changed; `Place(navigation::Pos)`: Go Back / Forward's selection and scroll (`navigation::place_view`); `Problem { place, select }`: a `problems::Place` — byte range in the open buffer (clamped) or LSP positions read with `pos::from_lsp_pos` — selected, or a cursor at its start, centred via `reveal_range`), `apply_goto`, `add_buffer` (= `register_buffer`: language, stored diagnostics, the first view — then a tab), `place_cursor` (1-based line/column, clamped), tab activation/cycling, `focus_group`, `split`, `close_tab`/`discard_tab`, save/`save_done` (the save's task runs `SaveJob::write`, sends `SaveDone`, then records the file history snapshot when `history_job` gave one; `SaveError::Conflict`: nothing written, a disk check shows the banner, a pending close / quit stops; every end of a save runs `disk_save_done`), quit.
- `prompt.rs` — `Prompt` (modal: `SaveBeforeClose`, `SaveAllBeforeQuit`, `Trust`, `Input`, `ConfirmDelete`, `SaveBeforeStage { buffer, line, file }` (staging from a dirty buffer — a change, or with `file` the whole file: Save and Stage / Cancel), `SaveBeforeStageAll { buffers }` (Stage All with dirty buffers among its files: Save and Stage → `save_then_stage_all`), `RestoreBackups` (the start's crash backups: R / Enter → `restore_backups`, D → `discard_backups`, L / Esc → `keep_backups`)), `Input` (a `field::TextField` plus what the name is for: `InputKind::{NewFile, NewFolder, Rename, RenameSymbol}` — the last is F2's new name, submitted to `request_rename` unless empty or unchanged, no file-name validation), `handle_prompt_key`, trust decisions (the `Trust` dialog also shows the current decision when reopened by "Manage Workspace Trust").
- `side.rs` — explorer commands, directory listings, file ops (`FileOp` → `AppEvent::FileOpDone`; a rename also moves file history: `history_rename`), fs-change batching (`flush_fs_changes` (paths under `.jed/` never get here: `fs_changed`): listings, `git_paths_changed`, `disk_paths_changed`, `diffs_paths_changed`), `.workspace` reload (`config_loaded`: `self.settings = self.workspace.settings()`, so the user's `settings.toml` stays layered underneath).
- `navigation.rs` — back / forward (`app.nav`, a `NavState`: `history` (`navigation::History`), the event's `jump` / `navigating` flags, `pending` (a file Go Back is reopening)): `nav_begin` / `nav_end(before, input)` (around every `handle_event`, `handle_app_event` — not `SessionRead` — and `test_execute`; see the root CLAUDE.md's invariant), `nav_jump`, `navigate(dir)` (`nav.back` / `nav.forward`: the entry's group, else the active one; a text tab of its file (a diff tab for a diff entry, either counts), else a new view of its loaded buffer, else `open_file(path, true, Goto::Place)` with `pending`), `nav_opened` (top of `files::opened`: the pending file arrived — gone from disk (no `disk()` stamp) or failed, and nothing else wanted it → dropped, its entry `skip`ped, navigation goes on), `place_view` (selection + scroll clamped to the text, cursor revealed).
- `palette.rs` — `open_palette(picker, text)` / `close_palette` (also drops `file_history.picker` and `recent.picker`), `palette_command` (`PaletteCommand`), `palette_key` / `palette_paste` (input → `refresh_palette`), `accept_palette` (run a command, open a file at `file:line:col`, go to line, set a log level, a history entry → `history_picked`, a recent workspace → `open_recent`, a tool → `open_tool_log`), `palette_mouse`; quick open's walk (`start_file_walk`, once per opening, into `FileMatcher`) and `files_matched` / `files_walked`; the palette-only commands: `manage_trust`, `open_log_file` (→ `AppEvent::LogFileFound`), `open_user_settings` (`config::settings::create_if_missing` off-thread → `AppEvent::UserSettingsReady` → opens it), `set_log_filter`.
- `cursors.rs` — `match_command` (Cmd+D / Cmd+Shift+L / Cmd+Alt+D through `multicursor`, keeping the `MatchSession` with the view — group, tab, buffer — it belongs to), `cursor_undo` (Cmd+U: pops `view.cursor_history`, restores selections and scroll), `note_pre_event` (start of `handle_event`: scroll before the event, for the Cmd+U entry) and `track_selections` (end of `sync_views`; also `view.auto_closed.validate`, so auto-closed pairs end once the cursors leave them, as VS Code checks on every selection change).
- `find.rs` — the find / replace widget (`app.find`, a `find::FindWidget`): `open_find(replace)` (seeds from a one-line selection or the word under an empty cursor, escaped when regex is on, selects the query, selects its match; with replace and a query the replace input gets the cursor), `close_find`, `find_command` (`FindCommand`), `find_key` / `find_paste` (edits the focused input; edits to the query `research`: re-search and select the first match from the primary's start), `refresh_find` (after every event: re-searches only when buffer/revision/query/options changed; closes the widget when there's no tab), next / previous via `Matcher::find_next` / `find_prev` with wrap, toggles (flip `find_options`, end a non-word-mode Cmd+D session via `find_options_changed`, say so in the status bar when the widget is closed), Alt+Enter (every match a selection, focus to the editor), replace one (`EditKind::Other`, then next) and replace all (one `ChangeSet` built with `push` — straight from the cached matches when the replacement names no group — one `Buffer::edit`, selections mapped through it), `find_mouse` (clicks on toggles / inputs, from `hits.find`).
- `workspace_search.rs` — the Search view (`app.search_view`, a `search_view::SearchView`): `search_focused` (focus `SidePanel` with `ui.side_panel == Search`: the query or the results list has the keys), `find_in_files` (Cmd+Shift+F: show the view, seed from a non-empty one-line primary selection, regex-escaped when its regex is on, select the query, search at once), `search_command` (`SearchCommand`: toggles flip the view's own options and search at once; `ToggleDetails` (`…`, Cmd+Shift+J: shows / hides the files to include / exclude, focusing the Search view first from elsewhere); `NextInput` / `PreviousInput` (Tab / Shift+Tab: `SearchView::cycle`); `Refresh` (Enter) searches now; `FocusEditor` (Esc) back to the editor when there's a tab, results kept), `search_key` / `search_paste` (edit the focused input — `search_view.input`: query, include or exclude; from the list, the one that last had the keys; edits schedule a debounced restart; emptying the query searches — i.e. clears — at once), `find_in_folder` (`explorer.findInFolder`: the selected explorer folder as `path_filter::folder_pattern` in the include input, details shown, the query focused and selected, searched now; a file: a message), `search_tick(now)` (the event loop's deadline branch and `settle`: runs a due restart), `run_search` (the view's query → `start_search`, error into `search_view.error`), `search_click(m, count)` (toggle buttons and the `…` details button from `hits.search`; an input's rect gives it the keys; a result row by its key: the list takes the keys and selects it, a match row opens with the focus staying in the list, a double click (also on a file row: its first match) opens and focuses the editor; else the input takes the keys), `search_scroll` (wheel). The results list (`search_view.list_focused`, `Context::SearchResults`): `FocusResults` (Down in the query: the list, keeping its selection or selecting the first row), `Up`/`Down`/`PageUp`/`PageDown`/`First`/`Last` (Up from the first row hands the keys back to the query), `Open` (Enter: the selected match, or a file row's first, opened via `open_result` with the editor focused); `NextResult`/`PreviousResult` (F4 / Shift+F4, global: `SearchView::step`, opened without moving the focus; nothing without results). In the list a typed character goes back to the query and types there (paste too); other unbound keys do nothing. `open_result(target, focus)` joins the root and opens with `Goto::Match` in the active group — the last focused one while the side panel has the keys. Also `start_search(Query)` (drops the running search's `Handle`, which cancels it; bumps `search_generation`; collects rope snapshots of dirty buffers inside the root; empty pattern → finished empty `Results` without spawning; invalid regex or glob (`workspace_search::filter`) → `search = None` and the `SearchError`; the query's include / exclude go to the job as its `filter`) and `search_results(batch)` (`AppEvent::SearchResults`: `Results::add` drops stale generations; the handle is released when done). `app.search` is what `ui::search` draws.
- `syntax.rs` — language detection for buffers (`detect_language`: associations / name / first line; `add_buffer` sets it, `redetect_languages` after an explorer rename or a `.workspace` change to `[files] associations`, `load_associations` compiles them in `new` and on reload, reporting bad entries) and `sync_syntax` (every buffer's `Syntax::update` with `settings.syntax_max_bytes`; spawns the `ParseJob` it returns → `AppEvent::Parsed { buffer, parsed }` → `parsed`). `sync_syntax` runs once per event-loop turn before drawing, in `start`, and in the test helpers `pump`/`settle`; without a tokio runtime it does nothing.
- `lsp.rs` — `sync_servers` (each loop turn, `start`, `pump` / `settle`; nothing before `lsp.started()`; when `servers_dirty` — set by `add_buffer`, `redetect_languages`, `decide_trust`, `config_loaded` — hands the open buffers' languages, `.workspace` and `trust` to `lsp::Manager::sync`; then always `lsp.sync_documents(&mut buffers)`: opens / closes / updates documents, so renames, language changes and closed tabs need no hook), `save_done` calls `lsp.saved(buffers, id)` (`didSave`), `lsp_event` (`AppEvent::Lsp`: `Event::Diagnostics` → `Manager::publish` (into the store and the file's buffer); anything else → `Manager::handle` → `notify`; then, as after `sync_servers`, `drop_cleared_diagnostics`: marks of servers the manager dropped are cleared from every buffer), `add_buffer` places stored diagnostics (`lsp.load_diagnostics`), `shutdown_servers` (async; tests after `Quit`; `run` quits through `tasks.rs`'s `shutdown`). Requests: `Request` (`Hover { word }`: `Some` = the mouse's run; `Definition { word }`; `Completion { generation }`: current while `completion.ask` has that generation and the cursor stays in its word, edits or not; `Resolve { generation, index, accepted }`: current while that list is shown, or with `accepted` while the buffer is at that revision; `References { word }`, `PrepareRename { word }`, `Rename { old, new }`, `Format`: current like hover / definition), `Pending`, `send_request` / `send_request_with(…, extra)` (cancels a pending one of the same kind, then `lsp.request_at`; false when no server takes it), `send_doc_request` (no position: formatting), `send_server_request` (params as given: resolve), `cancel_requests(which)`, `check_requests` (end of `handle_event`: cancels pending requests whose buffer was edited or whose cursor / pointer moved — `request_current`), `answer` (`Event::Response` by (server, id): stale → dropped; a routine error (`RpcError::is_routine`: cancelled, ContentModified) → dropped quietly, a completion's `ask` cleared; other errors → dropped (a definition error says "No definition found", a references error "No references found for 'w'", a prepareRename error its message, a rename error "Rename failed: …"), else `hover_answer` / `definition_answer` / `completion_answer` / `resolve_answer` / `references_answer` / `prepare_rename_answer` / `rename_answer` / `format_answer` (an error: "Format Document failed: …"); a completion error to Ctrl+Space says "No suggestions."); `Failed` / `Exited` drop the server's pending requests.
- `problems.rs` — the bottom panel and its Problems list (`app.problems`, a `problems::ProblemsView`; drawn by `ui::panel`): `toggle_panel` (Cmd+J: show + focus, or hide — the editor, else the side panel, gets the keys back if the panel had them), `toggle_problems` (Cmd+Shift+M: show + focus the list, or hide when it has the keys), `problem_counts_clicked` (status bar counts: show + focus, or hide when it shows Problems, focused or not), `focus_panel(tab)` (selects the first row when nothing is), `problems_command` (`ProblemsCommand`: Up/Down/PageUp/PageDown/First/Last move the selection (Up at the top stays), `Open` (Enter: `ProblemsView::target`, opened selected with the editor focused), `FocusEditor` (Esc, when there's a tab), `Next`/`Previous` → `step_problem`), `open_problem(target, select, focus)` (`open_file` with `Goto::Problem` in the active group), `step_problem` (F8 / Shift+F8, global: `problems::step` from the active view's primary selection start, with `last_problem` (path, index, cursor position) so problems at one place go one by one; cursor at the start, focus unchanged, the list's selection follows, the message (icon, one line, `source(code)`, "(k of n)") set as `app.message` without logging; VS Code shows a peek instead), `problems_click(m, count)` (as `search_click`: a problem row opens keeping the list focused, a double click — also a file row's — focuses the editor), `problems_scroll` (wheel). `problems::files` is rebuilt per use (cheap: per file, not per problem).
- `hover.rs` — hover (`app.hover`, `hover::HoverState`): `show_hover` (the command, `editor.showHover`, Cmd+Alt+I: closes the popup, asks for the active view's cursor; no server → "No hover information"), `hover_answer` (the popup anchored at the server's range, else the mouse's run / the word at the cursor; records the view's scroll and the buffer's revision; an empty answer to the command says so), `close_hover` (popup, rest timer and pending hover), `hover_mouse(m, hit)` (first in `handle_mouse`: over the popup the wheel scrolls it and every event stops there; `Moved` over text (`hover_target`: any group, not past a line's end or on blank space) starts / keeps `Rest` (the same run keeps its deadline) and sets `hover.mouse`; moving off a mouse-opened popup's range closes it, a command-opened one stays; other mouse events elsewhere close it), `hover_tick(now)` (the rest deadline: a mouse hover request), `check_hover` (after every event: closes the popup when its buffer's revision, its group's tab or its view's scroll changed). A key closes it in `handle_event`; Esc in the editor only does that.
- `completion.rs` — completion (`app.completion`, a `completion::Completion`; drawn by `ui::completion`): `completion_shown` (the list has rows and belongs to the active editor with the keys: `Context::Suggest`), `trigger_suggest` (Ctrl+Space, `editor.triggerSuggest`; no server → "No suggestions."), `ask_completion(trigger)` (at the primary cursor, `context.triggerKind`; the `Ask`'s `Anchor` snapshots the rope), `completion_typed(c)` (after a typed char: a server trigger character closes the list and asks; a word char with no list or request starts `quick` — `QUICK_DELAY` 10 ms, with `settings.quick_suggestions`), `completion_tick(now)` (the timer: asks if the revision is unchanged, the cursor is after a word and not in a string / comment by the tree), `completion_answer` (`completion::place` + `Popup::refilter` by what was typed since; nothing matching closes it unless incomplete; then `resolve_selected`), `check_completion` (after every input and background event: drops a no-longer-current `ask`; closes when the editor lost the keys, the tab changed or the cursor left the word — Backspace past its start too; else refilters, an incomplete list asks again with `triggerKind` 3), `close_completion`, `suggest_command` (`SuggestCommand`: Up / Down wrap, PageUp / PageDown, Accept (Enter / Tab), Close (Esc)), `completion_commit(c)` (a commit character of the selected item inserts it before the char is typed), `accept_completion(row)` (`completion::insert` at every cursor with the item's range relative to the primary — `start - lead` to `max(at + after, head)` — and its additional edits read in the snapshot and mapped by `Anchor::now`; an unresolved item without additional edits gets an `accepted` resolve after the insert, whose additional edits go in as their own step while the buffer is unchanged), `resolve_selected` (`completionItem/resolve` of the selected item when the server resolves), `resolve_answer`, `completion_mouse(m, hit)` (first in `handle_mouse`: over the list a click inserts that row, the wheel scrolls; a click or the wheel elsewhere closes it). `sync_views` hands every buffer's applied sets to `completion.follow`.
- `locations.rs` — go to definition (F12 `editor.revealDefinition`, Ctrl/Cmd+Click in `editor_click`) and references (Shift+F12 `editor.goToReferences`: `go_to_references` with `context.includeDeclaration`, `references_answer`: none → "No references found for 'w'", else always the list — one too — titled "References to 'w'"); `cursor_word` (the active group, buffer, primary head and the word there; seals undo) is shared with rename: `go_to_definition` (the word at the cursor for messages; no server → "No definition found for 'w'"), `definition_answer` (none → that message; one → `open_file` with `Goto::Problem { Place::Lsp, select: false }` (a cursor at its start, centred) and the jump recorded in the view's `cursor_history` so Cmd+U returns (a background answer has no key to record it; a file still loading starts its own history); several → `show_locations`: `app.locations` (`locations::Locations`, `locations_generation`), previews of open buffers at once and of other files via `spawn_blocking` → `AppEvent::LocationsRead` → `locations_read` (other generations dropped), the panel's Locations tab focused with the first place selected), `locations_command` (`LocationsCommand`: as the Problems list's; `Open` → `open_location` with the editor focused), `locations_click` (as `problems_click`), `locations_scroll`.
- `rename.rs` — rename symbol (F2 `editor.rename` in the editor; the explorer's F2 renames files): `rename_symbol` (read-only buffer or no rename server → message; with `prepareProvider` a `PrepareRename` request, else the word at the cursor (none → "The element can't be renamed.")), `prepare_rename_answer` (`rename::parse_prepare`: placeholder, else the range's text, `defaultBehavior` → the word, `null` → refused), `open_rename_prompt` (`InputKind::RenameSymbol` with the buffer's revision, the name all selected), `request_rename` (the prompt's Enter: `textDocument/rename` + `newName` at the same cursor; refused if the buffer changed), `rename_answer` (`rename::parse_workspace_edit`; every open file checked first — read-only, `version` ≠ `lsp.version`, overlapping edits refuse the whole edit — then each open buffer edited (`apply_changes`: one `EditKind::Other` step, sealed both sides; the active view's selections via `rename::follow`, undo restoring a view of that buffer's selections) and each file not open loaded through `open_for_edit` (a missing file is an error, not an empty buffer); `follow_edits`; "Renamed 'a' to 'b': n edits in m files"), `apply_pending_edits` (`opened`: the loaded buffer's edits, read-only → error). Files not open stay unsaved in their tabs (VS Code's dirty editors).
- `format.rs` — format document (`editor.formatDocument`, Shift+Alt+F / Linux Ctrl+Shift+I): `format_document` (read-only → message; seals undo; `send_doc_request` `textDocument/formatting` with `format::options` of the buffer language's settings; no server or no `documentFormattingProvider` → "There is no formatter for 'cpp' files installed."), `format_answer` (`format::parse` → `rename::changes` → `format::minimize`; empty → nothing; else `apply_changes` (rename's: one `EditKind::Other` step, selections via `rename::follow`) + `follow_edits`; an error / unreadable answer → "Format Document failed: …"). Stale like hover (text or cursor changed: cancelled, VS Code's rule).
- `git.rs` — the git status (`app.git`, a `GitState`: `status: Option<git::Status>` — `None` before the first read or with no repository, git features off — and the refresh in flight): `refresh_git(changed)` (`git::refresh` in `spawn_blocking` → `AppEvent::GitRefreshed { result, elapsed }` → `git_refreshed`; one at a time: a request while one runs is queued, merged with any other — `None` (read regardless) wins over path lists — and run when it ends), started in `start()` and by `git_paths_changed` (from `flush_fs_changes`, so debounced with `FS_DEBOUNCE`: the paths `Repo::affects_status` keeps; with no repository yet only a path inside a `.git` (`git init`), or any path while the first read runs (it may have read the files already)); the background task skips the read when every changed path is `.gitignore`d (`Refreshed::Unchanged`). `git_refreshed` watches the git directory when it's outside the workspace root (`Watcher::watch`, once) and warns on a slow read (`SLOW_TASK`). Reading the status writes nothing in `.git`, so it never triggers itself. Every status read (and losing the repository) calls `quick_diff_index_changed` (the gutter markers compare against the index), `blame_head_changed` (inline blame, against HEAD), `diffs_index_changed` (diff tabs read git's sides again) and `scm_status_changed` (the Source Control view's selection settles on its file or what took its place).
- `git_history.rs` — the Explorer view's "Git History" section (`app.git_history`, a `git_history::GitHistory`; drawn by `ui::side`): `sync_git_history` (each loop turn — `start`, `run`, `pump` / `settle`; nothing without a runtime: follows `active_path` (a diff tab counts as its file), resetting and reading page 1 when it changes — reads only while the section is on screen (side bar shown, Explorer view, not collapsed): otherwise the reset marks it `stale`, read when it shows; only with `git.status` and `repo.relative(path)`, else the section says "No history"; when `stale` — HEAD moved, the repository changed or was lost, set by `git_refreshed` comparing `Status::head_id` and `git_history_head_changed` — reads page 1 again for the same file, keeping the selected commit if it is still there (else the first) and scrolling to the top only when the first commit changed; reads the page after the loaded ones when `more` and the list is near its end), `history_repo`, `history_page` (`git::log::commits` in `spawn_blocking` → `AppEvent::GitHistory { path, skip, generation, result }`, one page at a time), `git_history_done` (stale generations / paths dropped; a first page replaces the list, later ones append only when `skip == commits.len()`; an error is drawn instead of the rows), `git_history_command` (`GitHistoryCommand`: Up / Down / PageUp / PageDown / First / Last move the selection, `Open` (Enter, or a click on a row; with nothing selected Enter selects and opens the first row) → `open_commit` with `git_history_file` (the history's file, work-tree-relative), `FocusTree` (Left / Esc) back to the tree), `git_history_focused` (`Context::GitHistory`). A commit tab is no file (`active_path()` is `None`), so the section says "No history" while one is active; its rows come back on the file's tab.
- `disk.rs` — open files changed on disk (`app.disk`, a `DiskChecks`: checks running, wanted `again` (with `force`), `checked` / `reloads` counters; its tests hand `disk_checked` hand-made `Checked` results to play checks racing a save or an edit): `disk_paths_changed(paths)` (buffers whose path or an ancestor is among them), `check_disk(id, force)` (`disk::check` in `spawn_blocking` → `AppEvent::DiskChecked(Box<Checked>)`; waits while one runs or the buffer saves; a base rope only when the buffer has no edits or `force`), `disk_checked` (a save started / ended since → again after it; `Missing` → `deleted` (only once the file was on disk: `disk()` is `Some`); `Unchanged` → not deleted, no conflict; `Changed` → banner (`disk_conflict`) with edits, else reload — again if the buffer changed since the read; binary / not UTF-8 → message + banner unless forced), `disk_save_done(id)` (from `save_done`), `apply_reload` (`Buffer::reload`, then every view on the buffer — the active one too, unlike `follow_edits` — `map_through` its applied sets, so each viewport stays on the same text; then each view's selections set from `rename::follow` computed before, Cmd+U history reset), the commands `reload_from_disk` (`file.reloadFromDisk`: a forced check of the active buffer) and `keep_mine` (`file.keepMine`: `Buffer::keep_mine`). The banner's buttons are `Hit::Banner(group, Some(action))`: `left_click` focuses the group and runs `action.command()`.
- `quick_diff.rs` — the gutter's git markers and staging from them (`app.quick_diff`, a `QuickDiffState`: the delay's `deadline`, `after_save`, `peek`, `staging`): `sync_quick_diff` (each loop turn, `start`, `pump` / `settle`, and the `Timer::QuickDiff` deadline; Things to know before editing:

- **Background work pattern:** clone `self.tx`, `tokio::task::spawn_blocking`, send an `AppEvent` variant, handle it in `handle_app_event`. In-flight sets (`listing`, the `opening` map) dedupe requests. Restartable work (quick open's walk, workspace search) carries a generation number so results of a replaced run are dropped, and a cancel flag (`Arc<AtomicBool>`; workspace search's `Handle` sets it on drop). Saves report `state` back so `finish_save` marks the right history state.
- `App::lsp` gets its event sink in `start()`; no server is spawned before that (`add_buffer` only marks `servers_dirty`).
- `App::new` must start no background work (it once crashed by spawning before the runtime existed); put it in `start()`.
- `Focus` is `Editor` (`Context::Suggest` while the completion list is shown: its keys first, then the editor's; `Context::Diff` while the active tab is a diff, `Context::Commit` while it's a commit, likewise), `SidePanel`, `Find` (the find widget's input; `find.field` picks `Context::Find` or `Context::Replace`) or `Panel` (the bottom panel; `ui.panel_tab` picks the context: `Problems`, `Locations` or `Task`; unbound keys and paste do nothing there, except in a task tab: its task gets them); `context()` maps it to the keymap `Context` (`SidePanel` is `Explorer`, or `Search` / `SearchResults` (by `search_view.list_focused`) when the side panel shows the Search view: unbound keys and paste then edit its focused input (query, files to include or exclude), never the buffer; `focus_side` gives that input the keys) (`Palette` whenever `app.palette` is open; the palette doesn't change `Focus`); with the Source Control view shown it is `Scm` (unbound keys and paste do nothing); with the Explorer shown and its Git History section focused (a click or the header) it is `GitHistory` (unbound keys and paste do nothing). The find widget stays shown when focus leaves it (an editor click sets `Focus::Editor`); Esc in the editor then closes it before dropping cursors. Starting with no file, or closing the last tab while the side panel is visible, focuses the side panel.
- The palette (`app.palette`) is not a `Prompt`: its keys go through the keymap's `Palette` context, unbound keys edit its `TextField`, and while it's open it takes every mouse event (click outside closes it). A prompt opened on top of it gets keys first. `execute` closes it before running any other command.
- Quick open: `FileMatcher`'s notify callback sends `AppEvent::FilesMatched` at most once until handled (`files_pending`); handling it calls `tick()` (never waits) and rebuilds rows. `FilesWalked { generation }` marks the walk done unless a newer walk started.
- `set_keymap(keymap, errors)` (from `main`) replaces the keymap and shows the first load error (`report_errors`: `settings.toml`'s and `keybindings.toml`'s, `(and N more)`); `log` (reload handle, `None` if logging is off) and `log_dir` are set by `main` / tests; `config_dir` (`paths::config_dir()`, where "Open User Settings" looks) and `state_dir` (`Some(paths::state_dir())` outside tests, `None` in them: sessions off unless set) by tests.
- A prompt swallows all keys and mouse events; `close_prompt()` re-opens a pending trust prompt (`trust_pending`), else a pending backup offer (`offer_backups`). Esc/Enter/letter handling per prompt is in `handle_prompt_key`; unrecognised keys put the prompt back.
- Leaving a tab/group (`activate_tab`, `cycle_tab`, `focus_group`, `split`, editor click) calls `buf.seal_undo()` first.
- Closing: the save prompt appears only when the tab is the last one (in any group) showing a dirty buffer (`groups.tabs_showing`); a diff tab closes without asking. `discard_tab` drops the buffer when no tab shows it and closes an empty group (never the last). `AfterSave::{Quit, Close}` continues a close/quit once saves finish.
- `sync_views` runs after every input event: the editing tab only re-anchors its viewport; every other view on the buffer runs `View::map_through`. Then `track_selections`: if the active view's buffer changed its Cmd+U history is reset, else a selection change pushes the previous list; any selection change not made by a match command (`session_changed`), or focus leaving the editor (palette, prompt, side panel, find widget), ends the Cmd+D session (VS Code's rule; word mode resets with it). Only input events are tracked, so selections set by background results are recorded at the next key.
- `find_options` (`search::Options`: case / whole word / regex) belongs to the find widget's toggles and is what Cmd+D uses for selected text (case and whole word only); toggling ends a Cmd+D session that uses them (not word mode).
- The bottom panel: `ui.panel_visible`, `ui.panel_height` (`PANEL_HEIGHT` = 10 until dragged; border and tab strip included), `ui.panel_tab` (`PanelTab::Problems` / `Locations` / `Task(id)` — a closed run's tab is never left there: `close_task`; `focus_panel(tab)` selects the tab's first row when nothing is). Cmd+B only moves the focus to the editor when the side panel had it.
- `update_crash_snapshot` (`app/backup.rs`) runs every loop turn so the panic hook can back up dirty buffers (into `state_dir`; nothing without one).
- Messages: `notify(Level, text)` sets the status-bar message and logs it; any key press clears it.
- Timers: `next_timer()` sleeps until the earliest of `fs_deadline`, `search_view.deadline()`, `hover.deadline()` (the mouse's rest, `hover::DELAY` 300 ms), `completion.deadline()` (quick suggestions, `completion::QUICK_DELAY` 10 ms), `quick_diff.deadline()` (edited buffers' gutter markers, `quick_diff::DELAY` 150 ms), `diffs.deadline()` (diff tabs of edited buffers, `diff_view::DELAY`), `blame.deadline()` (edited buffers' inline blame, `blame::DELAY` 300 ms), `backups.deadline()` (crash backups, `backup::INTERVAL` 30 s) and `log_tabs.deadline()` (log tabs' wake throttle, `tools::LOG_FRAME` 20 ms) (forever when none is set; the future borrows nothing) and `on_timer` runs it (`flush_fs_changes` / `search_tick` / `hover_tick` / `completion_tick` / `sync_quick_diff` / `sync_diffs` / `sync_blame` / `backup_tick` / `logs_tick`). `run`'s `select!` and `settle` both use this pair, so a new deadline goes there, not in a new `select!` branch.
- The Search view's query is debounced (`search_view::DEBOUNCE`, 150 ms) via `search_view.deadline()`; starting a search drops the running one's `Handle`.
- File system events are debounced (`FS_DEBOUNCE`, 100 ms) via `fs_deadline` (those under `<root>/.jed/` dropped first, `fs_changed`); explorer renames/deletes update open buffers' `path`/`deleted`.
