# syntax

Language detection, parse trees and highlight spans. No drawing (the editor draws the spans).

- `language.rs` — `Language` (`PlainText`, `C`, `Cpp`, `Python`, `Rust`, `Markdown`, `Yaml`, `Json`, `Jsonc`, `Xml`, `Toml`, `ShellScript`, `CMake`, `Makefile`, `Dockerfile`): `id()` (VS Code's ids: `plaintext`, `c`, `cpp`, `python`, `rust`, `markdown`, `yaml`, `json`, `jsonc`, `xml`, `toml`, `shellscript`, `cmake`, `makefile`, `dockerfile`, which LSP's `languageId` and `.workspace` associations use), `name()` (status bar, VS Code's: "JSON with Comments", "Shell Script", …), `grammar()` (tree-sitter `Language`; crates `tree-sitter-{c,cpp,python,rust,md,yaml,json,xml,toml-ng,bash,cmake,make,containerfile}`, all on `tree-sitter-language`; Markdown is the block grammar only (`tree_sitter_md::LANGUAGE`), so inline emphasis / code spans / links aren't parsed; JSON and JSONC share tree-sitter-json, which accepts comments), `highlight_queries()` (the grammar's `highlights.scm`, C++'s after C's, then jed's additions in `queries/<lang>.scm`: control keywords, built-in types, parameters, `self`, YAML keys as tags, XML tag punctuation, … for Dark+'s colours; for the same node a later pattern wins, so additions go last; Rust starts with an inline `(identifier) @variable`; CMake (`#lua-match?`, which tree-sitter ignores) and TOML (captures whole pairs) use only jed's query). `Associations` compiles `[files] associations` (glob → id; a glob with `/` matches the path relative to the root, else the file name; bad globs / unknown ids are returned as errors). `detect_path(path, root, associations)` (associations, then the name: `None` = the shebang decides) and `detect_shebang(first_line)` (else plain text) are its two halves, for a diff tab whose text is read off-thread. `detect(path, root, first_line, associations)`: associations, then `by_name` (exact names first: `Makefile` / `GNUmakefile`, `CMakeLists.txt`, `Dockerfile` / `Containerfile`, `Cargo.lock` / `Pipfile` / `poetry.lock` / `uv.lock` and jed's `.workspace` (TOML), `tsconfig.json` / `.eslintrc` / … (JSONC), `.clang-format` (YAML), shell dotfiles `.bashrc` / `.zshrc` / `.profile` / … and `PKGBUILD`; then `Dockerfile.*` / `Containerfile.*`, `tsconfig.*.json`, `.vscode/*.json` (JSONC); multi-dot suffixes `.js.map` / `.csproj.user`; then the extension, case-insensitive, VS Code's lists; a dotfile's name isn't an extension (`.c` is plain text); `.h` is C++ as in VS Code; `SConstruct`/`SConscript`/`*.scons` are Python), then the shebang's program (`env`, its options and `VAR=x` skipped; a trailing version allowed): `python*`/`pypy*` → Python, `sh`/`bash`/`zsh`/`ksh`/`dash`/`ash`/`mksh`/`yash`/`csh`/`tcsh`/… → shell, `make` → Makefile. Pure: no I/O.
- `config.rs` — `LanguageConfig` (`Language::config()`), VS Code's `language-configuration.json` data: `line_comment` (`//` for C/C++/Rust/JSONC, `#` for Python/YAML/TOML/shell/CMake/Makefile/Dockerfile; none for plain text, JSON, Markdown and XML: block comments only, which comment line doesn't do), `pairs` (`AutoPair { open, close, not_in_string, not_in_comment }`, single chars only: no `/*` / `/**` / `<!--` pairs), `brackets` (VS Code's `brackets`, single chars: auto-indent and bracket matching; `{}` `[]` `()` mostly, JSON `{}` `[]`, TOML `{}` `[]`, XML `<>` `{}` `()`), `tree_tokens` (false for Markdown: its block tree keeps a paragraph's text in one leaf, so brackets are read from the text, see `Syntax::token_tree`), `insert_spaces` (a language-specific default over the user's setting: `Some(false)` for Makefiles, VS Code's `[makefile]`; `edit::Settings::for_buffer` applies it, over any indentation guessed from the text), `surround` (C/C++/Rust also `<>`, Python and shell backticks, Markdown also `` ` `` `_` `*` `~` `$`), `close_before_quotes` / `close_before_brackets` (VS Code's `autoCloseBefore` defaults: none of the languages sets its own), `string_prefixes` (Python `r u f b`: VS Code's `f'`, `r"`, … pairs, `notIn` strings and comments). `notIn` per VS Code's files: C/C++ `'` not in strings or comments, `"` not in strings; Python `'` not in strings or comments, `"` and backtick not in strings; Rust only `"` among the quotes (lifetimes), not in strings; JSON / JSONC every pair not in strings, `"` and backtick not in comments either; YAML both quotes anywhere; XML `'` not in strings or comments, `"` not in strings; TOML, shell, CMake, Dockerfile quotes not in strings; Makefile as C; Markdown `<` not in strings, quotes don't auto-close. TOML and CMake have no VS Code built-in: Even Better TOML's and the CMake extension's data. Plain text = VS Code's built-in plaintext config: brackets auto-close, quotes don't; wraps in brackets, `<>`, quotes, backticks. Helpers: `is_pair_char`, `pair_opened_by`, `closes`, `brackets()`, `surround_for`, `closes_before(open, next)`; `is_quote`. A `const fn config(…)` builds the common case (default `autoCloseBefore`, tree tokens, user's indentation); `..config(…)` overrides the rest.
- `mod.rs` — `Syntax` (one per `Buffer`): `language()`, `scope_before(pos)` (`Scope::{Code, String, Comment}` of the char before `pos`: the smallest node holding it and its ancestors, each asked `scope_of(kind)`; `None` without a current tree — auto-close's `notIn`), `scope_of(kind)` (the one table of node kinds across the grammars: a kind containing `comment` (or XML's `Comment`) is a comment; one containing `string` (not Dockerfile's `unquoted_string`) or `char_literal`, YAML's quoted / block scalars, `heredoc_body`, CMake's quoted / bracket arguments, XML's `AttValue` / `EntityValue` / … is a string; `interpolation`, shell `expansion` / `simple_expansion` / `command_substitution` and CMake's `variable_ref` are code again; else the parent's; also used by `indent.rs` for trailing comments and closers in strings), `set_language` (a change drops the tree), `tree()` (`Some` only when current), `token_tree()` (the current tree when `LanguageConfig::tree_tokens`: what bracket matching and auto-indent read brackets from; Markdown's is `None`, so they scan the text), `tokens()` (a `Tokens` walk over the `token_tree`), `edit(changes, old, new)` (from `Buffer::apply`: each change → an `InputEdit` in the coordinates left by the earlier ones, positions via `pos::ts_point`; a set over `COALESCE_AT` (256) changes → one edit spanning them, or, spanning over `INLINE_BYTES`, back to `Wanted` with the old tree kept in `discard` for the next `ParseJob` to free off-thread), `update(rope, max_bytes)` (called by `App::sync_syntax`) and `parsed(Parsed)`. `highlight_text(language, text)` (blocking): one full parse of a text no buffer holds and `highlight::compute` over all of it (a diff tab's sides; the caller applies the size limit).
  - States: `Off` (no grammar), `TooLarge` (over `max_bytes`, 0 = never), `Wanted` (needs a full parse), `Parsing` (a background parse in flight: edits made meanwhile queue up and are applied to its result, up to `MAX_QUEUED` (4096) before it restarts; replacing the state drops `Cancel`, which stops the parse), `Ready` (tree + edits since it was parsed).
  - `update`: small pending edits (≤ `INLINE_EDITS` changes touching ≤ `INLINE_BYTES`) are re-parsed incrementally on the UI thread, stopping after `INLINE_TIME` (8 ms: with the highlight query and the frame a key stays near 10 ms); anything else (first parse, big edits, a re-parse that ran out of time) returns a `ParseJob` (rope snapshot + the edited old tree) for `spawn_blocking`; `ParseJob::run` is blocking and returns `Parsed` (dropped by `parsed` unless its generation is current; a tree finished after its cancel is freed in the job, not on the UI thread).
  - `parse` reads the rope chunk by chunk (`pos::chunk_from`, no copy). A stop (deadline or cancel) is checked in both the progress callback and the read callback (one lexer step can scan to the end of the file, e.g. an unterminated `/*`); once stopped it reports end of text and the result is dropped.
- `highlight.rs` — `KEYS` (the theme keys a capture can map to; each is in `Theme::dark_plus`; besides the code token keys, `markup.heading` / `markup.list` / `markup.quote` / `markup.raw` / `markup.link` for Markdown and `tag` / `tag.attribute` / `punctuation.tag` for XML (YAML keys are `tag`, Dark+'s `entity.name.tag.yaml`)), `ALIASES` (the grammars' own names for those: `boolean` → `constant.builtin`, `string.special.key` → `property`, `string.escape` → `escape`, `keyword.conditional` / `conditional` / `include` / … → `keyword.control`, Neovim's `text.title` / `text.literal` / `text.uri` / `text.reference` → markup keys), `highlight_for(capture)` (the dotted name, else its longest prefix, each in `KEYS` then `ALIASES`: `function.method` → `function`; none → uncoloured, and an uncoloured capture doesn't paint, so an earlier pattern's colour for the node stays), `Span { start, end, highlight }` (`ByteIdx` range; `Highlight::index()` indexes `KEYS`). Each language's query is compiled once (`OnceLock`; `warm` is called by `ParseJob::run`, so the UI thread never compiles it). `compute(language, tree, rope, start, end)`: a `QueryCursor` over the byte range (text predicates read the rope via `pos::bytes_in`), captures painted into a byte array (outer nodes first, inner over them; for the same node the later pattern wins), run-length encoded into sorted, non-overlapping spans clipped to the range (a block comment opened above the range colours its part).
  - `Highlights` (inside `Syntax`, reached through `Syntax::spans(rope, lines)`): up to 4 cached `Region`s (a byte range + spans + the `tree_version` they came from). With a current tree: a region of that version covering the lines, else query the lines ± `MARGIN` (50) and cache it (older versions dropped). Bytes are capped so one query stays under ~7 ms (~0.3 ms per KB of dense C++): only `MAX_QUERY_BYTES` (16 KB) from the first requested line's start are coloured (a 1 MB minified line: just its start, as VS Code stops tokenizing long lines), and the margin is at most `MARGIN_BYTES` (4 KB) either side; a caller wanting more (the Minimap) asks in pieces. Without one (re-parse running): the newest region that covers or overlaps, mapped through every change set by `Syntax::map_highlights` (from `Buffer::apply`; span starts `Assoc::After`, ends `Before`, so text typed at a span's edge stays plain until the new tree; emptied spans dropped). Positions are only compared, never used to index the rope. `set_language` and going `TooLarge` clear the cache. `tree_version` is bumped whenever a new current tree is installed (inline re-parse, or a background result with no edits queued).
  - Tests (in `highlight.rs`): prefix and alias mapping, every language's query compiling with each capture name mapped to a key or listed as intentionally plain (`attribute`, `none`, `embedded`, `spell`, `markup` (XML text), `@_` predicate names, …), exact spans for a snippet per language (C / C++ / Python / Rust / Markdown / YAML / JSON / JSONC / XML / TOML / shell / CMake / Makefile / Dockerfile), `#match?` predicates (also on a node spanning rope chunks), a comment opened above the range, the cache (`highlight_queries_run()` counts misses: none when nothing changed; stale spans shifted by an insert; right after the re-parse), stale span edges, deleted spans, language change and the size limit dropping the cache, the long-line cap.
- `tokens.rs` — `Tokens`: a `TreeCursor` walk over the tree's leaves for positions asked in increasing order (each node stepped over once; an earlier position restarts from the root): `leaf_from(b)` (first leaf ending after `b`; zero-width missing leaves skipped), `leaf_at(b)` (the leaf holding `b`, `None` between tokens), `is_token(b, text)` (a bracket that isn't inside a string / comment: those are single leaves or content leaves), `node_at(b)` (the leaf holding `b`, else the innermost node with `b` in a gap between its children: Rust's `line_comment` / `block_comment` hold only their delimiters as leaves; what auto-indent asks `scope_of` about), `each_leaf(lo, hi, f)`. Avoids `descendant_for_byte_range` per position, which scans a node's children linearly (a root with 60k children).
- Logging under `jed::syntax`: parse times at debug, `slow parse` warning over 500 ms.
- Tests (`tests.rs`) drive `Syntax` through a `Buffer` without the app: `scopes_in_every_language` (string / comment / code positions per grammar), `scope_kinds`, `markdown_has_no_token_tree`; `update` → `job.run()` → `parsed`; the random-edit test compares the incrementally kept tree with a fresh parse (S-expression and every node's range and positions); `input_edits_match_a_reference` checks the `InputEdit`s against ones computed by applying each change to a string. tree-sitter's error recovery can differ between incremental and fresh parses after many broken edits, so it runs a fixed number of seeded steps.
