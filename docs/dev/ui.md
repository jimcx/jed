# ui drawing (detail)

Every widget and editor drawing rule in `src/ui/` in full. `src/ui/CLAUDE.md` keeps the rules that apply to all drawing plus one line per widget; read the entries here for what you touch.

- `mod.rs::render` computes `layout::compute` regions, draws activity bar → side panel → commit tabs fitted to their groups' text width (`fit_commit_tabs` → `App::fit_commit_tabs`, `editor::text_width`) → each group (tab bar, the changed-on-disk banner when its active buffer — or the open buffer of its active diff tab's file — has a `disk_conflict` (`banner::render` on the editor's first row; the editor gets the rest, `GroupHit::banner`), editor or diff view (`diff::render`, `GroupHit::diff`), a shell tab (`task::render_shell` over the whole area, no scroll bar column; `GroupHit::editor`), a text or diff tab's scroll bar in the editor's last column (`scrollbar::render`, `GroupHit::scrollbar`; the changed lines' marks under the thumb; the editor / diff, `GroupHit::editor` and the find widget get the rest)) from `groups.tree.layout` (before the dividers, a dragged tab's target editor zone is `set_style`d in `editor.dropBackground`: `App::tab_drop_shade` gives the whole editor for a centre drop or the half an edge band would split off) → dividers → the bottom panel (`regions.panel`, when `ui.panel_visible`) → status bar → find widget (over the active group's editor) → the gutter's peek (`quick_diff::render`; `hits.quick_diff`) → hover popup (`hover::render`, over its group's editor; `hits.hover`) → completion list (`completion::render`; `hits.completion`) → code action list (`code_action::render`; `hits.code_actions`) → palette → cheat sheet (`hits.cheat_sheet`) → dialog (last, on top). It builds a fresh `HitMap` and stores it in `app.hits`; mouse handling uses the *previous* frame's map. Below 30×4 it draws nothing.
- Each widget's `render` returns what it drew for hit-testing (`activity` → icon rows, `side` → `SideHits` (explorer row area, the Search view's `SearchHit`, the Source Control view's `ScmHit`, the Tools view's `ToolsHit`), `tabs` → `TabBarHit` (each drawn `TabHit`, and the `TabArrows` while the tabs overflow the bar), `editor` → text rect without the gutter and any merge conflict action-row buttons); add new clickable things the same way (a `Hit` variant in `layout.rs`, filled here).
- `tabs::render` scrolls a bar narrower than its tabs (`Group::scroll`, `‹` / `›` in `tab.scrollArrow` / `.disabled` at its ends; the tabs between them) and reveals the active tab only when it or the bar's width changed (`Group::revealed`), so the wheel and the arrows can scroll it away from the active tab. With two or more groups (`number` from `Groups::ids()`), the bar's last cells are the group's number in reading order (`tab.groupNumber`); the tabs are laid out in `bar` left of it, so an overflowing bar's `›` sits one cell left of the number, and a click on those cells is `Hit::TabBar` → `App::focus_group`.
- `editor::render` mutates the `View`: sets `height`/`width` (used by page movement), re-anchors `set_top_line` (the buffer may have changed), and applies `reveal_range` (`reveal_in_center`, Cmd+D), else `reveal_pos` (`scroll_to`, minimal scroll to a position: add cursor above/below, box select), else `reveal_cursor` via `scroll_to_cursor`, clearing them. Commands that move cursors set `view.reveal_cursor = true` and let the next frame scroll. It also measures each drawn line's whole width (past the right edge only summed, `pos::col_after`: printable ASCII runs counted by bytes, graphemes only around the rest) into `view.scroll_width` (`scrollbar::ScrollWidth`), for sideways scrolling; visible lines only. With `Overlay::wrapping` it draws the wrapped rows `visual_rows` maps out from `top_line`/`top_row` instead: continuation rows start at the line's indentation, only a line's first row has its number (and quick-diff mark), nothing is measured for sideways scrolling (the horizontal bar is off), the byte-range overlays cover just the drawn rows, the line-end bits / merge labels / blame land on its last row, and the terminal cursor goes on the row the primary is on. `visual_rows` also reports each row's byte slice within its line, from `wrap::Wrap::layout` (cached by revision and width).
- `editor::render` takes an `Overlay { focused, find, whitespace, blame, wrapping }`: `find` is the find widget only for the active group, when its cache `is_current` for this buffer and revision; `wrapping` is `App::word_wrap`. Find matches on screen come from `FindWidget::matches_in(viewport)` (never a search per frame) and are walked with one index like selections: others `editor.findMatchHighlight`, then the selection, then the match that is the primary selection `editor.findMatch`.
- `find::render` draws the open find widget at the top right of the active editor (≤ 64 wide): the find input (scrolled to its cursor, placeholder when empty, `editor.selection` when all selected), toggles `Aa ab .*` (`find.option` / `find.option.active`), the count; the replace input row; an invalid regex's message (`dialog.error`) on the last row. Over a hex tab: a fourth toggle `0x` (`find_options.hex`), `ab` / `.*` in `find.option.disabled`, no replace row, `HexFind::count_label` ("…" while counting, "? of 100000+" past the cap; 17 columns for it) and an invalid hex query's `HexError` as the error. Terminal cursor in the focused input when `Focus::Find`. Returns `FindHit` (box, the query and replace input rects + their draw-time sideways scrolls, toggle rects: `[Aa, ab, .*, 0x]`, the last empty on a text tab) for `hits.find`.
- `side::render` colours explorer rows by git status (`app.git.status`'s `decoration(path)`: the theme key patched over the row style, selected rows too; a changed file's `letter()` at the right edge, folders tinted only) and sets `explorer.height` (used for page up/down) and clamps `explorer.scroll` to the row count; for `SidePanel::Search` it draws the title and hands the rest to `search::render`, returning its `SearchHit` for `hits.search` (`SourceControl`: `scm::render`, its `ScmHit` for `hits.scm`; `Tools`: `tools::render`, its `ToolsHit` for `hits.tools`). The activity bar (`activity::render`) has one icon per `SidePanel::ALL`: `▤ ⌕ ⑂ ≡`.
- The Explorer's body splits vertically with `GitHistory::split`: the tree above (with its scroll bar under `ScrollTarget::Side(Explorer)`) and, when there's room, the "Git History" section below — a divider row (`─`, `sideBar.border`; `Hit::HistoryDivider`, dragged as `Drag::HistoryDivider`), the `▾` / `▸` header (`sideBar.header`; `Hit::HistoryHeader` toggles the collapse), then the commit rows from the loaded commits (`history.height` set, scroll clamped, its own bar under `ScrollTarget::History`; `HistoryHit { divider, header, list, top }`). A row is ` summary` and, as space allows, `author, ago  short` at the right — the author dropped first, then the date, the summary cut with "…"; author / date / short in `gitHistory.author` / `.date` / `.hash`. The selected row takes `list.active` while the section has the keys, else `list.inactive`. Empty: "Reading history…" (first page loading), the error, or "No history", dimmed. Too short for both: the tree takes the body.
- `search::render` draws the Search view: the replace toggle (`▸` / `▾`, `search.chevron`) in the margin left of the query, the query input (`find::draw_field`, `dialog.input`), toggles `Aa ab .*` (case, whole word, regex) and the details button `…` (`find.option` / `find.option.active`; `…` lit while the details show or `hidden_filter()`), while `replacing` the replace input under the query (as wide as it) with the Replace All button `⇄ All` (`search.action`) where the query's toggles are, while `details` the "files to include" / "files to exclude" inputs (full width, one row each), the regex / glob error (`search.error`), a summary (`sideBar.dim`: "1,234 results in 56 files", "Searching…" while running or debouncing, "No results found"), the truncated note (`search.warning`), then the visible rows from `search_view::rows`: file rows (chevron `▾` / `▸` collapsed, `search.chevron`; name `search.fileName`, dimmed folder, count `search.count` at the right) and indented lines from `search_view::preview` (matches `search.match`, "…" where cut; while `search_view.previewing()` each match struck through on `search.replace.removed` followed by its replacement on `search.replace.inserted`, from `search_view::replacements` — `Matcher::replacement_at` with `results.matcher` — for the drawn rows only); the selected row filled with `list.active` while the list has the keys, else `list.inactive` (text keeps its colours, matches and counts their own backgrounds). Sets `search_view.list.height` and re-clamps its scroll. Terminal cursor in the focused input (`search_view.input`) when the side panel has focus and the list doesn't. `draw_line(out, x, y, width, line_match, (base, dim, matched), Option<&ReplacePreview>)` is shared with the panel's Locations list. Its `SearchHit` holds the toggles, the `…` button (`details`), the inputs' rects and their draw-time sideways scrolls (`inputs` / `input_scrolls`: query, include, exclude; empty while hidden), the replace toggle (`replace_toggle`) and input with its scroll (`replace` / `replace_scroll`, empty while hidden), the list rect and each visible row's `RowKey` (clicks map by key, not row number), each file row's chevron cells (`chevrons`) and the hovered row's `×` dismiss button (`dismiss`, drawn in the row's second-last cell, `search.action`, when `search_view.hover` names it) with, while `replacing`, its `⇄` replace button two cells left of it (`replace_row`), plus `replace_all` (empty while hidden).
- Text is drawn grapheme by grapheme through `pos::display_grapheme` — the same function column maths uses, so cursor placement and drawing never disagree. Don't measure buffer text any other way (labels in tabs/status/dialogs use `unicode_width` directly).
- Syntax colours: `buf.syntax.spans(rope, top..last+1)` (the editor takes `&mut Buffer` for this cache; no query unless the tree changed or the view left the cached lines) walked with one index like selections; a token's style (`theme.get(KEYS[i])`, a table built once per frame) patches the row style's foreground first, then find-match / selection backgrounds and cursors go over it (VS Code: selection background, token foreground). No tree yet (first parse, too large, plain text) → plain text; while a re-parse runs, the last spans. A commit buffer's colours are `CommitDoc::spans` (git's) instead.
- Rulers (`Settings::rulers`, after `for_buffer`: unset, `git-commit` gets 72): after the rows, each ruler column in the viewport gets `│` in `editorRuler.foreground` in every text-area row (rows past the buffer's end too) whose cell is still a plain space with no modifier, so text and secondary cursors stay on top; only the glyph and foreground change, so the cell keeps its background (current line, selection, find match). O(rows · rulers).
- Matched brackets (`Settings::match_brackets`): the heads of the selections on screen go to `view.brackets.get(rope, &syntax, revision, heads)` (cached, see `brackets::Matches`); the sorted positions are walked with one index and patched with `editor.bracketMatch` over the token colour, under find-match / selection backgrounds and cursors.
- Diagnostics: `buf.diagnostics.overlapping(viewport)` flattened by `diagnostics::runs` (the most severe wins; an empty range covers the grapheme there, the one before at a line end, or the cell past an empty line's end), walked with one index; the severity's key (`editorError.foreground`, … : underline + `underline_color`) is patched over the token colour, before find-match / selection backgrounds (which don't touch the underline).
- Rendered whitespace (`Overlay::whitespace`, `App::render_whitespace()`): per visible grapheme, `shows_whitespace` (VS Code's modes; only U+0020 and tab — NBSP and other Unicode spaces draw as themselves; `whitespace_bounds` trims each visible line once for `boundary` / `trailing`, `boundary` looks at the neighbouring bytes, `selection` uses the selection walk) replaces the drawn text with `·`, or a tab's `→` in its first cell and blanks after (same width: columns never change), and patches `editorWhitespace.foreground` over the token colour, under find-match / selection backgrounds; not at a drawn cursor (a secondary, whose reversed cell under `block` would take the dim colour as its background, or the primary while `focused`). Control chars keep `editor.whitespace.control`.
- Selections: only `selections.overlapping(viewport)` are looked at (there can be 60k); one index walks that sorted slice while bytes are visited in order; a selection over a line break paints one cell past the line end. Secondary cursors follow `Settings::cursor_style` (the terminal cursor's shape): an underlined cell in `editor.cursor.secondaryUnderline` (Dark+'s `editorCursor.foreground` as the underline colour, the char kept) for `line` / `underline`, a reversed cell (`editor.cursor.secondary`) for `block`; the terminal cursor marks the primary, only in the focused group with no prompt or palette open.
- Styles: start from the widget's base key (`editor`, `sideBar`, `dialog`, `statusBar.<colour>`) and `patch` modifier keys on top (`editor.selection`, `gutter.active`, …). Every key comes from `Theme::dark_plus`; never construct `Color`s here.
- Inline blame (`Overlay::blame` = `app.blame.on`): on the primary cursor's line only, unless the primary selection spans lines, `buf.blame.line(rope, line)` (one binary search per frame) → `blame::label` (the time from `history::now_ms`) drawn `blame::GAP` (3) cells after the line's end in `git.blame.editorDecorationForeground` over the row's style, cut by `blame::fit` with "…" at the text area's right edge (the scroll bar column is outside it); nothing when the line reaches the edge, fewer than `blame::MIN_WIDTH` cells are left, or the label's start is scrolled off to the left. Text never moves.
- Merge conflicts: the visible conflicts from `buf.conflicts.scan(rope, revision)` (cached by revision, one scan per text version) colour each block line's whole row from `merge.current` / `.incoming` / `.common{Header,Content}Background` — `merge_at` walks them with one index as the rows are drawn — and draw `(Current Change)` / `(Common Ancestor)` / `(Incoming Change)` after the `<<<<<<<` / `|||||||` / `>>>>>>>` lines' text in `git.blame.editorDecorationForeground`, cut by `blame::fit` as blame is. The `<<<<<<<` line then gets the action row — ` Accept Current `, ` Accept Incoming `, ` Accept Both `, ` Compare ` in `quickDiff.action` — dropped from the right (Compare first) when they don't fit; each drawn button's rect, `MergeButton` and its conflict's `start` go into `GroupHit::merge_buttons` (the editor returns them with its text rect).
- Quick diff's markers: `buf.quick_diff.visible(rope, top, last)` (by line, walked with one index) draw in the gutter's last column (the space between the number and the text, `text.x - 1`): `Marker::glyph` (`▎` added / modified, `▁` / `▔` deleted) in its `theme_key`'s foreground on the row's background.
- `quick_diff.rs` — the gutter's peek (`app.quick_diff.peek`, when its group shows its buffer and the change's last line is on screen): below the change (above its first line when there's no room), as wide as the text area ≤ 100; `popup::frame` in the hover's colours, a title row (" 1 line changed to 2", " n lines added / deleted" in `quickDiff.title`; ` Stage Change ` in `quickDiff.action`, ` × `), then `-` removed lines (`diffEditor.removedLineBackground`) and `+` the buffer's lines (`diffEditor.insertedLineBackground`), ≤ 12 rows, "…" in the bottom border when cut. Returns `QuickDiffHit` (box, buttons).
- `palette::render` draws the open palette (top centre: input, optional hint, up to 14 rows with fuzzy-match highlights and right-aligned bindings), its input through `find::draw_field` (scrolled to the cursor, its selection in `editor.selection`), sets `palette.height`, clamps `palette.scroll`, puts the terminal cursor in its input and returns `PaletteHit` (box, input rect + its scroll, rows) for `hits.palette`. The editor and explorer show no focus/cursor while it's open.
- `cheatsheet::render` draws the open keyboard cheat sheet centred over `regions.editor` (nothing below 12×4): a `dialog` box with borders, " Keyboard Cheat Sheet " title, a space either side, `cheatsheet::layout` for the width left (as many columns as fit), headings in `cheatSheet.heading`, keys in `dialog.key`, titles in `dialog`, truncated at the box's edge; its last inner column is the scroll bar (`ScrollTarget::CheatSheet`); writes back the sheet's `height` / `rows` (clamping `top`) and returns `CheatSheetHit { rect, scrollbar }`. While it's open the editor, find widget and task tabs don't place the terminal cursor.
- `keys::render` draws the open keyboard shortcuts view full screen over `regions.editor` (nothing below 12×4): a `dialog` box with borders and its title, then on the first inner row the `dialog.input` search box ("Search keybindings: " dimmed, then the query — or a placeholder while it's empty); two rows down, the rows `top..` that fit: the key in `dialog.key` for the widest key (at most a third of the width), the command's title, then the context and the source (their widest, `palette.detail`, right-aligned, the source at the edge); the selected row `list.active` across the whole row; "No matching keybindings" when the search matches nothing. Its last inner column is the scroll bar (`ScrollTarget::Keys`). Writes back the view's `height` (clamping `top`) and returns `KeysHit { rect, rows, scrollbar }` (a click on `rows` selects the row under the pointer). While it's open the editor places no terminal cursor.
- `popup.rs` — popups anchored at a buffer position (the hover, the completion list): `cell_of(rope, view, text_rect, pos, tab_width)` (the anchor's screen cell from the view's scroll; `None` off screen, a column scrolled off pulled to the edge), `place(area, anchor, width, height, Side::{Above, Below})` (the preferred side of the anchor's row if it fits, else the other, else the roomier one cut to it; left edge at the anchor, moved left to stay in `area` — the group's editor area), `frame(out, rect, fill, border)` (resets the cells — styles only patch, so the text's squiggles would show through — then fill + box border; returns the inside). The caller returns the rect for the `HitMap` (`Hit` checks it first, so events on it don't fall through).
- `hover.rs` — the hover popup (`app.hover.popup`): only when its group's active tab still shows its buffer and the anchor (the range's start) is on screen; width = widest line ≤ `hover::MAX_WIDTH` and the editor's width − 4 (border + a column of padding each side), rows = `hover::wrap` ≤ `MAX_HEIGHT`, `place`d above (else below); `editorHoverWidget.background` + `.foreground`, border `.border`, headings `.heading`, code blocks and inline code `textPreformat.foreground`, rules a line in the border colour, a `Kind::Diagnostic` line's icon in its severity's `icon_key`, `Kind::Source` in `editorHoverWidget.source`, `Kind::Link` ("Quick Fix…") in `textLink.foreground` (its screen row written back as `popup.link_row`); anchored at `popup.anchor`; writes back `popup.rows` / `shown` and clamps `top` (the wheel scrolls); "…" in the bottom / top border when rows are cut below / above.
- `code_action.rs` — the code action list (`app.code_actions.popup`, when its group's tab shows its buffer and the anchor is on screen): `place`d below the anchor's row (else above) from one column left of it, ≤ `code_action::MAX_ROWS` rows, as wide as the widest row ≤ `MAX_WIDTH`; each row `★` (`editorActionList.preferred`) for the preferred, then the title; a disabled one in `.disabledForeground` with `(reason)` after it; the selected row `.focusBackground`; base `.background` / `.foreground`, border `.border`; "…" in the border where rows are cut. Writes back `popup.rows`, clamps `top`; returns a `CompletionHit` for `hits.code_actions` (`Hit::CodeActions`, checked before everything). The lightbulb is drawn by `mod.rs` after the active group's editor: `💡` (`gutter` + `editorLightBulb.foreground`) over the gutter's first two cells on the cursor line when `App::bulb_line` says so; its rect goes to `app.code_actions.bulb_hit` (render-time state, cleared each frame) for `bulb_click`.
- `completion.rs` — the completion list (`app.completion.popup`, when it has rows, its group's tab shows its buffer and the word's start is on screen): `place`d below the word (else above), the labels lined up under it (border and icon column to its left), ≤ `completion::MAX_ROWS` rows, as wide as the widest label (+ the widest detail ≤ 30) ≤ `completion::MAX_WIDTH`; each row the kind's icon (`completion::icon`: a letter in `symbolIcon.*Foreground`), the label with the chars the word matched (`Filter::score` against the label) in `editorSuggestWidget.highlightForeground`; the selected row in `.selectedBackground` with the item's detail right-aligned (`.detail`); "…" in the border where rows are cut. Writes back `popup.rows` (the page size) and clamps `top` (no reveal: the wheel may scroll the selection out). Returns `CompletionHit` (box, rows, top) for `hits.completion` (`Hit::Completion`, checked before everything).
- `panel::render` draws the bottom panel: a `─` top border (`panel.border`; `Hit::PanelBorder` drags it), the tab strip (each `PanelTab::ALL`'s title, `panelTitle.active` / `.inactive`, with its total in `panel.badge`; Locations only while `app.locations` is set, its `title` dimmed after the tabs when shown; then a tab per task run, oldest first: its name, `task_mark` (`●` `task.running`, `✓` `task.succeeded`, `✗ 2` / `✗ killed` / `✗` `task.failed`) and a dimmed `×` close button; tabs past the right edge aren't drawn), then the shown tab's content — a task tab: `task::render`; Locations (`locations`): the same file rows, then each place's preview through `search::draw_line` (the place in `search.match`; "Ln x, Col y" dimmed until the file is read), "No locations." without a list; or the Problems list from `problems::files`: only `grouped::rows` for the visible rows, each file's problems fetched once per frame (`FileProblems::problems(from, n)`); file rows (name `panel.fileName`, the folder relative to the root dimmed, the count right-aligned in `panel.badge`), problem rows indented (icon in `Severity::icon_key`'s colour, the message's first line (control chars as spaces), then dimmed `source(code) [Ln x, Col y]` — the message is cut with "…" first, the tail dropped when there's no room); the selected row `list.active` while `Focus::Panel`, else `list.inactive`; "No problems have been detected in the workspace." when empty. Sets the list's `height` and re-clamps its scroll. Returns `PanelHits`: the tab rects, the task tabs' close buttons (`hits.panel_closes`) and a `ListHit` (rows by `RowKey`) for `hits.panel_list`.
- `task.rs` — a task tab's terminal in `layout::task_area(panel)` (below the tab strip, a column of padding): resizes every running run's PTY to it and sets `app.tasks.size` (render-time state); fills the area with `terminal.background`, draws the run's `vt100` screen with `tui-term`'s `PseudoTerminal` (its drawn cursor off) through `Shifted` (a screen taller than the area — an ended run that started bigger — drawn from `tasks::select::top_row`, keeping its last non-blank line and the cursor in view), then every cell through `Theme::terminal_cell` (no `Color` here), the run's mouse selection (`Run::selection`, `tasks::select::rows`) in `editor.selection`'s background over them, only the rows drawn; the rest of the tab strip's row shows "n lines back (Shift+PageDown, Ctrl+End)" while scrolled back, else the command (and its folder when not the root), dimmed; the terminal cursor at the screen's cursor while the tab has the keys, the run runs, it isn't scrolled back and the task didn't hide it. `render_shell(f, area, shell, theme, focused)` is the same drawing for a shell tab in the editor area: the caller (`mod.rs`) resizes the run to the whole area each frame; no tab strip / info line / scroll bar, the terminal cursor while the shell is focused, runs and isn't scrolled back. Both call `draw_screen` (the `Shifted` / `PseudoTerminal` / `terminal_cell` / selection / cursor core), which reads the run's status before taking its screen: the spawn holds the state lock while it takes the screen's (`tasks::run`), so the reverse order deadlocks with a run that is still starting.
- `status.rs`: the bar's background from `.workspace` `[window] status_bar` (`app.theme.get(app.workspace.config.window.status_bar.theme_key())`; warning / error / restricted cells keep theirs), the git branch (` ⎇ main*+ `: `Status::label`, only with a repository; ` Single file ` in single file mode, which also drops the Restricted badge) after the Restricted badge, then the file name, then a merge conflict count (`! 2 conflicts`, the active text buffer's `buf.conflicts.count()` from the frame's scan earlier in `ui::mod`; a diff / hex tab shows none), then problem counts for the workspace (`⊗ n  ⚠ m`, `app.lsp.diagnostics.counts()`, shown once a server runs or anything was published; `render` returns a `StatusHit`: their rect for `hits.status_problems`), then a language server's work in progress (`app.lsp.progress()`: ` rust-analyzer: Indexing 40% `, `statusBar` style), then the message: `app.message` (a notification) if set, else the cursor line's diagnostic (`Marks::for_line`: icon + message on one line, `statusBar` style); right side `Ln x, Col y` for one selection, `N selections` for several (as VS Code), then indent (`Settings::for_buffer`: the buffer's guessed or chosen indentation, `Spaces: indent_size()` / `Tab Size: tab_width`; a Makefile shows `Tab Size`; its drawn cells are `StatusHit::indentation` → `hits.status_indentation`, `Hit::StatusIndentation`: a click opens `Picker::Indentation`), encoding, line ending and the language mode (`Language::name()`; its drawn cells are `StatusHit::language` → `hits.status_language`, `Hit::StatusLanguage`: a click opens Change Language Mode). In editor mode (`app.editor_hint` drawn in place of ` Single file `) the hint wins: the right side keeps the position, then the language, indent, line ending and encoding only while each fits beside it, and the file name shows whole or not at all.
- `banner.rs` — the changed-on-disk banner (`banner`, its `⚠` in `banner.icon`): the message (cut first; "…and you have unsaved changes", or "…and wasn't reloaded" for a binary / non-UTF-8 file on a clean buffer), then a button per `disk::BannerAction::ALL` (` Reload ` / ` Keep Mine ` / ` Show Diff `, `banner.action`). Returns `BannerHit` (row, buttons).
- `tabs.rs`: a deleted file's tab reads `name (deleted)`, struck through (`tab.deleted`); a diff tab reads `DiffTab::title()` (`name (Working Tree)`, `name (History: 3 min ago)`), neither dirty; a shell tab its `title` (`zsh ○` at the prompt, `make ●` while a command runs, `zsh (2) ○`), never dirty, its last glyph in `tab.shellIdle` (red `tab.shellError` after a failed command) / `tab.shellRunning` (a commit tab is a text tab: its buffer's `name()`, the short id). While a tab is dragged, `render`'s `drop: Option<usize>` (the gap from `App::tab_drop_in`) draws one marker cell at that tab's `x0` (or the last drawn tab's `x1` at the bar's end or for an undrawn gap on a scrolled bar), clamped inside the bar, in `tab.dropMarker`. With two or more groups the bar's corner shows the group's number (`render`'s `number`: its 1-based place in `Groups::ids()`), which takes the bar's last cells and so keeps precedence over the `›`.
- `hex.rs` — a hex tab: `HexTab::fit` to the area first (bytes per row from `hex_bytes_per_line`, the scroll and a pending reveal), then only the visible rows as `hex::row` formats them (so a drawn row is exactly `hexdump -C`'s; cut at the area's width) on `editor`, patched: offsets `hexEditor.offset`, the two `|`s `hexEditor.border`, a non-printable byte's hex and `.` `hexEditor.nonPrintable`, selected bytes `editor.selection` in both columns (the gap to the next selected byte too), find's matches (`Overlay { focused, find }`: the widget's `HexFind::query` when it's shown over this tab in the active group) from `hex::find_in` over the visible bytes only, counted per byte with a difference array (`Found`), as `editor.findMatchHighlight` under the selection and the selected match as `editor.findMatch` over it (the editor's layering; runs painted through the hex gaps; a match over a row break on both rows), the cursor's byte the terminal cursor in its column when focused and `editor.cursor.secondary` in the other (both when not). Returns the rows' rect (`GroupHit::text`); `mod.rs` draws its scroll bar from `HexTab::scroll()`, the status bar (`status.rs`) shows its offset (hex and decimal), byte value, selection length and size instead of the text tab's fields, the tab bar its file name with `(deleted)`.
- `diff.rs` — a diff tab: `set_layout` (inline below `diff_view::SIDE_BY_SIDE_MIN` columns) and `scroll_to_cursor` first; a header row (`diffEditor.header`: the sides' titles over their columns, "n changes" — or the last load's error — at the right), then only the visible rows of `Doc::aligned(inline)`: side by side each half its line number (`gutter`, the current row's `gutter.active`) and text from `left_col` through `pos::display_grapheme`; removed lines on `diffEditor.removedLineBackground`, inserted on `insertedLineBackground`, a changed pair's `changed_parts` on `removedTextBackground` / `insertedTextBackground`, the missing side `╱` in `diffEditor.diagonalFill`, unchanged rows plain (the current one `editor.lineHighlight`), a `│` between; inline: both numbers, `-` / `+`, the text. Syntax colours: each side's `Lines::spans` through a `Walk` per side (a binary search for its first visible line, then one index, as rows visit each side's lines in order), the token's style without its background (`syntax::KEYS` table built per frame) patched over the row's background, then the changed-part background, then control chars; no spans → plain. Each hunk's first row ends with ` Stage ` / ` Unstage ` (`quickDiff.action`) when the pair stages; an unstaged pair (Index ↔ Working Tree) also gets ` Revert ` (`diffEditor.revertAction`, red) at the right end of the left column (inline: left of Stage), dropped when it doesn't fit (`DiffHit::reverts`). The terminal cursor on the current row's text when focused. "Loading…", the error, "Binary file: the diff isn't shown", "Both sides are empty" otherwise. Writes `d.text_width` (the text's columns; side by side the narrower half, as they share `left_col`) and measures the drawn rows' widest line (either side; `draw_text` returns a line's whole width) into `d.scroll_width`. Returns `DiffHit` (rows rect, buttons by hunk).
- `scm.rs` — the Source Control view (`SidePanel::SourceControl`, below the title): the branch line (` ⎇ main*+`, `Status::label`, `sideBar.header`), then `ScmView::rows` from its clamped scroll (sets `scm.height`): headers (` ▾ Merge Changes` / ` ▾ Staged Changes` / ` ▸` collapsed, `sideBar.header`, the count in `scm.count` at the right) and files (indented name in its change's `Decoration::theme_key` colour — Merge Changes' `!` in `gitDecoration.conflictingResourceForeground` — `scm.deleted` struck through when deleted, the folder dimmed, the letter at the right edge in the same colour); the selected row `list.active` while focused, else `list.inactive`; the selected and the hovered (`scm.hover`) row show their button left of the letter / badge (`+` stage in Merge Changes / Changes, `−` unstage in Staged, `scm.action`; none on an empty header). No status: "Reading the git status…" while the first read runs, else "The folder currently open doesn't have a git repository." (wrapped, dimmed; no `ScmHit`); nothing changed: "No changes in the working tree.". Returns `ScmHit` (list rect, each drawn row's `RowKey`, buttons with their key and side).
- `tools.rs` — the Tools view (`SidePanel::Tools`, below the title): `tools_view::rows` (built once per frame from `logs.error_counts()`, kept in `tools_view.errors_drawn`), `settle`d and clamped (sets `tools_view.height`), the visible rows: a server's state mark (`ServerState::glyph` in its `tools.*` colour), name, then dimmed its languages · state (its progress while running with some) · its root when not the workspace's; a task run's `panel::task_mark` glyph in its `task.*` colour, name, dimmed `task · <task_label>`; "jed" (`≡`, dimmed `jed's own log`); a log's error count at the right edge in `tools.errorBadge`, one blank column before the scroll bar; the selected row `list.active` while focused, else `list.inactive`. Returns `ToolsHit` (list rect, each drawn row's `RowKey`) and its bar.
- `splash.rs` — what a group with no tabs shows: the "Jed" logo (`splash.logo`) centred in the editor area, "Jim's Editor" (`splash.subtitle`) under its "ed" and the version (`JED_VERSION`, cut with `…` to the "ed"'s width) under that; only the subtitle when the logo doesn't fit, nothing when neither does.
- `dialog.rs` draws the prompts (`ConfirmReplace`: "Replace 41 occurrences across 6 files?", the replace text, [R]eplace [C]ancel; `RestoreBackups`: each backup's `Backup::label` (an untitled buffer's first line), else its path relative to the root, with `history::ago` of each; [R]estore [D]iscard [L]ater; `InstallShellIntegration`: the source line in `dialog.key`, the snippet and init paths (`~`-shortened), [C]opy [A]ppend to <init>); an `Input`'s text is drawn in `editor.selection` over `dialog.input` over `field.selection()` (F2's prefilled name is selected: typing replaces it).
- `scrollbar.rs` — vertical scroll bars: `take_column(&mut area)` (the area's last column, always reserved so nothing reflows; `None` below 2 columns), `look(app, target)` (dragged / hovered / normal), `render(out, track, scroll, look, base, theme, marks)` (the track on `base` — `editor`, `sideBar`, `panel` — then the changed lines' `marks` — `ui::scrollbar::Mark { lines, key }`, `Scroll::cell` projecting each onto the track, the key's foreground filling the blank cell (the gutter keys hold their colour so) — under the thumb, drawn even when there is none). An editor group's: the track (one column, `editor`; a diff tab's starts below its header row, whose cell takes `diffEditor.header`) and the thumb (`scrollbar::Scroll::thumb`: from the line count, `view.height` and the top line — a diff's rows, `height`, `top` — no per-line work) in `scrollbarSlider.background`, `.hoverBackground` (`ui.scrollbar_hover`) or `.activeBackground` (`App::scrollbar_dragged`, drawn even when the drag reaches the top of a short text). Returns `ScrollBarHit` (track, thumb).
