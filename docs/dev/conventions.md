# Feature conventions (detail)

Rules for one area or feature, moved out of the root `CLAUDE.md` (which keeps the cross-cutting invariants and a pointer here). Read the ones for the area you touch.

## Features

- **Files changed on disk:** every `Buffer` keeps the `Stamp` (length + SHA-256 of the bytes) of its file as it last knew it (`disk()`: loaded, saved, reloaded, or accepted by "keep mine"); never compare times. `flush_fs_changes` → `disk_paths_changed` checks each buffer whose file (or a folder above it) changed, off-thread, one check per buffer at a time and none while it saves (`save_epoch`: a check overlapping a save is redone after it). Unchanged = nothing (our own saves); missing → `deleted` (tab "(deleted)", struck through; a save recreates); changed and no edits (`has_edits`) → `Buffer::reload` (one `EditKind::Other` step through `Buffer::edit`, ends clean, undoable; every view's selections via `rename::follow`); changed with edits → `disk_conflict` (the banner: `file.reloadFromDisk` / `file.keepMine`, unbound, in the palette); binary / not UTF-8 → no silent reload, a message and the banner. A save refuses (`SaveError::Conflict`, nothing written) when the file holds neither the known stamp nor what it would write. Files outside the workspace root aren't watched (the save check still guards them). Hex tabs are checked by path the same way (`check_hex`: off-thread `hex::check` against their bytes' stamp): changed → every hex tab of the file gets the new bytes (`set_doc`: cursor / top clamped; even if the file is text now); missing → `deleted`; back → cleared; grown over `HEX_MAX_BYTES` → the old bytes kept, a warning. A reload also guesses the new text's indentation in the check's blocking task (`Check::defaults` → `Reload::guess`) and drops an indentation chosen for the buffer.
- **Log tabs:** a tool's log is an ordinary text tab on a `Buffer` with `log: Some(LogTab)` (`Buffer::log(tool)`): an empty `path`, `read_only` ("a log can't be edited": edits, cut, paste, undo refused by `active_writable`; copy, find, select all, splits work), text changed only by `Buffer::append` (no undo step, never dirty), one per tool (reused: `open_tool_log`). Anything keyed by a file must skip it — `active_path()` / `active_file_buffer()` (Save, history, git, Compare…) are `None` on it, `git_path`, `detect_language` (plain text), `disk_paths_changed`, navigation's `here`, `reveal_active`, `session_snapshot` and `start_servers` (no `[lsp.plaintext]` for a log) check `Buffer::has_file()` (false for a log or a commit); the empty path keeps the rest out (`lsp::documents` and sessions want absolute paths, `Repo::relative` / `history::relative` fail, never dirty: no backups, no workspace search snapshot). Drawn without whitespace glyphs. Commit tabs are the same kind of buffer (`commit_view`).
- **File history:** `App::save` takes a `history::Job` (`App::history_job`: `[history] enabled` and `history::relative`) into the save's task; `SaveJob::write` returns the bytes written and, after `SaveDone { history: true }` is sent, `history::record` runs in a second `spawn_blocking` → `AppEvent::HistoryDone(Result<(), String>)` (an error: a warning message; the save already succeeded). An explorer rename moves the history in the file op's blocking task after the rename (`history_rename`), also ending with `HistoryDone`; a delete keeps it. The Search view's Replace records a file it rewrites (not open) itself, in its own blocking task: the bytes before (no snapshot, no write), then after (`app/replace.rs`). Watcher events under `<root>/.jed/` are dropped in `fs_changed` before `fs_pending`, so history writes cause no listings, git refreshes or disk checks. "File History: Show" / "Restore" (`fileHistory.show` / `.restore`, unbound): the entries are read off-thread (`AppEvent::HistoryListed`) before the palette opens (`Picker::History { restore }`, rows from `app.file_history.picker`); a restore reads + decodes + diffs the entry off-thread (`AppEvent::HistoryRestore`) and applies it with `apply_changes` (one `EditKind::Other` step, `rename::follow` selections), re-diffed if the buffer changed meanwhile. Entry points: the palette, the explorer ("Explorer: Show File History", `explorer.showFileHistory`, on the selected file; right-click on a file's row) and the tab bar (right-click on a tab: its file's). The file needn't be open: Compare's `Text::Buffer` side reads the disk until it opens; Restore opens it first (`OpenRequest::restore`) and restores into the buffer, nothing written.
- **Sessions:** `App::state_dir` (`Some(paths::state_dir())`; `None` under `cfg(test)` unless a test sets it before `test_start`: sessions off) holds `sessions/`. `start` reads the workspace's session and its text tabs' files in one `spawn_blocking` (`session::read`) → `AppEvent::SessionRead` → `session_read`, which replaces the start layout at once (the first frame may be drawn before it): groups, tree, tabs (text tabs' views: selections clamped to the text, `top_line`, `left_col`, no reveal; diff tabs by path and pair, loading as usual; hex tabs by path with cursor, column and top — their bytes read in the same `spawn_blocking`, whatever the file holds now, a missing file drops the tab), panels (the bottom panel on Problems); groups left without tabs close; tabs open before it (the command line's file) go on top in the restored active group, activated — onto the group's tab of that file when it has one, its view taking the command line's cursor only when a line was given (`jed a.rs:12`). A bad session file restores nothing (logged). `App::shutdown` writes the session (`save_session`: snapshot on the UI thread, atomic write in `spawn_blocking`, awaited), except while the restore's read is still running (`session.loading()`), so a quick quit never loses it. Never written on a crash. A non-empty untitled tab is saved as `TabState::Untitled { id, … }` and restored from its crash backup (read in the same `spawn_blocking`; no prompt, and `drop_open_untitled_offers` keeps the offer from repeating it); an empty one isn't saved. A clean quit (`should_quit`: every untitled buffer was saved or discarded) writes none and `remove_all` drops their backups, so the session case is the terminal going away (`shutdown` without Quit: session and every dirty buffer's backup).
- **Crash backups:** dirty buffers are written under `App::state_dir` (`backup::dir`: per workspace) every `backup::INTERVAL` (30 s) — `sync_backups` sets the deadline once a dirty buffer differs from its backup (by revision and key), `Timer::Backup` → `backup_tick` writes every such buffer (rope snapshots, one `spawn_blocking` job at a time: queued removals first, then the writes → `AppEvent::BackupDone`; a failed write is due again, reported once). A backup is removed when its buffer is no longer dirty (saved, reloaded, undone to clean), closed or renamed (`sync_backups`, every turn). `App::shutdown`, after the session: the running job awaited, then a clean quit (`should_quit`: every buffer saved or discarded) removes the workspace's backups except ones put off with Later or not yet offered; the event stream ending without Quit writes every dirty buffer's backup instead; while the start's scan still runs, a clean quit removes nothing and a lost terminal writes only files without a backup (not yet offered). `start` scans (`backup::list`, no writes until it's done) → `backups_found`, offered once the session is restored (`session_read` → `offer_backups`; after the trust dialog when that's open) as `Prompt::RestoreBackups` (`app.backups.offered`): Restore (R / Enter) — each backup through `restore_backup`: the open buffer, else the file opened (`OpenRequest::backup`), diffed off-thread (`disk::changes`) → `AppEvent::BackupRestore` → `apply_changes` (one `EditKind::Other` step, left dirty, nothing written; redone if the buffer changed meanwhile); a backup whose base `disk` stamp isn't the buffer's (the file changed since) makes it `Buffer::set_disk_base(base)` + `check_disk`: the banner, and a save refuses until Reload / Keep Mine — Discard (D) removes them, Later (L / Esc) keeps them on disk to be offered at the next start (a backup this session writes for the same file replaces it). Read-only buffers and files that fail to open keep their backup. An untitled buffer with text is backed up too, under `untitled-<id>.bak` (`Buffer::untitled_id`, kept by a restore; a Save As clears it, so `sync_backups` removes the file: it compares `Key`s); Restore opens an `Untitled-N` tab with the text, left dirty; single file mode offers none. Panic backups (`panic.rs`) are the same files.
- **Back / forward navigation:** recording is one before / after compare per event (`nav_begin` / `nav_end`), not calls at each jump site: the place before is recorded when the active group or file changed, when a jump command set `nav.jump` (`nav_jump`: `open_file` — so quick open, results, F8, go to definition —, `go_to_line`, Cmd+Home / End) and the primary moved without an edit, or for input when it moved `navigation::MIN_LINES`+ lines without an edit. A new jump kind that doesn't go through `open_file` calls `nav_jump()`. Go Back / Go Forward (`nav.back` / `nav.forward`) set `nav.navigating` so they record nothing; a place whose tab was closed reopens through `open_file` (`Goto::Place`), `opened` asks `nav_opened` first: a file gone from disk (loaded with no `disk()` stamp, or failed) is skipped and navigation goes on. Entries map through edits in `follow_edits` and `apply_reload`; positions are clamped when used. A session restore records nothing. Diff and hex tabs are path-only entries (`pos: None`).
- **Recent workspaces:** `start` records the root in `<state dir>/recent.toml` off-thread (`record_recent`; nothing without `App::state_dir`). "Open Recent Workspace" (`workspace.openRecent`, Ctrl+R on both platforms — literal Ctrl on macOS as VS Code, global, so a focused task tab doesn't get it) reads the list off-thread (`recent::list`: missing folders pruned, the current root left out) and then opens `Picker::Recent` (none → a message). Picking one goes through `recent::how_to_open`: jed never switches its own workspace; outside kitty (all of 13c) it's a status-bar message with the path and `jed <path>`.
- **Tool logs:** each language server's task pushes its stderr lines (Info), lifecycle (`Starting: <command line> (in <root>)`, `Started, pid N`, `Initialized: <serverInfo> <version>, positions in UTF-8`, `Can't start: …` / `Failed to initialize: …` / `Crashed: <why>` (Error), `Stopped (<status>)`) and `window/logMessage` / `window/showMessage` (`Message: …`; level by type) to `app.logs` under `Tool::Server(config.name)`, off the UI thread; while `Server::set_trace(true)` (off by default; "Tools: Toggle Protocol Trace") every JSON-RPC message too (`→` / `←`, Trace). jed's own events reach "jed" through `logs::layer` (only what passes the log filter; not written again under `logs/tools`). Log tabs (`app/tools.rs`): `sync_logs` each loop turn takes each log buffer's new lines as one change set; the store's waker (`AppEvent::LogsChanged`) wakes the loop when lines arrive, rearmed by `Timer::Logs` at most every `LOG_FRAME` (20 ms) and only while a log tab exists. A syntax plugin's build is a tool too (`Tool::Grammar(id)`, file `grammar-<id>.log`; the build's command lines and compiler output at Info, a failure at Error; cleared when a build starts; a Tools view row with state waiting / building / ready / failed). Task runs aren't tools with logs (their output is the PTY; the Tools view's task rows focus their panel tab). The Tools view keeps current without polling: server state / progress and task status come as app events (each redraws); new log lines wake the loop while it's shown too, and redraw only when an error count changed. `report_log_errors` (each loop turn) shows the first disk write error once; quitting flushes (`flush_tool_logs`, ≤ 500 ms) after the servers stop.
- **Side and panel lists' reveals before the first draw:** each list's `height` is 0 until drawn (`grouped::ListState`, `ScmView`, `ToolsView`, `GitHistory`, `Explorer`), so a reveal then (`reveal_selected` / `scroll_to_selected`: Ctrl+Shift+G's first file, the Explorer's start file, Shift+F12's first place) only marks itself pending; drawing sets the height through `set_height`, which runs it once — never assign `height` directly in `ui/`. A new scrolled list does the same.

## Tabs

- **Tabs:** a tab is a text editor, a diff view, a hex view or a shell (`group::Tab`); log and commit tabs are text tabs (see Log tabs). Code acting on "the active editor" uses `Group::active_tab()` / `App::active_mut()` / `active_buffer()`, which are `None` on a diff, hex or shell tab — so editor commands, find, completion, hover, LSP requests and the gutter do nothing there without checks of their own. What a diff tab should still do goes through `App::active_file_buffer()` (a text tab's buffer, or the open buffer of a diff tab's file: Save, Reload, Keep Mine, Compare with Disk) or the diff's own arms in `execute` (`diff_command`, `diff_stage`); a hex tab has no buffer (`active_file_buffer()` is `None`, `active_path()` its file: reveal, git) and its own arms (`hex_command`, `hex_copy`; `app/hex.rs`), and file-keyed code that walks buffers never meets it. A new tab kind adds a `Tab` variant, its drawing in `ui::mod` and `ui::tabs`, its `split` copy and its context — or, when it's text to read, is a read-only buffer as logs and commits are. Dragging a tab by the mouse (`Drag::Tab`, `app/tab_drag.rs`) activates it on the press (a drag that never leaves it is a click) and reorders its group's bar on release; the drop marker is one cell in `tab.dropMarker` (`ui::tabs`), positioned from `App::tab_drop_in`.

## Untitled buffers

`Buffer::untitled(n)` has no path: `has_file()` is false, so every path-keyed feature (disk checks, watcher, history, git, LSP; sessions and crash backups key it by `untitled_id`) skips it by that check; use `is_untitled()` only where it should act like an editable text (whitespace glyphs, dirty-ness: it is dirty while it has text). A picked language lives in `Buffer::language_override`. Path-keyed entry points check `has_file()` (`check_disk` too); `Buffers::find_path` and `App::buffer_of` skip such buffers, so an empty path never matches one (a workspace edit or fs event can't land in it). Save As (`SaveJob::save_as`, [app.md](app.md)) gives it a path: `Buffer::finish_save_as` clears `untitled`, and the path-keyed features then see a normal file. A buffer that changes path follows through `App::buffer_moved` (Save As: `refresh_git`, the Explorer's listings and reveal) and `forget_path_state` (also the explorer rename's, per moved buffer): `quick_diff.reset`, `blame.reset` (both drop a running computation's result: it carries the generation it began with), `diagnostics.clear_all` and `servers_dirty`, so the next turn recomputes markers / blame and `sync_documents` sends didClose (old) / didOpen (new); `lsp.saved` (`Documents::saved`) syncs the documents before its didSave, so a Save As's didSave names the new document, after its didOpen. History is not moved by a Save As (a copy: the old file keeps its entries, the new path starts with the save's snapshot); the watcher covers the workspace. `untitled_tests.rs` has one test per feature (disk / fs events, history and git commands, blame, sessions).

## Keymaps

- **Keymaps are data:** commands never look at keys. Default bindings live in `keymap::defaults` (a `Vec<Binding>`; list order decides which key the palette shows), per platform (`cmd` = Super on macOS, Ctrl on Linux; `word` = Alt on macOS, Ctrl on Linux). A context binding wins over a global (`None`) one. `keybindings.toml` (`[[binding]]` with `key`, `command`, optional `context` = `editor`/`explorer`/`palette`/`find`/`replace`/`search`/`searchResults`/`problems`/`locations`/`suggest`/`codeActions`/`diff`/`scm`/`tools`/`gitHistory`/`commit`/`task`/`hex`/`shell`) is loaded once at startup in `main` (`App::set_keymap` reports errors): every command it names loses all its default keys; a user key also overrides whatever was on it in that context. Text fields (find, Search view, palette, prompts) have no keys of their own: `App::field_key` runs the editor context's moves / deletes / select all / clipboard commands on them. `Command` must stay `Copy + Hash` (no owned payloads).

## Settings

- **Settings layer per key:** `edit::Settings::default()` ← `~/.config/jed/settings.toml` ← `.workspace` `[settings]`, only in `config::settings::layer` (via `Workspace::settings()`, stored in `App::settings`, recomputed on a `.workspace` reload). `settings.toml` is read once at startup (live reload is a TODO in PLAN.md). Adding a setting: a field in `edit::Settings` (+ default), an `Option` field in `SettingsOverrides` and a line in its `apply`, a row in `config/settings.rs`'s doc table and a line in its `TEMPLATE` (`template_lists_every_key_at_its_default` names every field without `..`, so it won't compile until the new one is added there, and then fails if `TEMPLATE` lacks it); it then works from both files. Code measuring or indenting a buffer's text reads `tab_width` / `insert_spaces` from `settings.for_buffer(buf)` (language, then the buffer's guessed / chosen indentation), never `app.settings` directly.

## Language server requests

- **Language server requests:** `App::send_request(group, buffer, at, method, supported, Request)` (`app/lsp.rs`) sends through `lsp::Manager::request_at` (`send_doc_request` / `Manager::request_doc`: no `position`, for whole-document requests like formatting) and keeps a `Pending` (request kind, group, buffer, revision, position, encoding) in `App::requests` by (server, id); a newer request of the same kind cancels the older (`$/cancelRequest`), `check_requests` after each input event cancels ones whose place moved on (buffer edited; the cursor — the active view of the active group — or, for a mouse hover, the pointer elsewhere), answers are taken only for pending and still current requests (else dropped as stale; errors that are `RpcError::is_routine` — cancelled, ContentModified (rust-analyzer while loading) — dropped quietly, no message) and go to their kind's handler (`hover_answer`, `definition_answer`, `completion_answer`, `references_answer`, `rename_answer`, `format_answer`, …); `Failed` / `Exited` drop that server's pending ones. A new request kind adds a `Request` variant and an arm in `App::answer`.

## Edits from background results

- **Edits from background results** (a rename's `WorkspaceEdit`) go through `Buffer::edit` like any other; the code sets the active view's selections itself when it shows the buffer, then calls `App::follow_edits` (`sync_views` without the Cmd+U / Cmd+D tracking) so every other view follows at once. A file not open is loaded through the `opening` map (`OpenRequest { background, edits }`), never on the UI thread.

## Logging

- **Logging:** `tracing` only — never print while the UI is up. Targets are module paths (`jed::app`, `jed::buffer`, …) except explicit `target: "input"` (key/mouse/paste at trace), `target: "panic"`, `"lsp::wire"` (every JSON-RPC message in / out at trace, with `server`) and `"lsp::stderr"` (server stderr lines at debug; a crash logs the last 20 at warn). Each `execute` runs in a `command` span with the command name. User-visible messages go through `App::notify(Level, text)`, which also logs. `JED_LOG=input=trace` / `--log-level` set the filter.

## Scroll bars

- **Scroll bars:** anything scrolled gets the one-column bar by implementing `scrollbar::Scrollable` (rows, height, top as a row index, set top — O(1) / per group, never per row: lists keeping their top by key convert by binary search), drawing it in its area's last column (`ui::scrollbar::take_column`, always reserved, + `render` with `look(app, target)`) and reporting the `ScrollBarHit` under a `ScrollTarget`, plus an arm in `App::with_scrollable`; clicks, drags, hover and the wheel then work as for the others. Text and diff tabs also get a horizontal bar (`ScrollTarget::Columns`, `ui::scrollbar::render_row`) on the editor's last row while a drawn line is wider than the view.

## Adding a command end to end

1. `command.rs`: add a variant to `Command` (or `ExplorerCommand` / `PaletteCommand`), its name in `Command::name()` (`area.camelCase`), its `title()` (both matches are exhaustive) and add it to `Command::all()` (not checked by the compiler; the palette and `keybindings.toml` only know commands listed there).
2. Behaviour: text/cursor work goes in `edit.rs` — add an arm in `edit::run`, and to `edit::is_edit` if it changes text; build changes per selection with `replace_each`/`replace_each_landing`; seal undo if it's not an edit. App-level work gets an arm in `App::execute` (`app/mod.rs`), with helpers in the right `app/` submodule.
3. Binding: add to the `editor`, `explorer`, `palette`, `find`, `replace`, `search`, `task`, `shell` or `global` list in `keymap::defaults`, for both platforms (`cmd`, `word`, `if mac { … }`). Don't bind plain characters in the editor, find, replace or search contexts (they'd stop typing).
4. If it uses Cmd on macOS: add a row to `docs/terminals/README.md` and the key to every snippet.
5. Tests: a unit test next to the code, plus the end-to-end case in the milestone's test file through `press`.
6. PLAN.md's Milestones entry (✅, "Deferred", hand checks) is updated in the milestone's own commit.
