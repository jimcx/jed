# Module map and data flow (detail)

The full per-module reference that the root `CLAUDE.md` summarises in one line each. Read the entries for the modules you touch; nested `CLAUDE.md` files (`src/app`, `src/buffer`, `src/lsp`, `src/syntax`, `src/ui`) go further for their directories. Keep entries to what the code does; the code's `//!` docs are the deeper reference.

## Module map (`src/`)

- `main.rs` — arg parsing (`jed [<folder> | <file>[:line[:col]]]`, `--new-language <id>` / `--check-language <id> [--sample <file>]` (`Authoring`, run by `run_authoring` before logging and the UI: print and exit), `-s` / `--single <file>[:line[:col]]` (`resolve_single`: a file, not a folder; a missing one in an existing folder opens as `Buffer::new_file`, created on save; root as for `jed <file>`) → `App::new_in(Mode::SingleFile, …)`, `--log-level`, `--perf` (perf logging on: `perf::enable`)), loads the first file, `.workspace`, `settings.toml`, `tasks.toml` (into `app.tasks.user`) and `keybindings.toml` *before* raw mode (their load errors go to `App::set_keymap` after the UI starts), builds the tokio runtime, runs `App`
- `build.rs` — sets `JED_VERSION` (`--version`, the startup log line) from git: the tag on `HEAD`, else `branch (short hash)`, else `Cargo.toml`'s version
- `app/` — `App`: owns all state, the event loop, `execute(Command)`, prompts, mouse, background-result handling (see `src/app/CLAUDE.md`)
- `command.rs` — `Command` / `Motion` / `ExplorerCommand` / `PaletteCommand` / `FindCommand` / `GitHistoryCommand` / `CommitCommand` enums; `Command::all()` (what the palette lists and keybindings can name; `ExplorerCommand::FindInFolder` = `explorer.findInFolder`, `SearchCommand::{ToggleDetails, NextInput, PreviousInput}` = `search.toggleDetails` (Cmd+Shift+J) / `search.nextInput` / `search.previousInput` (Tab / Shift+Tab in the Search view); `ShowTools` = `tools.show` (Cmd+Shift+U, VS Code's Output), `ToggleToolTrace` = `tools.toggleTrace` and `RestartServer` = `tools.restartServer` (both unbound), `RebuildSyntaxPlugins` = `languages.rebuildSyntaxPlugins` (unbound), `ToolsCommand` = `toolsView.*` (the Tools view's list keys)), `name()` (stable dotted names like `edit.copy`), `from_name`, `title()` (palette text, `Category: Action`)
- `config/keymap.rs` — `Keymap` (data: `(KeyCombo, Option<Context>) -> Command`), `Context` (`Editor`, `Explorer`, `Palette`, `Find`, `Replace`, `Search`, `SearchResults`, `Problems`, `Locations`, `Suggest` (the completion list while shown), `Diff` (the editor with a diff tab active: F7 / Shift+F7), `Scm` (the Source Control view's list), `Tools` (the Tools view's list: arrows, PageUp / PageDown, Home / End, Enter, Esc), `GitHistory` (the Explorer view's "Git History" section: Up/Down/PageUp/PageDown/Home/End select a commit, Enter opens it, Left/Esc back to the tree; unbound keys do nothing), `Commit` (the editor with a commit tab active: Enter opens the cursor's stat row's diff; other keys come from `Editor`), `Task` (a task tab in the panel: Shift+PageUp / PageDown, Ctrl+Shift+Up / Down, Ctrl+Home / End scroll, Esc back to the editor, Cmd+W closes it; keys bound neither here nor globally go to the task); `lookup` tries the context, then its parent — `Replace` → `Find`, `SearchResults` → `Search`, `Suggest` / `Diff` / `Commit` → `Editor` — then global), `Platform`, `default_for(platform)` (F8 / Shift+F8 and Alt+F8 / Shift+Alt+F8 everywhere: Problems and Next / Previous Conflict), `load(path, platform)` (defaults + `keybindings.toml`), `KEYBINDINGS_TEMPLATE` / `create_if_missing(path)` (the file, never overwriting one) / `stub_bindings(keymap, command, spec, context)` + `append_stub(path, bindings)` (blocking: the `[[binding]]` tables the keyboard shortcuts view's Enter adds — the selected row's binding first, then the command's other keys so changing one doesn't drop the rest, `key = ""` noted for a command with no key), `binding_for(cmd)` (the key the palette shows), `bindings_with_source()` with `Source::{Default, User}` (every binding with where it came from — the defaults or `keybindings.toml`: the keyboard shortcuts view's source column), `context_bindings(context)` (the commands bound in that context itself, one key each — the palette's when it is one —, by title: the cheat sheet's first section); `KeyCombo::parse` / `spec` (config spelling) / `label` (`Cmd+Shift+P`); `from_event` turns a shifted US digit with Cmd/Ctrl/Alt (`Cmd+!`, how kitty-protocol terminals report Cmd+Shift+1) into digit + Shift, Ctrl+@ (a legacy terminal's Ctrl+Space, NUL) into Ctrl+Space, and `_` with Ctrl/Alt/Cmd (kitty's Ctrl+Shift+-) into `-` + Shift
- `config/settings.rs` — `SettingsOverrides` (the `[settings]` table shared by the user's `settings.toml` and `.workspace`, every key an `Option`; the module doc has the table of keys, types and defaults), `apply`, `layer(user, workspace)` (defaults ← `settings.toml` ← `.workspace`, per key: the one place precedence lives), `load(path)` / `parse` → `UserSettings { overrides, errors }` (missing file: silent; TOML syntax error: defaults + one error with its line; unknown key, misplaced key/table or wrong type: reported and skipped, the other keys apply — VS Code's leniency, unlike `.workspace`, which rejects the whole file), `TEMPLATE` (every key commented out at its default) and `create_if_missing` (for "Preferences: Open User Settings"; `create_new`, so it never overwrites a file)
- `edit.rs` — movement and editing at every selection (`edit::run`, `insert_char(buf, view, c, settings)`, `paste`, `copy_text`, `cut`), `Settings` (tab width, spaces, `syntax_max_bytes`, `auto_close_pairs`, `auto_indent`, `match_brackets`, `quick_suggestions`, `render_whitespace`: `RenderWhitespace::{None, Boundary, Selection, Trailing, All}`, VS Code's `editor.renderWhitespace`, default `All`, serde lowercase strings; drawing only, the effective mode is `App::render_whitespace()`; `cursor_style`: `CursorStyle::{Line, Block, Underline}`, default `Line`, and `cursor_blinking`, default true: the terminal cursor's shape and secondary cursors' look; `hex_bytes_per_line`, default 32: a hex tab's widest row, `SettingsOverrides` rejects anything but a power of two from 1 to 64); `detect_indentation` (default true). Everything reading `insert_spaces` / `tab_width` for a buffer's text (`edit::run`, `insert_char`, so indent / outdent, Enter, comment line, Up / Down, box select; the status bar, the drawn width of a tab, popups' and the gutter peek's cells, mouse hits, go to line / column, format options) goes through `Settings::for_buffer(buf)`: the language's `LanguageConfig::insert_spaces` (Makefiles always indent with tabs, VS Code's `[makefile]` default), then the buffer's own: `Buffer::indentation` (chosen by a command), else with `detect_indentation` `Buffer::guess()` applied over the settings (not for a language that fixes `insert_spaces`), then `Buffer::tab_display` ("Change Tab Display Size": `tab_width` only; with spaces the indent size moves to `Settings::indent_size`, VS Code's `indentSize`). `tab_width` is the tab stop (drawing, column maths); `indent_size()` (`indent_size: Option`, `None` = `tab_width`; never a user setting) is spaces per level: Tab with spaces, `indent::unit` / `unindent`, `shift`'s levels, the status bar's `Spaces: N`, format's `tabSize` with spaces. `Settings::indentation()` is the settings' `Indentation`, the guess's defaults. Diff tabs and the Problems list's columns still use `app.settings.tab_width`. Enter is `indent::newline`; Tab (`InsertTab`) is `shift::tab` when a selection covers lines or a whole line, else a tab (spaces to the next stop) at each selection, `EditKind::Insert`. `insert_char` tries `indent::type_char` (with `auto_indent`), then `pairs::type_char` (only for a char in the language's pairs; any other char takes the plain path untouched); Backspace tries `pairs::delete_pair`. `replace_each_landing` (`Land::{AfterText, Inside(n), Keep(p)}`) also carries the view's `AutoClosed` through its edit (`follow` before, `edited` after). `paste(buf, view, text, whole_line, pieces)` spreads one part per cursor (VS Code's `multiCursorPaste: spread`): jed's own copied pieces if there are as many, else the text's lines (one final line break ignored); never for a whole-line copy or one cursor. `copy_text` returns a `clipboard::Copied`; only one empty cursor's copy is whole-line (VS Code). The merge conflict commands (`Command::Merge`, Alt+F8 / Shift+Alt+F8 for Next / Previous, unbound otherwise) are `merge_command` (the `Choice`; the conflicts the selections touch via `conflicts_touching`, or every one for `AcceptAll*`; Next / Previous / Compare aren't edits and `execute` runs them elsewhere) and `accept_merge` (`conflict::accept_all` as one `EditKind::Other` step, cursors collapsed onto their mapped heads) — also what a click on an action-row button runs
- `completion.rs` — completion's model (no drawing; `app/completion.rs` drives it, `ui/completion.rs` draws it): `parse` (`CompletionItem[]` / `CompletionList` with `itemDefaults`; an item inserts its `textEdit` — an `InsertReplaceEdit`'s `insert` range — else `insertText` / `label` over the word before the cursor), `strip_snippet` (placeholders → their defaults; selects the first tab stop, else `$0`), `Filter` (nucleo fuzzy, case-insensitive, first char at a word start), `Anchor` (where a request was asked: rope snapshot + primary cursor, the word's `start` and the cursor `at` followed through edits by `Buffer::sets_applied`, `in_word`, `now(p)` for snapshot positions), `place` (each item's range → `lead` / `after` bytes), `Popup` (items, `shown` sorted by score then `sortText`, `refilter`, selection / scroll), `Completion` (`popup`, the pending `ask`, the `quick` timer), `insert(buf, view, Insertion)` (the item at every selection — the same char counts before / after each as at the primary, only word chars when the primary's are — plus `additionalTextEdits`, one `ChangeSet`, `EditKind::Other`, O(selections) via `Peek`; multi-line text gets each line's indentation and the buffer's EOL)
- `column.rs` — add cursor above / below (`add_cursor`, keeps the goal column), Shift+Alt+I (`cursors_at_line_ends`), column (box) select: `select(from, to)` per line between two display columns (nearest grapheme boundary, short lines skipped, VS Code's `ColumnSelection`), `step` for Cmd+Shift+Alt+arrows, `current` (the view's `ColumnBox` while its selections are unchanged, else the primary's anchor/head). Uses `pos::LineWalker`, not per-cursor lookups
- `commit_view.rs` — a commit tab's model (no drawing, no app state: `app/commit_tabs.rs` opens, loads and fits it). A commit tab is a read-only text tab, as a log tab is (see Log tabs): a `Buffer` with `commit: Some(CommitDoc)` (`Buffer::commit(id, file)`, `name()` = the 7-hex short id). `CommitDoc { commit (full id), file (the work-tree-relative path whose history opened it), show: Option<Arc<git::show::Show>>, error, running }` + the lines last rendered; `want()` (`Now` only before a load; a commit never changes, a failed load isn't retried), `begin` / `finish`, `render(width) -> Option<String>` (the text — `git_show::render` at that width, lines joined with `\n`, or the load's error — only when it isn't the one shown; no I/O), `title()`, `file_at(line)` / `file_row(k)` / `own_file_row()` (stat lines ↔ `Show::files`), `spans(rope, lines)` (git's colours as byte ranges + theme keys: the id `gitShow.commit`, a stat's `+` `gitShow.add`, `-` `gitShow.del`; what `ui::editor` draws instead of syntax colours)
- `conflict.rs` — merge conflicts: the model and the accept changes (the editor draws the blocks, the marker labels and the action row from it; no app state): `Conflicts` on every `Buffer` (`buf.conflicts`), a line scan of the text for git's markers at line starts (a `<<<<<<<` with no `>>>>>>>`, or another `<<<<<<<` before it, isn't a conflict) → `Conflict { start, end (the whole marker-to-marker span), current, base (`|||||||`, diff3 only), incoming }`s, sorted, cached by revision (`scan(rope, revision)`) and invalidated by every change set (`map`, from `Buffer::apply`); `count()` is the last scan's number (the status bar's `N conflicts`; `None` before a scan and after an edit); `next` / `previous` wrap; `block(rope, conflict, Choice::{Current, Incoming, Both, Base})` → the chosen block's text (a two-way conflict's base is empty: accepting it removes the conflict), `accept_all(rope, conflicts, choice)` → the `ChangeSet` replacing each whole span with its block (one `EditKind::Other` step when applied), which the palette's `Command::Merge(MergeCommand)` accept commands apply at the conflicts the selections touch (or every conflict for `AcceptAll*`), and the editor draws the blocks, marker labels and action row from `Conflict`
- `comment.rs` — comment line (Cmd+/, `toggle`): VS Code's `LineCommentCommand` per selection (a line shared by two belongs to the first; one ending at a later line's start doesn't take it): uncomment if every non-blank line starts with the token (+ one space), else comment the non-blank lines (all, if all are blank) at the selection's smallest indentation (never inside a tab); one `ChangeSet` via `LineWalker`, one undo step (`EditKind::Other`); selections keep text inserted at their edges, a cursor at the insertion point lands after the token. No token (plain text): nothing
- `indent.rs` — auto-indent at every cursor (VS Code's `autoIndent: full`, approximated; the module doc lists the rules and differences): `newline` (Enter: the line's indentation up to the cursor; + a level after an opening bracket token, a Python block keyword line ending in `:` or a YAML line ending in `:` / `-`; C/C++ and Rust also VS Code's (C/C++) `indentationRules` (+ a level after a bracket left unclosed anywhere before the cursor, − one before a closing bracket after it; the tree is walked only when the text has a quote or `/*`); `IndentOutdent` between a pair (closer on its own line, cursor on the indented middle line, `Land::Inside`); − a level after Python `return`/`pass`/…; trailing comments skipped (tree, else the line comment token); a whitespace-only line's rest dropped; all new texts in one `String`, one `EditKind::Insert` edit) and `type_char` (a closing bracket first on its line re-indents the line to its opener's line, via `brackets::Openers`, not inside a multi-line string / comment; Python `else:` / `elif …:` / `except …:` / `finally:` to the nearest less indented `if` / `try` / … line). Enter's lines via `LineWalker`, tree checks via forward `syntax::Tokens` walks; a closer reads only bytes (`Peek::blank_line_start` / `line_indent`), not lines, so 65k cursors stay well within the 80 ms line-command budget (Enter ~50 ms, `}` ~20 ms). `Settings::auto_indent = false`: Enter is a plain line break, no outdent
- `indentation.rs` — guessing a file's indentation (VS Code's `guessIndentation`, ported; the module doc has the rules): `guess(rope, defaults) -> Guess { spaces: Option<bool>, size: Option<usize> }` over the first `MAX_LINES` (10k) lines via `pos::each_line` (no allocation per line, ~2 ms on 10 MB in release: `milestone_indentation_budget_detect_10mb`), `Guess::apply(defaults) -> Indentation { spaces, size }` (the size only with spaces). `defaults` (`Settings::indentation()`) only decide whether an aligned-looking line counts. Run where the file is read, off the UI thread: `Buffer::open_with(path, defaults)` (main's first file after the workspace's settings load, opens via `app/hex.rs::load`, rename's loads, the session restore's `session::read`) and `disk::check` (`Check::defaults` → `Reload::guess` → `Buffer::reload`, which via `Buffer::redetect` also drops a chosen `Buffer::indentation` / `tab_display`; "Detect Indentation from Content" calls `redetect` with a guess of the text as it is, on the UI thread: `app/indentation.rs`). `Buffer::open(path)` (the default settings' defaults) is `cfg(test)` only. "Convert Indentation to Spaces / Tabs": `changes(rope, spaces, tab_width) -> ChangeSet` (one pass over `each_line`, a change only where a line's leading whitespace differs; measured in columns at the tab width, so it differs from VS Code's string replace only for spaces before a tab: the module doc) and `convert(buf, view, …)` (one `EditKind::Other` step, the view's selections mapped with `mapper()`; nothing to change → no step; ~13 ms at 46k selections on 1 MB: `milestone_indentation_budget_convert_1mb`). Session-only: nothing is stored
- `brackets.rs` — bracket matching over the language's bracket pairs (`LanguageConfig::brackets`): `match_at(rope, syntax, pos)` (the bracket after the cursor, else before it, and its partner; with a current token tree (`Syntax::token_tree`: not Markdown's) only bracket tokens count — not in strings / comments — and the partner is found among the token's siblings (missing = unmatched); without one, a text scan of at most `WINDOW` (16 KB) each way), `Openers` (innermost unclosed opener before increasing positions: one pass over tokens or text with a stack, restarting `WINDOW` back after a gap) and `Matches` (the view's highlight cache: recomputed only when revision, language, tree availability or the on-screen cursor heads (first `MAX_CURSORS`, 64) change)
- `pairs.rs` — auto-close at every cursor, VS Code's defaults, each rule all-or-nothing over the selections (as VS Code): type-over (only closers jed inserted: `AutoClosed` on the `View`, one action per auto-closing key, live while every cursor is strictly inside one of its pairs (after the open char, before the closer's end) and they stay on one line (a typed line break drops them, as VS Code); dropped by any edit not made through `replace_each_landing` of that view, checked by buffer revision), auto-close (next char in `autoCloseBefore` or a closing bracket; `'` / `"` not after a word char unless a Python string prefix letter is before every cursor (then `notIn` strings and comments), not in a string / comment per pair when the tree is current: `Syntax::scope_before`; seals undo before, `EditKind::Insert`), wrap non-blank selections (`EditKind::Other`, inner text stays selected), Backspace in an auto-inserted empty pair deletes both. `pos::Peek` reads the chars next to each cursor. Off with `Settings::auto_close_pairs = false`. `pairs::tests::{setup, show}` mark text with `|` (cursor) and `«…»` (selection) — the comment tests use them too
- `lines.rs` — move lines (`move_lines`, Alt+Up/Down) and copy lines (`copy_lines`, Shift+Alt+Up/Down) at every selection: selections are grouped into line blocks (sharing a line; for moves also neighbouring lines); a non-empty selection ending at a line start doesn't take that line; one undo step (`EditKind::Other`), none if nothing moves; selections follow the moved / lower copied text
- `shift.rs` — indent / outdent lines (`indent` = Cmd+] `edit.indentLines`, `outdent` = Cmd+[ / Shift+Tab `edit.outdentLines`; Linux Ctrl+] / Ctrl+[), VS Code's `ShiftCommand`: each touched line's indentation (tabs measured `tab_width` wide) to the next / previous multiple of the indent size (`Settings::indent_size()`), written in the buffer's spaces / tabs (`Settings::for_buffer`; mixed indentation normalised, only the differing part replaced); `comment.rs`'s line rules (an end at a line start doesn't take it, a shared line once); empty lines skipped unless the selection is on that line alone; `tab` (Tab) per selection as VS Code: over lines or a whole line → its lines indented, else a tab in its place, one step — `false` when none indents (then `edit::insert_tab`). Selections keep their text (a non-empty one starting in its first line's indentation keeps that column, growing / shrinking). One `ChangeSet` via `LineWalker`, forward only, `EditKind::Other`; nothing to change = no step
- `shell_integration.rs` — opt-in shell integration, the model (no app state; "Terminal: Install Shell Integration" is `app/shell.rs` + `app/prompt.rs`, `ui/dialog.rs` draws it): the zsh / bash / fish snippets (`SNIPPETS`; each opens with a `JED_IPC` guard so sourcing it elsewhere does nothing, preexec sends `133;B` then `OSC 0 <first word>`, precmd `133;D;<exit code>`), written into the state dir by blocking `write_snippets(state_dir)`; `init_for(home, config_home, state_dir, shell_base)` → `Init { snippet, init, source }` (`~/.zshrc`, `~/.bashrc`, `<config_home>/fish/config.fish`; `None` for a shell without a snippet — `sh`, …), `source` single-quoted; blocking `append_line(init, line)` (creates the file and its folder, one `O_APPEND` write, a newline first when the file has text and doesn't end in one)
- `buffer/` — `Buffer`/`Buffers`, `ChangeSet`, undo `History`, file load/save, and **all** position types/conversions in `buffer::pos` (see `src/buffer/CLAUDE.md`)
- `selection.rs` — `Selection` (anchor, head, goal column) and `Selections` (sorted, merged, never empty; a primary and a *newest* — the one added last, which Cmd+D searches after; `new` takes the last list entry as newest, `with_newest` names it). The list is an `Arc` (copy on write): clones are cheap and equal clones compare by pointer; normalizing skips the sort when the list is already sorted (after an edit or mapping) and merges in place. Merging is VS Code's: overlapping, or touching when one is an empty cursor; two non-empty selections that only touch stay apart. `overlapping(from, to)` (binary search, for drawing) and `contains_range`
- `view.rs` — `View`: selections + scroll for one tab; `map_through` follows edits made via another view (and clears its Cmd+U history first, so the list is mapped in place; positions go start then end, in order, for the mapper's forward stepping); `reveal_range` (centre a range if off screen, set by Cmd+D); `reveal_pos` (scroll just enough to show a position, e.g. the newest added cursor); `column` (the last `column::ColumnBox`); `auto_closed` (`pairs::AutoClosed`: the closers typing can step over); `brackets` (`brackets::Matches`, the highlighted brackets); `scroll_width` (written by drawing) and `scroll_columns(delta)` (the sideways wheel: clamped by it, selections and reveals untouched); `CursorHistory` (Cmd+U: up to 50 earlier selection lists + scroll, cleared by any text change)
- `wrap.rs` — soft wrap's model (no drawing, no app state): `Layout::compute(text, width, tab_width)` breaks one line into `Row { start (byte in the line), col (0 on the first row, the line's indentation on continuation rows) }`s — after the last space that fits (a space that doesn't fit ends the row before it), else between graphemes, a wide char or tab whole, at least one grapheme a row — with `row_of(pos)` / `byte_at(row, col)` / `row_end(row)` (tabs expand from the row's column); `Wrap`, a view's cache: `total_rows` / `line_rows` from each line's row count (laid out for every line per revision / width / tab width, then `map(changes, rope, revision)` lays out only the edited lines again; a line-count change or a net-zero line-break shift lays everything out again), and `layout(rope, revision, line, …)` laying out one line at a time, kept by (revision, width, tab width) for `MAX_LAYOUTS` lines
- `multicursor.rs` — Cmd+D / Cmd+Alt+D (`next_match`, `Step::{Add, Skip}`) and Cmd+Shift+L (`select_all`) as VS Code's `MultiCursorSession`: a `Session` is word mode (empty single cursor: whole word, case-sensitive) or the primary's text literally with the find widget's case/whole-word (`App::find_options`, default off); searches after the newest selection, wraps, skips already-selected matches. Several selections with different text: Cmd+D first expands empty cursors to words
- `navigation.rs` — back / forward navigation's model (no app state; `app/navigation.rs` records and navigates): `History` (one per window, `MAX` 50 `Entry { group, path, pos: Option<Pos { anchor, head, top, left_col }> }` — `None`: a diff or hex tab — and `index` (`len` = live); `record` drops the forward entries, `back(current)` / `forward(current)` store where you are first, `skip(dir)` drops a gone file's entry, `map(path, changes)` follows edits (`Assoc::Before`); consecutive same places (group, path, selection) collapse), `MIN_LINES` (10: a move that far is recorded), `Dir::{Back, Forward}`
- `group.rs` — `Tab::{Text(TextTab { buffer, view }), Diff(Box<DiffTab>), Hex(Box<HexTab>), Shell(Box<ShellTab>)}` (`text()`, `diff()`, `hex()`, `shell()`, `buffer()` — `None` for a diff, hex or shell tab; `Group::active_hex()` / `find_hex(path)`, `Groups::hex_tabs()` / `hex_tabs_mut()`; a split copies a hex tab, sharing its bytes; `same_as` matches hex tabs by path; `Group::active_shell()`, `Groups::shell_tabs()` / `shell_tabs_mut()`; a shell is never copied into a split (`same_as` matches nothing)), `Group` (tabs, active; the tab bar's `scroll` — first tab shown — and `revealed` (active tab + bar width last scrolled into view), so the wheel / arrows can scroll it away from the active tab; `scroll_tabs(delta)` (drawing clamps it); `active_tab()` / `active_tab_mut()` = the active tab *only when it's a text tab*, `active_diff()` / `active_diff_mut()`, `find(buffer)` and `text_tabs_mut()` text tabs only; `open(buffer, view)` / `open_tab(Tab)` activate the new tab, `open_background` keeps the active one; `take(tab)` — a tab moved in — replaces the tab `Tab::same_as` it (same buffer, or same diff path and pair: it takes the moved view) else opens it, `move_active(±1)` swaps the active tab with a neighbour, no wrap), `Groups` (map + `SplitTree`, always ≥1 group; `split(dir, diff_id)` copies the active tab — a diff tab as `DiffTab::copy` with a new id — in a group from `split_empty(dir)` (no tabs), or `split_empty_of(target, side)` (the new group on that edge, first in reading order for left / up); `tabs_showing(buffer)`, `diff_tabs_mut()`; `move_active_tab(forward)` moves the active tab into the next / previous group in reading order (`ids()`) and activates it — forward with none splits right (`split_empty`) unless it's its group's only tab (a no-op: the emptied group would close), back with none does nothing — closing the group it left if empty; `restore(tree, groups, active)` (a session's: `check_restore` — the tree's leaves are exactly the group ids, `active` among them — then ratios sanitized, new ids after the largest))
- `layout.rs` — `SidePanel::{Explorer, Search, SourceControl, Tools}` (`ALL`: the activity bar's order; serde snake_case in sessions), screen `Regions` (`compute(area, side_visible, side_width, panel_height)`: the bottom panel under the editor groups only, the side panel keeping its height; clamped so the editor keeps `MIN_EDITOR_HEIGHT` and the panel gets `MIN_PANEL_HEIGHT` when that fits), `PanelTab` (`Problems`, `Locations` (its tab only while there's a list), `Task(RunId)` (one per run, after them, until closed); - `tools_view.rs` — the Tools view's model (no drawing; `app/tools.rs` drives it, `ui/tools.rs` draws it): `RowKey::{Server(name), Task(RunId), Grammar(id), Jed}`, `GrammarState::{Waiting, Building, Ready, Failed}` (rows from `app.grammars`), `Row::{Server(ServerRow { name, languages, root (only when not the workspace's), state: ServerState::{Starting, Running, Failed, Exited} (`label`, `glyph` `○ ● ✗ –`, `theme_key` `tools.*`), progress (running only), errors }), Task { id, name, status }, Jed { errors }}` (`key`, `is`, `tool()`: the log it opens — none for a task, `errors`), `task_label` (`exited 0` / `killed` / a signal's name / `failed to start`), `server_rows(manager, errors, root)` (live servers, then `Manager::stopped` ones not shadowed by name, then servers known only by their log; one row per name, the log's), `rows(manager, runs, errors, root)` (servers, task runs, "jed" last), `ToolsView` (`app.tools_view`: the selection by key plus its last index — a row that leaves hands it to the row taking its place, `settle` each frame —, `select` / `select_key` / `move_selection` / `scroll` / `scroll_by` / `clamp` / `reveal_selected`, `height` set by drawing (`set_height`: runs a reveal asked for before the first draw), `errors_drawn` (the counts the last frame drew), `was_shown`; `scrollable(rows)` → `ToolsScroll`)
- `milestone*_tests.rs` — end-to-end tests per milestone (`#[cfg(test)]` modules declared in `main.rs`); `todo_tests.rs` — end-to-end tests for single PLAN.md tasks (no subtasks), one `mod` per item; `syntax_plugins_tests.rs` — syntax plugins (`syntax_plugins_*`)

## Data flow

1. `App::run` (`app/mod.rs`): `tokio::select!` over crossterm `EventStream`, the `AppEvent` channel (`rx`), and one timer (`App::next_timer`: the earliest of the fs-event debounce, the Search view's debounce, the mouse's hover rest, the quick-suggestion delay, the gutter markers' delay, the diff tabs' delay, inline blame's delay, the crash backups' interval and log tabs' wake throttle, run by `on_timer`); then drains queued input so a burst becomes one frame; then `sync_syntax` (once per turn: every buffer's tree re-parsed incrementally, or a background parse started), `sync_quick_diff` (once per turn: starts the gutter markers' computations due, O(buffers) when none is), `sync_blame` (the same for inline blame while it's on, shown buffers only), `sync_diffs` (the same for diff tabs' loads), `sync_commit_tabs` (the same for commit tabs' `git show` reads), `sync_git_history` (the Explorer's "Git History" section: follows the active file, reads pages, reloads after HEAD moved), `sync_backups` (O(buffers): queues removals of clean / closed buffers' backups, sets the backup deadline), `sync_logs` (log tabs take their tools' new lines: one change set per log) and `sync_servers` (starts / stops language servers when `servers_dirty`, then `lsp::Manager::sync_documents`: `didOpen` / `didClose` to match the buffers and one `didChange` per document with the turn's edits), and redraws only when `needs_redraw` (`App::redraw`: a frame that asks for another — the horizontal bar's row appearing or going — gets it at once).
2. `handle_event`: any key first closes the hover popup (`close_hover`; Esc in the editor then does nothing else) and the gutter's peek (except Enter — stage — and Esc in the editor, which it takes); an open `prompt` gets every key; else `keymap.lookup(&key, self.context())` → `Command` (`context()` is `Palette` while the palette is open, `Diff` while the editor has the keys and its active tab is a diff, `Commit` while it's a commit, `Find`/`Replace` while `Focus::Find`, `Problems` / `Locations` / `Task` (by `ui.panel_tab`) while `Focus::Panel`, `Scm` / `Tools` while the side panel has the keys and shows Source Control / Tools (unbound keys and paste do nothing there), `GitHistory` while it shows the Explorer with the history section focused (unbound keys and paste do nothing there), else the Explorer's, `Task` while the panel shows a task tab (keys bound neither here nor globally go to its task: `task_key` / `task_paste`)); else an open palette's `TextField` gets the key; else the find widget's focused input (`find_key`, incremental search); else an unbound plain/Shift char in the editor is typed via `edit::insert_char` (a commit character of the selected completion inserts it first; then `completion_typed`: trigger characters ask, word chars start the quick-suggestion timer). The context is `Suggest` while the completion list is shown. `Event::Paste` (bracketed paste) → the prompt input, the palette, the find input, the Search view, a focused task tab, or `App::paste`. After `sync_views`, `refresh_find` keeps the open widget's match cache current (also after background events), `check_requests` cancels language server requests whose place moved on and `check_hover` closes a popup whose buffer was edited or view scrolled (`check_peek` likewise the peek). Every input event and background result runs between `nav_begin` (the active place before) and `nav_end` (records it in `app.nav.history` if the event jumped: `app/navigation.rs`), before `sync_views`. Mouse events go to `hover_mouse` first (the popup takes events over it; moves start the hover rest timer), then `peek_mouse`.
3. `execute(cmd)`: any command except `Palette(_)` / `ShowCommands` / `QuickOpen` / `GoToLine` first closes an open palette. App-level commands (save, tabs, splits, focus, explorer, copy/cut/paste, find) are handled in `App` (Esc's `CancelSelection` in the editor closes an open find widget first); on a diff tab `diff_command` takes the rest (movement keys move its cursor, next / previous change; anything else does nothing); everything else falls to `edit::run(cmd, buf, view, &settings)` on the active tab, after a read-only check if `edit::is_edit(cmd)`.
4. `edit` builds a `ChangeSet` over all selections and calls `Buffer::edit(changes, before, after, kind)` — one undo transaction.
5. `sync_views` (after every event) drains `Buffer::take_applied()` and maps every *other* view on that buffer through the changes, then `track_selections` records the active view's selection change for Cmd+U and ends the Cmd+D session if something else changed the selections or the editor lost focus.
6. Background results come back as `AppEvent` variants (`SaveDone`, `HistoryDone` (a file history snapshot or move, `app/history.rs`), `HistoryListed` / `HistoryRestore` (File History's picker entries, an entry diffed for a restore), `Opened`, `Listed`, `FsChanged`, `ConfigLoaded`, `FileOpDone`, `FilesMatched`, `FilesWalked`, `LogFileFound`, `SearchResults`, `Parsed`, `LocationsRead` (the Locations list's previews), `GitRefreshed` (a git status refresh, `app/git.rs`), `DiskChecked` (an open file read after file system events naming it, `app/disk.rs`), `QuickDiff` (a buffer's gutter markers), `Blame` (a buffer's inline blame, `app/blame.rs`), `Staged` (a change staged / unstaged, `app/quick_diff.rs`), `DiffLoaded` (a diff tab's texts read and diffed), `DiffStaged` (a stage from a diff tab or of a whole file, `app/diff_view.rs`), `CommitLoaded` (a commit tab's `git show`, `app/commit_tabs.rs`), `Lsp` (every language server task's `lsp::Event`, through the `Sink` closure `start` gives `lsp::Manager`), `Task` (a task run's `tasks::Event`, through the `Sink` `start` gives `app.tasks`), `Shell` (a shell tab's `tasks::Event`, through the sink its tab's run got), `SessionRead` (the session file and its text tabs' files, read once in `start`: `app/session.rs`), `BackupsFound` / `BackupDone` / `BackupRestore` (the start's scan for crash backups, a write / remove job, a backup diffed against its buffer: `app/backup.rs`), `RecentRecorded` / `RecentListed` (the start's record in `recent.toml`, the list read for Ctrl+R: `app/recent.rs`), `ShellIntegrationWritten` / `ShellIntegrationInstalled` (the shell integration snippets written into the state dir, the source line appended to an init file: `app/shell.rs`), `LogsChanged` (a tool log got lines: `app/tools.rs`)) → `handle_app_event`. On quit `run` awaits `App::shutdown` (language servers, bounded by `lsp::SHUTDOWN_TIMEOUT` + 1 s, running tasks and shells killed, `tasks::SHUTDOWN_TIMEOUT`, and the session written off-thread by `save_session`, concurrently; then `finish_backups`) before returning.
7. `ui::render(f, &mut app)` draws and writes back render-time state: `view.height/width`, scroll for `reveal_cursor`, `explorer.height`, the lists' heights (`search_view.list`, `problems.list`), commit tabs' text for their width (`fit_commit_tabs`, a pre-pass before the groups are drawn), running tasks' PTY size and `app.tasks.size` (from the shown task tab), and `app.hits` (used by the *next* mouse event).
