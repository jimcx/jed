# jed

A VS Code-style terminal text editor in Rust (ratatui + crossterm + tokio, ropey 2 beta for text).
**PLAN.md is the source of truth for design and scope** — read the section you need instead of
guessing: Features (one subsection per area), [Keybindings](PLAN.md#keybindings-vs-code-defaults),
[Architecture](PLAN.md#architecture), [Text positions](PLAN.md#text-positions),
[Async and blocking work](PLAN.md#async-and-blocking-work), [Logging](PLAN.md#logging),
[Milestones](PLAN.md#milestones) (each has "Needs", "Deferred" and a "Done when" to test against).
Milestones 1–13 are done and keep their numbers; later ones have names and short ids, not numbers, and no order ([Named milestones](PLAN.md#named-milestones): those marked ✅ are done), each built task by task (`tools-a`, `tools-b`, …), one commit per task, via `/milestones <name>`. Further work is PLAN.md's TODO list, one item per commit via `/todo` (an item too big becomes smaller items or a new named milestone).

## Toolchain and checks

`rust-toolchain.toml` pins 1.99. On Linux plain `cargo` works (the rustup proxy is on PATH); on macOS cargo isn't
on PATH, so prefix every command with `export PATH="$HOME/.rustup/toolchains/1.99-aarch64-apple-darwin/bin:$PATH"`.

```sh
cargo fmt --check                            # rustfmt.toml: max_width = 120
cargo clippy --all-targets -- -D warnings
cargo test                                   # ~150 tests, ~5 s (search's random reference test is most of it)
cargo test --release milestone -- --nocapture --test-threads=1   # M1 and M6 (1 MB Cmd+Shift+L + typing; line/cursor commands at 61k selections; find + replace all) budgets: release only (M6 has coarse debug bounds); serial, since parallel tests nearly double the timings on a slow machine
cargo test --release search -- --nocapture      # so are the 1 MB find-all and 10 MB workspace-search budgets
```

All three must pass before a commit. Cap test runs with `scripts/timeout 300 cargo test …` (macOS has no `timeout`; this kills the whole process group, so cargo's test binary can't outlive it). Edition 2024 (let-chains are used freely).

## Module map (`src/`)

- `main.rs` — arg parsing (`jed [<folder> | <file>[:line[:col]]]`, `--log-level`), loads the first file, `.workspace`, `settings.toml`, `tasks.toml` (into `app.tasks.user`) and `keybindings.toml` *before* raw mode (their load errors go to `App::set_keymap` after the UI starts), builds the tokio runtime, runs `App`
- `app/` — `App`: owns all state, the event loop, `execute(Command)`, prompts, mouse, background-result handling (see `src/app/CLAUDE.md`)
- `command.rs` — `Command` / `Motion` / `ExplorerCommand` / `PaletteCommand` / `FindCommand` / `GitHistoryCommand` / `CommitCommand` enums; `Command::all()` (what the palette lists and keybindings can name; `ExplorerCommand::FindInFolder` = `explorer.findInFolder`, `SearchCommand::{ToggleDetails, NextInput, PreviousInput}` = `search.toggleDetails` (Cmd+Shift+J) / `search.nextInput` / `search.previousInput` (Tab / Shift+Tab in the Search view); `ShowTools` = `tools.show` (Cmd+Shift+U, VS Code's Output), `ToggleToolTrace` = `tools.toggleTrace` and `RestartServer` = `tools.restartServer` (both unbound), `ToolsCommand` = `toolsView.*` (the Tools view's list keys)), `name()` (stable dotted names like `edit.copy`), `from_name`, `title()` (palette text, `Category: Action`)
- `config/keymap.rs` — `Keymap` (data: `(KeyCombo, Option<Context>) -> Command`), `Context` (`Editor`, `Explorer`, `Palette`, `Find`, `Replace`, `Search`, `SearchResults`, `Problems`, `Locations`, `Suggest` (the completion list while shown), `Diff` (the editor with a diff tab active: F7 / Shift+F7), `Scm` (the Source Control view's list), `Tools` (the Tools view's list: arrows, PageUp / PageDown, Home / End, Enter, Esc), `GitHistory` (the Explorer view's "Git History" section: Up/Down/PageUp/PageDown/Home/End select a commit, Enter opens it, Left/Esc back to the tree; unbound keys do nothing), `Commit` (the editor with a commit tab active: Enter opens the cursor's stat row's diff; other keys come from `Editor`), `Task` (a task tab in the panel: Shift+PageUp / PageDown, Ctrl+Shift+Up / Down, Ctrl+Home / End scroll, Esc back to the editor, Cmd+W closes it; keys bound neither here nor globally go to the task); `lookup` tries the context, then its parent — `Replace` → `Find`, `SearchResults` → `Search`, `Suggest` / `Diff` / `Commit` → `Editor` — then global), `Platform`, `default_for(platform)`, `load(path, platform)` (defaults + `keybindings.toml`), `binding_for(cmd)` (the key the palette shows); `KeyCombo::parse` / `spec` (config spelling) / `label` (`Cmd+Shift+P`); `from_event` turns a shifted US digit with Cmd/Ctrl/Alt (`Cmd+!`, how kitty-protocol terminals report Cmd+Shift+1) into digit + Shift, Ctrl+@ (a legacy terminal's Ctrl+Space, NUL) into Ctrl+Space, and `_` with Ctrl/Alt/Cmd (kitty's Ctrl+Shift+-) into `-` + Shift
- `config/settings.rs` — `SettingsOverrides` (the `[settings]` table shared by the user's `settings.toml` and `.workspace`, every key an `Option`; the module doc has the table of keys, types and defaults), `apply`, `layer(user, workspace)` (defaults ← `settings.toml` ← `.workspace`, per key: the one place precedence lives), `load(path)` / `parse` → `UserSettings { overrides, errors }` (missing file: silent; TOML syntax error: defaults + one error with its line; unknown key, misplaced key/table or wrong type: reported and skipped, the other keys apply — VS Code's leniency, unlike `.workspace`, which rejects the whole file), `TEMPLATE` (every key commented out at its default) and `create_if_missing` (for "Preferences: Open User Settings"; `create_new`, so it never overwrites a file)
- `edit.rs` — movement and editing at every selection (`edit::run`, `insert_char(buf, view, c, settings)`, `paste`, `copy_text`, `cut`), `Settings` (tab width, spaces, `syntax_max_bytes`, `auto_close_pairs`, `auto_indent`, `match_brackets`, `quick_suggestions`, `render_whitespace`: `RenderWhitespace::{None, Boundary, Selection, Trailing, All}`, VS Code's `editor.renderWhitespace`, default `All`, serde lowercase strings; drawing only, the effective mode is `App::render_whitespace()`); `edit::run` (and the status bar) use `Settings::for_language` (the buffer language's `LanguageConfig::insert_spaces`: Makefiles always indent with tabs, VS Code's `[makefile]` default). Enter is `indent::newline`; Tab (`InsertTab`) is `shift::tab` when a selection covers lines or a whole line, else a tab (spaces to the next stop) at each selection, `EditKind::Insert`. `insert_char` tries `indent::type_char` (with `auto_indent`), then `pairs::type_char` (only for a char in the language's pairs; any other char takes the plain path untouched); Backspace tries `pairs::delete_pair`. `replace_each_landing` (`Land::{AfterText, Inside(n), Keep(p)}`) also carries the view's `AutoClosed` through its edit (`follow` before, `edited` after). `paste(buf, view, text, whole_line, pieces)` spreads one part per cursor (VS Code's `multiCursorPaste: spread`): jed's own copied pieces if there are as many, else the text's lines (one final line break ignored); never for a whole-line copy or one cursor. `copy_text` returns a `clipboard::Copied`; only one empty cursor's copy is whole-line (VS Code)
- `completion.rs` — completion's model (no drawing; `app/completion.rs` drives it, `ui/completion.rs` draws it): `parse` (`CompletionItem[]` / `CompletionList` with `itemDefaults`; an item inserts its `textEdit` — an `InsertReplaceEdit`'s `insert` range — else `insertText` / `label` over the word before the cursor), `strip_snippet` (placeholders → their defaults; selects the first tab stop, else `$0`), `Filter` (nucleo fuzzy, case-insensitive, first char at a word start), `Anchor` (where a request was asked: rope snapshot + primary cursor, the word's `start` and the cursor `at` followed through edits by `Buffer::sets_applied`, `in_word`, `now(p)` for snapshot positions), `place` (each item's range → `lead` / `after` bytes), `Popup` (items, `shown` sorted by score then `sortText`, `refilter`, selection / scroll), `Completion` (`popup`, the pending `ask`, the `quick` timer), `insert(buf, view, Insertion)` (the item at every selection — the same char counts before / after each as at the primary, only word chars when the primary's are — plus `additionalTextEdits`, one `ChangeSet`, `EditKind::Other`, O(selections) via `Peek`; multi-line text gets each line's indentation and the buffer's EOL)
- `column.rs` — add cursor above / below (`add_cursor`, keeps the goal column), Shift+Alt+I (`cursors_at_line_ends`), column (box) select: `select(from, to)` per line between two display columns (nearest grapheme boundary, short lines skipped, VS Code's `ColumnSelection`), `step` for Cmd+Shift+Alt+arrows, `current` (the view's `ColumnBox` while its selections are unchanged, else the primary's anchor/head). Uses `pos::LineWalker`, not per-cursor lookups
- `commit_view.rs` — a commit tab's model (no drawing, no app state: `app/commit_tabs.rs` opens, loads and fits it). A commit tab is a read-only text tab, as a log tab is (see Log tabs): a `Buffer` with `commit: Some(CommitDoc)` (`Buffer::commit(id, file)`, `name()` = the 7-hex short id). `CommitDoc { commit (full id), file (the work-tree-relative path whose history opened it), show: Option<Arc<git::show::Show>>, error, running }` + the lines last rendered; `want()` (`Now` only before a load; a commit never changes, a failed load isn't retried), `begin` / `finish`, `render(width) -> Option<String>` (the text — `git_show::render` at that width, lines joined with `\n`, or the load's error — only when it isn't the one shown; no I/O), `title()`, `file_at(line)` / `file_row(k)` / `own_file_row()` (stat lines ↔ `Show::files`), `spans(rope, lines)` (git's colours as byte ranges + theme keys: the id `gitShow.commit`, a stat's `+` `gitShow.add`, `-` `gitShow.del`; what `ui::editor` draws instead of syntax colours)
- `comment.rs` — comment line (Cmd+/, `toggle`): VS Code's `LineCommentCommand` per selection (a line shared by two belongs to the first; one ending at a later line's start doesn't take it): uncomment if every non-blank line starts with the token (+ one space), else comment the non-blank lines (all, if all are blank) at the selection's smallest indentation (never inside a tab); one `ChangeSet` via `LineWalker`, one undo step (`EditKind::Other`); selections keep text inserted at their edges, a cursor at the insertion point lands after the token. No token (plain text): nothing
- `indent.rs` — auto-indent at every cursor (VS Code's `autoIndent: full`, approximated; the module doc lists the rules and differences): `newline` (Enter: the line's indentation up to the cursor; + a level after an opening bracket token, a Python block keyword line ending in `:` or a YAML line ending in `:` / `-`; C/C++ and Rust also VS Code's (C/C++) `indentationRules` (+ a level after a bracket left unclosed anywhere before the cursor, − one before a closing bracket after it; the tree is walked only when the text has a quote or `/*`); `IndentOutdent` between a pair (closer on its own line, cursor on the indented middle line, `Land::Inside`); − a level after Python `return`/`pass`/…; trailing comments skipped (tree, else the line comment token); a whitespace-only line's rest dropped; all new texts in one `String`, one `EditKind::Insert` edit) and `type_char` (a closing bracket first on its line re-indents the line to its opener's line, via `brackets::Openers`, not inside a multi-line string / comment; Python `else:` / `elif …:` / `except …:` / `finally:` to the nearest less indented `if` / `try` / … line). Enter's lines via `LineWalker`, tree checks via forward `syntax::Tokens` walks; a closer reads only bytes (`Peek::blank_line_start` / `line_indent`), not lines, so 65k cursors stay well within the 80 ms line-command budget (Enter ~50 ms, `}` ~20 ms). `Settings::auto_indent = false`: Enter is a plain line break, no outdent
- `brackets.rs` — bracket matching over the language's bracket pairs (`LanguageConfig::brackets`): `match_at(rope, syntax, pos)` (the bracket after the cursor, else before it, and its partner; with a current token tree (`Syntax::token_tree`: not Markdown's) only bracket tokens count — not in strings / comments — and the partner is found among the token's siblings (missing = unmatched); without one, a text scan of at most `WINDOW` (16 KB) each way), `Openers` (innermost unclosed opener before increasing positions: one pass over tokens or text with a stack, restarting `WINDOW` back after a gap) and `Matches` (the view's highlight cache: recomputed only when revision, language, tree availability or the on-screen cursor heads (first `MAX_CURSORS`, 64) change)
- `pairs.rs` — auto-close at every cursor, VS Code's defaults, each rule all-or-nothing over the selections (as VS Code): type-over (only closers jed inserted: `AutoClosed` on the `View`, one action per auto-closing key, live while every cursor is strictly inside one of its pairs (after the open char, before the closer's end) and they stay on one line (a typed line break drops them, as VS Code); dropped by any edit not made through `replace_each_landing` of that view, checked by buffer revision), auto-close (next char in `autoCloseBefore` or a closing bracket; `'` / `"` not after a word char unless a Python string prefix letter is before every cursor (then `notIn` strings and comments), not in a string / comment per pair when the tree is current: `Syntax::scope_before`; seals undo before, `EditKind::Insert`), wrap non-blank selections (`EditKind::Other`, inner text stays selected), Backspace in an auto-inserted empty pair deletes both. `pos::Peek` reads the chars next to each cursor. Off with `Settings::auto_close_pairs = false`. `pairs::tests::{setup, show}` mark text with `|` (cursor) and `«…»` (selection) — the comment tests use them too
- `lines.rs` — move lines (`move_lines`, Alt+Up/Down) and copy lines (`copy_lines`, Shift+Alt+Up/Down) at every selection: selections are grouped into line blocks (sharing a line; for moves also neighbouring lines); a non-empty selection ending at a line start doesn't take that line; one undo step (`EditKind::Other`), none if nothing moves; selections follow the moved / lower copied text
- `shift.rs` — indent / outdent lines (`indent` = Cmd+] `edit.indentLines`, `outdent` = Cmd+[ / Shift+Tab `edit.outdentLines`; Linux Ctrl+] / Ctrl+[), VS Code's `ShiftCommand`: each touched line's indentation to the next / previous multiple of the tab width, written in the language's spaces / tabs (`Settings::for_language`; mixed indentation normalised, only the differing part replaced); `comment.rs`'s line rules (an end at a line start doesn't take it, a shared line once); empty lines skipped unless the selection is on that line alone; `tab` (Tab) per selection as VS Code: over lines or a whole line → its lines indented, else a tab in its place, one step — `false` when none indents (then `edit::insert_tab`). Selections keep their text (a non-empty one starting in its first line's indentation keeps that column, growing / shrinking). One `ChangeSet` via `LineWalker`, forward only, `EditKind::Other`; nothing to change = no step
- `buffer/` — `Buffer`/`Buffers`, `ChangeSet`, undo `History`, file load/save, and **all** position types/conversions in `buffer::pos` (see `src/buffer/CLAUDE.md`)
- `selection.rs` — `Selection` (anchor, head, goal column) and `Selections` (sorted, merged, never empty; a primary and a *newest* — the one added last, which Cmd+D searches after; `new` takes the last list entry as newest, `with_newest` names it). The list is an `Arc` (copy on write): clones are cheap and equal clones compare by pointer; normalizing skips the sort when the list is already sorted (after an edit or mapping) and merges in place. Merging is VS Code's: overlapping, or touching when one is an empty cursor; two non-empty selections that only touch stay apart. `overlapping(from, to)` (binary search, for drawing) and `contains_range`
- `view.rs` — `View`: selections + scroll for one tab; `map_through` follows edits made via another view (and clears its Cmd+U history first, so the list is mapped in place; positions go start then end, in order, for the mapper's forward stepping); `reveal_range` (centre a range if off screen, set by Cmd+D); `reveal_pos` (scroll just enough to show a position, e.g. the newest added cursor); `column` (the last `column::ColumnBox`); `auto_closed` (`pairs::AutoClosed`: the closers typing can step over); `brackets` (`brackets::Matches`, the highlighted brackets); `CursorHistory` (Cmd+U: up to 50 earlier selection lists + scroll, cleared by any text change)
- `multicursor.rs` — Cmd+D / Cmd+Alt+D (`next_match`, `Step::{Add, Skip}`) and Cmd+Shift+L (`select_all`) as VS Code's `MultiCursorSession`: a `Session` is word mode (empty single cursor: whole word, case-sensitive) or the primary's text literally with the find widget's case/whole-word (`App::find_options`, default off); searches after the newest selection, wraps, skips already-selected matches. Several selections with different text: Cmd+D first expands empty cursors to words
- `navigation.rs` — back / forward navigation's model (no app state; `app/navigation.rs` records and navigates): `History` (one per window, `MAX` 50 `Entry { group, path, pos: Option<Pos { anchor, head, top, left_col }> }` — `None`: a diff tab — and `index` (`len` = live); `record` drops the forward entries, `back(current)` / `forward(current)` store where you are first, `skip(dir)` drops a gone file's entry, `map(path, changes)` follows edits (`Assoc::Before`); consecutive same places (group, path, selection) collapse), `MIN_LINES` (10: a move that far is recorded), `Dir::{Back, Forward}`
- `group.rs` — `Tab::{Text(TextTab { buffer, view }), Diff(Box<DiffTab>)}` (`text()`, `diff()`, `buffer()` — `None` for a diff tab), `Group` (tabs, active; the tab bar's `scroll` — first tab shown — and `revealed` (active tab + bar width last scrolled into view), so the wheel / arrows can scroll it away from the active tab; `scroll_tabs(delta)` (drawing clamps it); `active_tab()` / `active_tab_mut()` = the active tab *only when it's a text tab*, `active_diff()` / `active_diff_mut()`, `find(buffer)` and `text_tabs_mut()` text tabs only; `open(buffer, view)` / `open_tab(Tab)` activate the new tab, `open_background` keeps the active one), `Groups` (map + `SplitTree`, always ≥1 group; `split(dir, diff_id)` copies the active tab — a diff tab as `DiffTab::copy` with a new id — in a group from `split_empty(dir)` (no tabs); `tabs_showing(buffer)`, `diff_tabs_mut()`; `restore(tree, groups, active)` (a session's: `check_restore` — the tree's leaves are exactly the group ids, `active` among them — then ratios sanitized, new ids after the largest))
- `layout.rs` — `SidePanel::{Explorer, Search, SourceControl, Tools}` (`ALL`: the activity bar's order; serde snake_case in sessions), screen `Regions` (`compute(area, side_visible, side_width, panel_height)`: the bottom panel under the editor groups only, the side panel keeping its height; clamped so the editor keeps `MIN_EDITOR_HEIGHT` and the panel gets `MIN_PANEL_HEIGHT` when that fits), `PanelTab` (`Problems`, `Locations` (its tab only while there's a list), `Task(RunId)` (one per run, after them, until closed); `task_area(panel)`: a task tab's terminal rect, the PTY's size), `SplitTree` of editor groups (serde: the session file stores it as is, group ids at the leaves; `sanitize` repairs ratios read from a file), `HitMap`/`Hit` for mouse hit-testing (`PanelBorder` (resize drag), `PanelTab`, `PanelTabClose(RunId)` (a task tab's `×`, `HitMap::panel_closes`), `Panel` + `HitMap::panel_list` (the shown tab's list: `ListHit`, list rect + each row's `RowKey`), `Hover` (`HitMap::hover`, the popup's rect: checked first, nothing under it gets the event), `QuickDiff` (`HitMap::quick_diff`: the gutter's peek, `QuickDiffHit { rect, stage, close }`, checked after the hover), `StatusProblems` (the status bar's counts, `HitMap::status_problems`), `HitMap::scm` (the Source Control view: `ScmHit { list, rows: Vec<scm::RowKey>, buttons: (rect, key, unstage) }`; its clicks arrive as `Hit::SidePanel`), `HitMap::tools` (the Tools view: `ToolsHit { list, rows: Vec<tools_view::RowKey> }`, also `Hit::SidePanel`), `Banner(group, Option<BannerAction>)` (the changed-on-disk banner over a group's editor, `GroupHit::banner`: `BannerHit { row, actions }`), `GroupHit::diff` (a diff tab: `DiffHit { rows, buttons: (rect, hunk), reverts: (rect, hunk) }`; its clicks arrive as `Hit::Editor(group)`), `ScrollBar(ScrollTarget)` (`ScrollTarget::{Group(GroupId), Side(SidePanel), Panel(PanelTab), History}`: what a bar scrolls; `ScrollBarHit { track, thumb }` in `GroupHit::scrollbar` (the editor's last column — `GroupHit::editor` excludes it), `HitMap::side_scrollbar` / `panel_scrollbar` / `history_scrollbar` (the shown list's last column — its list / row rects exclude it); `HitMap::scrollbar(target)`; checked before the editor / rows / panel), `Hit::HistoryDivider` / `HistoryHeader` / `HistoryRow(row)` (`HitMap::history`: the Explorer's "Git History" section — `HistoryHit { divider, header, list, top }`, checked before the explorer rows), `Hit::TabArrow(group, forward)` (a tab bar's `‹` / `›` while its tabs overflow: `GroupHit::tab_arrows`, a `TabArrows { back, forward }`, checked before its tabs))
- `ui/` — ratatui drawing, `ui::render(f, &mut App)`; colours only via `Theme` (see `src/ui/CLAUDE.md`)
- `theme.rs` — `Theme::dark_plus(truecolor)`: named keys (`"editor.selection"`, `"statusBar.error"`, …) → `Style`, 256-colour fallback; syntax token keys are bare capture names (`keyword`, `keyword.control`, `string`, `comment`, `type.builtin`, … = `syntax::KEYS`) with Dark+'s token colours, incl. `markup.{heading,list,quote,raw,link}` (Markdown; heading bold, link underlined) and `tag` / `tag.attribute` / `punctuation.tag` (XML; YAML keys are `tag`); `editor.bracketMatch` (matched brackets' background); `editorWhitespace.foreground` (rendered spaces `·` / tabs `→`, Dark+'s blended over the editor); `editorError.foreground` / `editorWarning.foreground` / `editorInfo.foreground` / `editorHint.foreground` (diagnostics' squiggles: `Modifier::UNDERLINED` + `underline_color`, no fg / bg — ratatui has no undercurl; the editors' scroll bar thumb `scrollbarSlider.background` / `.hoverBackground` / `.activeBackground` (Dark+'s translucent sliders blended over the editor; the track is `editor`); the diff view's Revert button `diffEditor.revertAction` (red); the Source Control view's `scm.count` (section badges), `scm.action` (its `+` / `−` buttons), `scm.deleted` (struck through); the Explorer's "Git History" rows' `gitHistory.author` / `gitHistory.date` / `gitHistory.hash` (the short id); a commit tab's `gitShow.commit` (the commit id, yellow), `gitShow.add` (its stat's `+`, green) and `gitShow.del` (`-`, red); inline blame's `git.blame.editorDecorationForeground`; the Tools view's state marks `tools.starting` / `.running` / `.failed` / `.exited` and `tools.errorBadge`
- `diagnostics.rs` — diagnostics as the editor shows them (no LSP, no drawing): `Severity` (`Error` < `Warning` < `Info` < `Hint`; `from_lsp` (missing = error), `theme_key`, `icon` `⊗ ⚠ ⓘ …`, `icon_key` (the Problems list's icon colours)), `Diagnostic` (severity, message, source, code; shared as `Arc` between the LSP store and buffers), `Mark { start, end, server, diag }` and `Marks` (on every `Buffer` as `buf.diagnostics`: sorted by (start, end) with a prefix max of ends; `replace(server, marks)` (one server's set), `clear(server)`, `map(&ChangeSet)` (called by `Buffer::apply`: start `Assoc::After`, end `Before`, so text typed at a range's edges stays outside and a deleted range becomes empty), `overlapping(from, to)` (binary search both ends: thousands of marks, few on screen), `for_line(start, end, head)` (the status bar's: most severe touching the line, the one under the cursor first)), `runs(marks, extent)` (flattened, non-overlapping, most severe wins: what the editor draws)

## Data flow

1. `App::run` (`app/mod.rs`): `tokio::select!` over crossterm `EventStream`, the `AppEvent` channel (`rx`), and one timer (`App::next_timer`: the earliest of the fs-event debounce, the Search view's debounce, the mouse's hover rest, the quick-suggestion delay, the gutter markers' delay, the diff tabs' delay, inline blame's delay, the crash backups' interval and log tabs' wake throttle, run by `on_timer`); then drains queued input so a burst becomes one frame; then `sync_syntax` (once per turn: every buffer's tree re-parsed incrementally, or a background parse started), `sync_quick_diff` (once per turn: starts the gutter markers' computations due, O(buffers) when none is), `sync_blame` (the same for inline blame while it's on, shown buffers only), `sync_diffs` (the same for diff tabs' loads), `sync_commit_tabs` (the same for commit tabs' `git show` reads), `sync_git_history` (the Explorer's "Git History" section: follows the active file, reads pages, reloads after HEAD moved), `sync_backups` (O(buffers): queues removals of clean / closed buffers' backups, sets the backup deadline), `sync_logs` (log tabs take their tools' new lines: one change set per log) and `sync_servers` (starts / stops language servers when `servers_dirty`, then `lsp::Manager::sync_documents`: `didOpen` / `didClose` to match the buffers and one `didChange` per document with the turn's edits), and redraws only when `needs_redraw`.
2. `handle_event`: any key first closes the hover popup (`close_hover`; Esc in the editor then does nothing else) and the gutter's peek (except Enter — stage — and Esc in the editor, which it takes); an open `prompt` gets every key; else `keymap.lookup(&key, self.context())` → `Command` (`context()` is `Palette` while the palette is open, `Diff` while the editor has the keys and its active tab is a diff, `Commit` while it's a commit, `Find`/`Replace` while `Focus::Find`, `Problems` / `Locations` / `Task` (by `ui.panel_tab`) while `Focus::Panel`, `Scm` / `Tools` while the side panel has the keys and shows Source Control / Tools (unbound keys and paste do nothing there), `GitHistory` while it shows the Explorer with the history section focused (unbound keys and paste do nothing there), else the Explorer's, `Task` while the panel shows a task tab (keys bound neither here nor globally go to its task: `task_key` / `task_paste`)); else an open palette's `TextField` gets the key; else the find widget's focused input (`find_key`, incremental search); else an unbound plain/Shift char in the editor is typed via `edit::insert_char` (a commit character of the selected completion inserts it first; then `completion_typed`: trigger characters ask, word chars start the quick-suggestion timer). The context is `Suggest` while the completion list is shown. `Event::Paste` (bracketed paste) → the prompt input, the palette, the find input, the Search view, a focused task tab, or `App::paste`. After `sync_views`, `refresh_find` keeps the open widget's match cache current (also after background events), `check_requests` cancels language server requests whose place moved on and `check_hover` closes a popup whose buffer was edited or view scrolled (`check_peek` likewise the peek). Every input event and background result runs between `nav_begin` (the active place before) and `nav_end` (records it in `app.nav.history` if the event jumped: `app/navigation.rs`), before `sync_views`. Mouse events go to `hover_mouse` first (the popup takes events over it; moves start the hover rest timer), then `peek_mouse`.
3. `execute(cmd)`: any command except `Palette(_)` / `ShowCommands` / `QuickOpen` / `GoToLine` first closes an open palette. App-level commands (save, tabs, splits, focus, explorer, copy/cut/paste, find) are handled in `App` (Esc's `CancelSelection` in the editor closes an open find widget first); on a diff tab `diff_command` takes the rest (movement keys move its cursor, next / previous change; anything else does nothing); everything else falls to `edit::run(cmd, buf, view, &settings)` on the active tab, after a read-only check if `edit::is_edit(cmd)`.
4. `edit` builds a `ChangeSet` over all selections and calls `Buffer::edit(changes, before, after, kind)` — one undo transaction.
5. `sync_views` (after every event) drains `Buffer::take_applied()` and maps every *other* view on that buffer through the changes, then `track_selections` records the active view's selection change for Cmd+U and ends the Cmd+D session if something else changed the selections or the editor lost focus.
6. Background results come back as `AppEvent` variants (`SaveDone`, `HistoryDone` (a file history snapshot or move, `app/history.rs`), `HistoryListed` / `HistoryRestore` (File History's picker entries, an entry diffed for a restore), `Opened`, `Listed`, `FsChanged`, `ConfigLoaded`, `FileOpDone`, `FilesMatched`, `FilesWalked`, `LogFileFound`, `SearchResults`, `Parsed`, `LocationsRead` (the Locations list's previews), `GitRefreshed` (a git status refresh, `app/git.rs`), `DiskChecked` (an open file read after file system events naming it, `app/disk.rs`), `QuickDiff` (a buffer's gutter markers), `Blame` (a buffer's inline blame, `app/blame.rs`), `Staged` (a change staged / unstaged, `app/quick_diff.rs`), `DiffLoaded` (a diff tab's texts read and diffed), `DiffStaged` (a stage from a diff tab or of a whole file, `app/diff_view.rs`), `CommitLoaded` (a commit tab's `git show`, `app/commit_tabs.rs`), `Lsp` (every language server task's `lsp::Event`, through the `Sink` closure `start` gives `lsp::Manager`), `Task` (a task run's `tasks::Event`, through the `Sink` `start` gives `app.tasks`), `SessionRead` (the session file and its text tabs' files, read once in `start`: `app/session.rs`), `BackupsFound` / `BackupDone` / `BackupRestore` (the start's scan for crash backups, a write / remove job, a backup diffed against its buffer: `app/backup.rs`), `RecentRecorded` / `RecentListed` (the start's record in `recent.toml`, the list read for Ctrl+R: `app/recent.rs`), `LogsChanged` (a tool log got lines: `app/tools.rs`)) → `handle_app_event`. On quit `run` awaits `App::shutdown` (language servers, bounded by `lsp::SHUTDOWN_TIMEOUT` + 1 s, running tasks killed, `tasks::SHUTDOWN_TIMEOUT`, and the session written off-thread by `save_session`, concurrently; then `finish_backups`) before returning.
7. `ui::render(f, &mut app)` draws and writes back render-time state: `view.height/width`, scroll for `reveal_cursor`, `explorer.height`, the lists' heights (`search_view.list`, `problems.list`), commit tabs' text for their width (`fit_commit_tabs`, a pre-pass before the groups are drawn), running tasks' PTY size and `app.tasks.size` (from the shown task tab), and `app.hits` (used by the *next* mouse event).

## Invariants and conventions

- **Positions:** `ByteIdx` (UTF-8 byte offset, char boundary; cursors on grapheme boundaries) is the canonical unit; `DisplayCol` for screen columns. Line/column/grapheme/word conversions live only in `buffer::pos` (`line_of`, `line_start`, `line_end`, `display_col`, `byte_at_col`, `next_grapheme`, `word_left`, …). Other modules hold `&Rope` but only call `len()`, `slice(..)`, `to_string()`, `clone()`, `floor_char_boundary()` on it. No raw `usize` byte offsets across modules (line indices are plain 0-based `usize`).
- **Text only changes through `Buffer::edit` / `undo` / `redo`** (the sole `rope.insert/remove` is in `ChangeSet::apply`, called only from `Buffer::apply`, which also feeds each change set to `Syntax::edit` and, while a language server has the document open, records it with the rope from before it for `take_tracked`). Bypassing it breaks undo, other views' cursors, the parse tree and the servers' copies.
- **Parse trees:** `buf.syntax.tree()` is `Some` only while the tree matches the text exactly (never a stale one); between an edit and the next `sync_syntax`, and while a background parse runs, it is `None`. Drawing never reads the tree: it asks `buf.syntax.spans(rope, lines)`, which keeps the last colours (mapped through the edits) until the new tree arrives. tree-sitter `Point`s come from `pos::ts_point` (rows count LF only, as tree-sitter does).
- **Selection list everywhere:** every command works on `view.selections` (a `Selections`, never a single cursor). Build new lists with `Selections::new`/`single`/`transform` so they stay sorted and merged.
- **Undo grouping:** `EditKind::Insert`/`Delete` join consecutive same-kind edits (<1 s, selections continuous); `EditKind::Other` (paste, cut, comment line, wrapping a selection) is always its own step; an auto-close seals before itself, so it starts a step that later typing joins (VS Code). Non-edit actions (moves, clicks, tab/group switches, select-all) call `buf.seal_undo()`.
- **Files changed on disk:** every `Buffer` keeps the `Stamp` (length + SHA-256 of the bytes) of its file as it last knew it (`disk()`: loaded, saved, reloaded, or accepted by "keep mine"); never compare times. `flush_fs_changes` → `disk_paths_changed` checks each buffer whose file (or a folder above it) changed, off-thread, one check per buffer at a time and none while it saves (`save_epoch`: a check overlapping a save is redone after it). Unchanged = nothing (our own saves); missing → `deleted` (tab "(deleted)", struck through; a save recreates); changed and no edits (`has_edits`) → `Buffer::reload` (one `EditKind::Other` step through `Buffer::edit`, ends clean, undoable; every view's selections via `rename::follow`); changed with edits → `disk_conflict` (the banner: `file.reloadFromDisk` / `file.keepMine`, unbound, in the palette); binary / not UTF-8 → no silent reload, a message and the banner. A save refuses (`SaveError::Conflict`, nothing written) when the file holds neither the known stamp nor what it would write. Files outside the workspace root aren't watched (the save check still guards them).
- **Read-only buffers:** `App::active_writable()` gates edits, cut and paste; copy still works.
- **Log tabs:** a tool's log is an ordinary text tab on a `Buffer` with `log: Some(LogTab)` (`Buffer::log(tool)`): an empty `path`, `read_only` ("a log can't be edited": edits, cut, paste, undo refused by `active_writable`; copy, find, select all, splits work), text changed only by `Buffer::append` (no undo step, never dirty), one per tool (reused: `open_tool_log`). Anything keyed by a file must skip it — `active_path()` / `active_file_buffer()` (Save, history, git, Compare…) are `None` on it, `git_path`, `detect_language` (plain text), `disk_paths_changed`, navigation's `here`, `reveal_active`, `session_snapshot` and `start_servers` (no `[lsp.plaintext]` for a log) check `Buffer::has_file()` (false for a log or a commit); the empty path keeps the rest out (`lsp::documents` and sessions want absolute paths, `Repo::relative` / `history::relative` fail, never dirty: no backups, no workspace search snapshot). Drawn without whitespace glyphs. Commit tabs are the same kind of buffer (`commit_view`).
- **Tabs:** a tab is a text editor or a diff view (`group::Tab`); log and commit tabs are text tabs (see Log tabs). Code acting on "the active editor" uses `Group::active_tab()` / `App::active_mut()` / `active_buffer()`, which are `None` on a diff tab — so editor commands, find, completion, hover, LSP requests and the gutter do nothing there without checks of their own. What a diff tab should still do goes through `App::active_file_buffer()` (a text tab's buffer, or the open buffer of a diff tab's file: Save, Reload, Keep Mine, Compare with Disk) or the diff's own arms in `execute` (`diff_command`, `diff_stage`). A new tab kind adds a `Tab` variant, its drawing in `ui::mod` and `ui::tabs`, its `split` copy and its context — or, when it's text to read, is a read-only buffer as logs and commits are.
- **Keymaps are data:** commands never look at keys. Default bindings live in `keymap::defaults` (a `Vec<Binding>`; list order decides which key the palette shows), per platform (`cmd` = Super on macOS, Ctrl on Linux; `word` = Alt on macOS, Ctrl on Linux). A context binding wins over a global (`None`) one. `keybindings.toml` (`[[binding]]` with `key`, `command`, optional `context` = `editor`/`explorer`/`palette`/`find`/`replace`/`search`/`searchResults`/`problems`/`locations`/`suggest`/`diff`/`scm`/`tools`/`gitHistory`/`commit`/`task`) is loaded once at startup in `main` (`App::set_keymap` reports errors): every command it names loses all its default keys; a user key also overrides whatever was on it in that context. `Command` must stay `Copy + Hash` (no owned payloads).
- **Settings layer per key:** `edit::Settings::default()` ← `~/.config/jed/settings.toml` ← `.workspace` `[settings]`, only in `config::settings::layer` (via `Workspace::settings()`, stored in `App::settings`, recomputed on a `.workspace` reload). `settings.toml` is read once at startup (live reload is a TODO in PLAN.md). Adding a setting: a field in `edit::Settings` (+ default), an `Option` field in `SettingsOverrides` and a line in its `apply`, a row in `config/settings.rs`'s doc table and a line in its `TEMPLATE` (`template_lists_every_key_at_its_default` names every field without `..`, so it won't compile until the new one is added there, and then fails if `TEMPLATE` lacks it); it then works from both files.
- **Colours:** no `Color::`/`Modifier::` outside `theme.rs`; widgets call `theme.get("key")` (a missing key logs `missing theme key`). Add new keys to `Theme::dark_plus`.
- **Never block the UI thread:** file reads, saves, listings, file ops, config reloads, workspace search, first parses and every `git2` call go through `tokio::task::spawn_blocking` and report back with an `AppEvent`; language servers are async tokio tasks (process spawn included) reporting via `AppEvent::Lsp`; task runs spawn their PTY process in `spawn_blocking` and read / wait on their own threads, reporting via `AppEvent::Task` (output throttled to one event per frame). Blocking functions are documented `/// Blocking: call from spawn_blocking`. `App::new` must not spawn anything (it can run before the runtime is entered); `App::start` does.
- **Language server requests:** `App::send_request(group, buffer, at, method, supported, Request)` (`app/lsp.rs`) sends through `lsp::Manager::request_at` (`send_doc_request` / `Manager::request_doc`: no `position`, for whole-document requests like formatting) and keeps a `Pending` (request kind, group, buffer, revision, position, encoding) in `App::requests` by (server, id); a newer request of the same kind cancels the older (`$/cancelRequest`), `check_requests` after each input event cancels ones whose place moved on (buffer edited; the cursor — the active view of the active group — or, for a mouse hover, the pointer elsewhere), answers are taken only for pending and still current requests (else dropped as stale; errors that are `RpcError::is_routine` — cancelled, ContentModified (rust-analyzer while loading) — dropped quietly, no message) and go to their kind's handler (`hover_answer`, `definition_answer`, `completion_answer`, `references_answer`, `rename_answer`, `format_answer`, …); `Failed` / `Exited` drop that server's pending ones. A new request kind adds a `Request` variant and an arm in `App::answer`.
- **Edits from background results** (a rename's `WorkspaceEdit`) go through `Buffer::edit` like any other; the code sets the active view's selections itself when it shows the buffer, then calls `App::follow_edits` (`sync_views` without the Cmd+U / Cmd+D tracking) so every other view follows at once. A file not open is loaded through the `opening` map (`OpenRequest { background, edits }`), never on the UI thread.
- **File history:** `App::save` takes a `history::Job` (`App::history_job`: `[history] enabled` and `history::relative`) into the save's task; `SaveJob::write` returns the bytes written and, after `SaveDone { history: true }` is sent, `history::record` runs in a second `spawn_blocking` → `AppEvent::HistoryDone(Result<(), String>)` (an error: a warning message; the save already succeeded). An explorer rename moves the history in the file op's blocking task after the rename (`history_rename`), also ending with `HistoryDone`; a delete keeps it. Watcher events under `<root>/.jed/` are dropped in `fs_changed` before `fs_pending`, so history writes cause no listings, git refreshes or disk checks. "File History: Show" / "Restore" (`fileHistory.show` / `.restore`, unbound): the entries are read off-thread (`AppEvent::HistoryListed`) before the palette opens (`Picker::History { restore }`, rows from `app.file_history.picker`); a restore reads + decodes + diffs the entry off-thread (`AppEvent::HistoryRestore`) and applies it with `apply_changes` (one `EditKind::Other` step, `rename::follow` selections), re-diffed if the buffer changed meanwhile. Entry points: the palette, the explorer ("Explorer: Show File History", `explorer.showFileHistory`, on the selected file; right-click on a file's row) and the tab bar (right-click on a tab: its file's). The file needn't be open: Compare's `Text::Buffer` side reads the disk until it opens; Restore opens it first (`OpenRequest::restore`) and restores into the buffer, nothing written.
- **Sessions:** `App::state_dir` (`Some(paths::state_dir())`; `None` under `cfg(test)` unless a test sets it before `test_start`: sessions off) holds `sessions/`. `start` reads the workspace's session and its text tabs' files in one `spawn_blocking` (`session::read`) → `AppEvent::SessionRead` → `session_read`, which replaces the start layout at once (the first frame may be drawn before it): groups, tree, tabs (text tabs' views: selections clamped to the text, `top_line`, `left_col`, no reveal; diff tabs by path and pair, loading as usual), panels (the bottom panel on Problems); groups left without tabs close; tabs open before it (the command line's file) go on top in the restored active group, activated — onto the group's tab of that file when it has one, its view taking the command line's cursor only when a line was given (`jed a.rs:12`). A bad session file restores nothing (logged). `App::shutdown` writes the session (`save_session`: snapshot on the UI thread, atomic write in `spawn_blocking`, awaited), except while the restore's read is still running (`session.loading()`), so a quick quit never loses it. Never written on a crash.
- **Crash backups:** dirty buffers are written under `App::state_dir` (`backup::dir`: per workspace) every `backup::INTERVAL` (30 s) — `sync_backups` sets the deadline once a dirty buffer differs from its backup (by revision and path), `Timer::Backup` → `backup_tick` writes every such buffer (rope snapshots, one `spawn_blocking` job at a time: queued removals first, then the writes → `AppEvent::BackupDone`; a failed write is due again, reported once). A backup is removed when its buffer is no longer dirty (saved, reloaded, undone to clean), closed or renamed (`sync_backups`, every turn). `App::shutdown`, after the session: the running job awaited, then a clean quit (`should_quit`: every buffer saved or discarded) removes the workspace's backups except ones put off with Later or not yet offered; the event stream ending without Quit writes every dirty buffer's backup instead; while the start's scan still runs, a clean quit removes nothing and a lost terminal writes only files without a backup (not yet offered). `start` scans (`backup::list`, no writes until it's done) → `backups_found`, offered once the session is restored (`session_read` → `offer_backups`; after the trust dialog when that's open) as `Prompt::RestoreBackups` (`app.backups.offered`): Restore (R / Enter) — each backup through `restore_backup`: the open buffer, else the file opened (`OpenRequest::backup`), diffed off-thread (`disk::changes`) → `AppEvent::BackupRestore` → `apply_changes` (one `EditKind::Other` step, left dirty, nothing written; redone if the buffer changed meanwhile); a backup whose base `disk` stamp isn't the buffer's (the file changed since) makes it `Buffer::set_disk_base(base)` + `check_disk`: the banner, and a save refuses until Reload / Keep Mine — Discard (D) removes them, Later (L / Esc) keeps them on disk to be offered at the next start (a backup this session writes for the same file replaces it). Read-only buffers and files that fail to open keep their backup. No untitled buffers exist, so every backup has a path. Panic backups (`panic.rs`) are the same files.
- **Back / forward navigation:** recording is one before / after compare per event (`nav_begin` / `nav_end`), not calls at each jump site: the place before is recorded when the active group or file changed, when a jump command set `nav.jump` (`nav_jump`: `open_file` — so quick open, results, F8, go to definition —, `go_to_line`, Cmd+Home / End) and the primary moved without an edit, or for input when it moved `navigation::MIN_LINES`+ lines without an edit. A new jump kind that doesn't go through `open_file` calls `nav_jump()`. Go Back / Go Forward (`nav.back` / `nav.forward`) set `nav.navigating` so they record nothing; a place whose tab was closed reopens through `open_file` (`Goto::Place`), `opened` asks `nav_opened` first: a file gone from disk (loaded with no `disk()` stamp, or failed) is skipped and navigation goes on. Entries map through edits in `follow_edits` and `apply_reload`; positions are clamped when used. A session restore records nothing.
- **Recent workspaces:** `start` records the root in `<state dir>/recent.toml` off-thread (`record_recent`; nothing without `App::state_dir`). "Open Recent Workspace" (`workspace.openRecent`, Ctrl+R on both platforms — literal Ctrl on macOS as VS Code, global, so a focused task tab doesn't get it) reads the list off-thread (`recent::list`: missing folders pruned, the current root left out) and then opens `Picker::Recent` (none → a message). Picking one goes through `recent::how_to_open`: jed never switches its own workspace; outside kitty (all of 13c) it's a status-bar message with the path and `jed <path>`.
- **Logging:** `tracing` only — never print while the UI is up. Targets are module paths (`jed::app`, `jed::buffer`, …) except explicit `target: "input"` (key/mouse/paste at trace), `target: "panic"`, `"lsp::wire"` (every JSON-RPC message in / out at trace, with `server`) and `"lsp::stderr"` (server stderr lines at debug; a crash logs the last 20 at warn). Each `execute` runs in a `command` span with the command name. User-visible messages go through `App::notify(Level, text)`, which also logs. `JED_LOG=input=trace` / `--log-level` set the filter.
- **Tool logs:** each language server's task pushes its stderr lines (Info), lifecycle (`Starting: <command line> (in <root>)`, `Started, pid N`, `Initialized: <serverInfo> <version>, positions in UTF-8`, `Can't start: …` / `Failed to initialize: …` / `Crashed: <why>` (Error), `Stopped (<status>)`) and `window/logMessage` / `window/showMessage` (`Message: …`; level by type) to `app.logs` under `Tool::Server(config.name)`, off the UI thread; while `Server::set_trace(true)` (off by default; "Tools: Toggle Protocol Trace") every JSON-RPC message too (`→` / `←`, Trace). jed's own events reach "jed" through `logs::layer` (only what passes the log filter; not written again under `logs/tools`). Log tabs (`app/tools.rs`): `sync_logs` each loop turn takes each log buffer's new lines as one change set; the store's waker (`AppEvent::LogsChanged`) wakes the loop when lines arrive, rearmed by `Timer::Logs` at most every `LOG_FRAME` (20 ms) and only while a log tab exists. Task runs aren't tools with logs (their output is the PTY; the Tools view's task rows focus their panel tab). The Tools view keeps current without polling: server state / progress and task status come as app events (each redraws); new log lines wake the loop while it's shown too, and redraw only when an error count changed. `report_log_errors` (each loop turn) shows the first disk write error once; quitting flushes (`flush_tool_logs`, ≤ 500 ms) after the servers stop.
- **Scroll bars:** anything scrolled gets the one-column bar by implementing `scrollbar::Scrollable` (rows, height, top as a row index, set top — O(1) / per group, never per row: lists keeping their top by key convert by binary search), drawing it in its area's last column (`ui::scrollbar::take_column`, always reserved, + `render` with `look(app, target)`) and reporting the `ScrollBarHit` under a `ScrollTarget`, plus an arm in `App::with_scrollable`; clicks, drags, hover and the wheel then work as for the others.
- **Many selections:** Cmd+Shift+L can make 60k+ selections. Anything per edit or per frame must stay O(selections · log n): map positions with `ChangeSet::mapper()` (not `map` in a loop, and in order), no rope lookup or allocation per selection (build changes with `ChangeSet::push`, borrow the text), draw only `Selections::overlapping` the viewport, and don't scan the selection list per cell. `ChangeSet::apply` rebuilds the rope in one pass from 256 changes up. A rope line lookup costs a few hundred ns: commands that need each selection's line (add cursor, box select, line commands) visit them through `pos::LineWalker` in order instead of `line_of`/`display_col` per selection.
- Slow-work warnings: frames > 16 ms (`SLOW_FRAME`), saves and parses > 500 ms (`SLOW_TASK`).

## Adding a command end to end

1. `command.rs`: add a variant to `Command` (or `ExplorerCommand` / `PaletteCommand`), its name in `Command::name()` (`area.camelCase`), its `title()` (both matches are exhaustive) and add it to `Command::all()` (not checked by the compiler; the palette and `keybindings.toml` only know commands listed there).
2. Behaviour: text/cursor work goes in `edit.rs` — add an arm in `edit::run`, and to `edit::is_edit` if it changes text; build changes per selection with `replace_each`/`replace_each_landing`; seal undo if it's not an edit. App-level work gets an arm in `App::execute` (`app/mod.rs`), with helpers in the right `app/` submodule.
3. Binding: add to the `editor`, `explorer`, `palette`, `find`, `replace`, `search` or `global` list in `keymap::defaults`, for both platforms (`cmd`, `word`, `if mac { … }`). Don't bind plain characters in the editor, find, replace or search contexts (they'd stop typing).
4. If it uses Cmd on macOS: add a row to `docs/terminals/README.md` and the key to every snippet.
5. Tests: a unit test next to the code, plus the end-to-end case in the milestone's test file through `press`.
6. PLAN.md's Milestones entry (✅, "Deferred", hand checks) is updated in the milestone's own commit.

## Commits

Look at `git log`. Milestone work: subject `<Milestone name> (<task id>): <short summary>` (one task, e.g. `Tools view and logs (tools-a): …`; the numbered milestones used `Milestone N (Na): …`), blank line, `- ` bullets of user-visible behaviour and notable internals (wrapped ~75 cols). Smaller changes: short imperative subject (`Mark milestone 4 done in the plan`, `Fix crash opening a file inside its workspace; add .workspace`) with a prose body explaining the why when non-obvious. Plan-only edits go in their own commit. End with the `Co-Authored-By:` trailer.

## Keeping these files current

When a change adds a module, a convention, a test helper or a new way of doing background work, update this file (and the nested `CLAUDE.md` for that directory) in the same change. Keep them short and only state what the code actually does.
