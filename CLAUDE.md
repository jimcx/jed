# red

A VS Code-style terminal text editor in Rust (ratatui + crossterm + tokio, ropey 2 beta for text).
**PLAN.md is the source of truth for design and scope** — read the section you need instead of
guessing: Features (one subsection per area), [Keybindings](PLAN.md#keybindings-vs-code-defaults),
[Architecture](PLAN.md#architecture), [Text positions](PLAN.md#text-positions),
[Async and blocking work](PLAN.md#async-and-blocking-work), [Logging](PLAN.md#logging),
[Milestones](PLAN.md#milestones) (each has "Needs", "Deferred" and a "Done when" to test against).
Milestones 1–10 are done; work happens one milestone at a time, split into tasks (8a, 8b, …), one commit per task.

## Toolchain and checks

`rust-toolchain.toml` pins 1.99. On Linux plain `cargo` works (the rustup proxy is on PATH); on macOS cargo isn't
on PATH, so prefix every command with `export PATH="$HOME/.rustup/toolchains/1.99-aarch64-apple-darwin/bin:$PATH"`.

```sh
cargo fmt --check                            # rustfmt.toml: max_width = 120
cargo clippy --all-targets -- -D warnings
cargo test                                   # ~150 tests, ~5 s (search's random reference test is most of it)
cargo test --release milestone -- --nocapture --test-threads=1   # M1 and M6 (1 MB Cmd+Shift+L + typing; line/cursor commands at 61k selections; find + replace all) budgets: release only (M6 has coarse debug bounds); serial, since parallel tests nearly double the timings on a slow machine
cargo test --release search -- --nocapture      # so are the 1 MB find-all and 10 MB workspace-search budgets
```

All three must pass before a commit. Cap test runs with `scripts/timeout 300 cargo test …` (macOS has no `timeout`; this kills the whole process group, so cargo's test binary can't outlive it). Edition 2024 (let-chains are used freely).

## Module map (`src/`)

- `main.rs` — arg parsing (`red [<folder> | <file>[:line[:col]]]`, `--log-level`), loads the first file, `.workspace`, `settings.toml` and `keybindings.toml` *before* raw mode (their load errors go to `App::set_keymap` after the UI starts), builds the tokio runtime, runs `App`
- `app/` — `App`: owns all state, the event loop, `execute(Command)`, prompts, mouse, background-result handling (see `src/app/CLAUDE.md`)
- `command.rs` — `Command` / `Motion` / `ExplorerCommand` / `PaletteCommand` / `FindCommand` enums; `Command::all()` (what the palette lists and keybindings can name), `name()` (stable dotted names like `edit.copy`), `from_name`, `title()` (palette text, `Category: Action`)
- `config/keymap.rs` — `Keymap` (data: `(KeyCombo, Option<Context>) -> Command`), `Context` (`Editor`, `Explorer`, `Palette`, `Find`, `Replace`, `Search`, `SearchResults`, `Problems`, `Locations`, `Suggest` (the completion list while shown), `Diff` (the editor with a diff tab active: F7 / Shift+F7), `Scm` (the Source Control view's list); `lookup` tries the context, then its parent — `Replace` → `Find`, `SearchResults` → `Search`, `Suggest` / `Diff` → `Editor` — then global), `Platform`, `default_for(platform)`, `load(path, platform)` (defaults + `keybindings.toml`), `binding_for(cmd)` (the key the palette shows); `KeyCombo::parse` / `spec` (config spelling) / `label` (`Cmd+Shift+P`); `from_event` turns a shifted US digit with Cmd/Ctrl/Alt (`Cmd+!`, how kitty-protocol terminals report Cmd+Shift+1) into digit + Shift, and Ctrl+@ (a legacy terminal's Ctrl+Space, NUL) into Ctrl+Space
- `config/settings.rs` — `SettingsOverrides` (the `[settings]` table shared by the user's `settings.toml` and `.workspace`, every key an `Option`; the module doc has the table of keys, types and defaults), `apply`, `layer(user, workspace)` (defaults ← `settings.toml` ← `.workspace`, per key: the one place precedence lives), `load(path)` / `parse` → `UserSettings { overrides, errors }` (missing file: silent; TOML syntax error: defaults + one error with its line; unknown key, misplaced key/table or wrong type: reported and skipped, the other keys apply — VS Code's leniency, unlike `.workspace`, which rejects the whole file), `TEMPLATE` (every key commented out at its default) and `create_if_missing` (for "Preferences: Open User Settings"; `create_new`, so it never overwrites a file)
- `edit.rs` — movement and editing at every selection (`edit::run`, `insert_char(buf, view, c, settings)`, `paste`, `copy_text`, `cut`), `Settings` (tab width, spaces, `syntax_max_bytes`, `auto_close_pairs`, `auto_indent`, `match_brackets`, `quick_suggestions`); `edit::run` (and the status bar) use `Settings::for_language` (the buffer language's `LanguageConfig::insert_spaces`: Makefiles always indent with tabs, VS Code's `[makefile]` default). Enter is `indent::newline`. `insert_char` tries `indent::type_char` (with `auto_indent`), then `pairs::type_char` (only for a char in the language's pairs; any other char takes the plain path untouched); Backspace tries `pairs::delete_pair`. `replace_each_landing` (`Land::{AfterText, Inside(n), Keep(p)}`) also carries the view's `AutoClosed` through its edit (`follow` before, `edited` after). `paste(buf, view, text, whole_line, pieces)` spreads one part per cursor (VS Code's `multiCursorPaste: spread`): red's own copied pieces if there are as many, else the text's lines (one final line break ignored); never for a whole-line copy or one cursor. `copy_text` returns a `clipboard::Copied`; only one empty cursor's copy is whole-line (VS Code)
- `completion.rs` — completion's model (no drawing; `app/completion.rs` drives it, `ui/completion.rs` draws it): `parse` (`CompletionItem[]` / `CompletionList` with `itemDefaults`; an item inserts its `textEdit` — an `InsertReplaceEdit`'s `insert` range — else `insertText` / `label` over the word before the cursor), `strip_snippet` (placeholders → their defaults; selects the first tab stop, else `$0`), `Filter` (nucleo fuzzy, case-insensitive, first char at a word start), `Anchor` (where a request was asked: rope snapshot + primary cursor, the word's `start` and the cursor `at` followed through edits by `Buffer::sets_applied`, `in_word`, `now(p)` for snapshot positions), `place` (each item's range → `lead` / `after` bytes), `Popup` (items, `shown` sorted by score then `sortText`, `refilter`, selection / scroll), `Completion` (`popup`, the pending `ask`, the `quick` timer), `insert(buf, view, Insertion)` (the item at every selection — the same char counts before / after each as at the primary, only word chars when the primary's are — plus `additionalTextEdits`, one `ChangeSet`, `EditKind::Other`, O(selections) via `Peek`; multi-line text gets each line's indentation and the buffer's EOL)
- `column.rs` — add cursor above / below (`add_cursor`, keeps the goal column), Shift+Alt+I (`cursors_at_line_ends`), column (box) select: `select(from, to)` per line between two display columns (nearest grapheme boundary, short lines skipped, VS Code's `ColumnSelection`), `step` for Cmd+Shift+Alt+arrows, `current` (the view's `ColumnBox` while its selections are unchanged, else the primary's anchor/head). Uses `pos::LineWalker`, not per-cursor lookups
- `comment.rs` — comment line (Cmd+/, `toggle`): VS Code's `LineCommentCommand` per selection (a line shared by two belongs to the first; one ending at a later line's start doesn't take it): uncomment if every non-blank line starts with the token (+ one space), else comment the non-blank lines (all, if all are blank) at the selection's smallest indentation (never inside a tab); one `ChangeSet` via `LineWalker`, one undo step (`EditKind::Other`); selections keep text inserted at their edges, a cursor at the insertion point lands after the token. No token (plain text): nothing
- `indent.rs` — auto-indent at every cursor (VS Code's `autoIndent: full`, approximated; the module doc lists the rules and differences): `newline` (Enter: the line's indentation up to the cursor; + a level after an opening bracket token, a Python block keyword line ending in `:` or a YAML line ending in `:` / `-`; C/C++ and Rust also VS Code's (C/C++) `indentationRules` (+ a level after a bracket left unclosed anywhere before the cursor, − one before a closing bracket after it; the tree is walked only when the text has a quote or `/*`); `IndentOutdent` between a pair (closer on its own line, cursor on the indented middle line, `Land::Inside`); − a level after Python `return`/`pass`/…; trailing comments skipped (tree, else the line comment token); a whitespace-only line's rest dropped; all new texts in one `String`, one `EditKind::Insert` edit) and `type_char` (a closing bracket first on its line re-indents the line to its opener's line, via `brackets::Openers`, not inside a multi-line string / comment; Python `else:` / `elif …:` / `except …:` / `finally:` to the nearest less indented `if` / `try` / … line). Enter's lines via `LineWalker`, tree checks via forward `syntax::Tokens` walks; a closer reads only bytes (`Peek::blank_line_start` / `line_indent`), not lines, so 65k cursors stay well within the 80 ms line-command budget (Enter ~50 ms, `}` ~20 ms). `Settings::auto_indent = false`: Enter is a plain line break, no outdent
- `brackets.rs` — bracket matching over the language's bracket pairs (`LanguageConfig::brackets`): `match_at(rope, syntax, pos)` (the bracket after the cursor, else before it, and its partner; with a current token tree (`Syntax::token_tree`: not Markdown's) only bracket tokens count — not in strings / comments — and the partner is found among the token's siblings (missing = unmatched); without one, a text scan of at most `WINDOW` (16 KB) each way), `Openers` (innermost unclosed opener before increasing positions: one pass over tokens or text with a stack, restarting `WINDOW` back after a gap) and `Matches` (the view's highlight cache: recomputed only when revision, language, tree availability or the on-screen cursor heads (first `MAX_CURSORS`, 64) change)
- `pairs.rs` — auto-close at every cursor, VS Code's defaults, each rule all-or-nothing over the selections (as VS Code): type-over (only closers red inserted: `AutoClosed` on the `View`, one action per auto-closing key, live while every cursor is strictly inside one of its pairs (after the open char, before the closer's end) and they stay on one line (a typed line break drops them, as VS Code); dropped by any edit not made through `replace_each_landing` of that view, checked by buffer revision), auto-close (next char in `autoCloseBefore` or a closing bracket; `'` / `"` not after a word char unless a Python string prefix letter is before every cursor (then `notIn` strings and comments), not in a string / comment per pair when the tree is current: `Syntax::scope_before`; seals undo before, `EditKind::Insert`), wrap non-blank selections (`EditKind::Other`, inner text stays selected), Backspace in an auto-inserted empty pair deletes both. `pos::Peek` reads the chars next to each cursor. Off with `Settings::auto_close_pairs = false`. `pairs::tests::{setup, show}` mark text with `|` (cursor) and `«…»` (selection) — the comment tests use them too
- `lines.rs` — move lines (`move_lines`, Alt+Up/Down) and copy lines (`copy_lines`, Shift+Alt+Up/Down) at every selection: selections are grouped into line blocks (sharing a line; for moves also neighbouring lines); a non-empty selection ending at a line start doesn't take that line; one undo step (`EditKind::Other`), none if nothing moves; selections follow the moved / lower copied text
- `buffer/` — `Buffer`/`Buffers`, `ChangeSet`, undo `History`, file load/save, and **all** position types/conversions in `buffer::pos` (see `src/buffer/CLAUDE.md`)
- `selection.rs` — `Selection` (anchor, head, goal column) and `Selections` (sorted, merged, never empty; a primary and a *newest* — the one added last, which Cmd+D searches after; `new` takes the last list entry as newest, `with_newest` names it). The list is an `Arc` (copy on write): clones are cheap and equal clones compare by pointer; normalizing skips the sort when the list is already sorted (after an edit or mapping) and merges in place. Merging is VS Code's: overlapping, or touching when one is an empty cursor; two non-empty selections that only touch stay apart. `overlapping(from, to)` (binary search, for drawing) and `contains_range`
- `view.rs` — `View`: selections + scroll for one tab; `map_through` follows edits made via another view (and clears its Cmd+U history first, so the list is mapped in place; positions go start then end, in order, for the mapper's forward stepping); `reveal_range` (centre a range if off screen, set by Cmd+D); `reveal_pos` (scroll just enough to show a position, e.g. the newest added cursor); `column` (the last `column::ColumnBox`); `auto_closed` (`pairs::AutoClosed`: the closers typing can step over); `brackets` (`brackets::Matches`, the highlighted brackets); `CursorHistory` (Cmd+U: up to 50 earlier selection lists + scroll, cleared by any text change)
- `multicursor.rs` — Cmd+D / Cmd+Alt+D (`next_match`, `Step::{Add, Skip}`) and Cmd+Shift+L (`select_all`) as VS Code's `MultiCursorSession`: a `Session` is word mode (empty single cursor: whole word, case-sensitive) or the primary's text literally with the find widget's case/whole-word (`App::find_options`, default off); searches after the newest selection, wraps, skips already-selected matches. Several selections with different text: Cmd+D first expands empty cursors to words
- `group.rs` — `Tab::{Text(TextTab { buffer, view }), Diff(Box<DiffTab>)}` (`text()`, `diff()`, `buffer()`), `Group` (tabs, active; `active_tab()` / `active_tab_mut()` = the active tab *only when it's a text tab*, `active_diff()` / `active_diff_mut()`, `find(buffer)` and `text_tabs_mut()` text tabs only; `open(buffer, view)` / `open_tab(Tab)` activate the new tab, `open_background` keeps the active one), `Groups` (map + `SplitTree`, always ≥1 group; `split(dir, diff_id)` copies the active tab — a diff tab as `DiffTab::copy` with a new id; `tabs_showing(buffer)`, `diff_tabs_mut()`)
- `layout.rs` — screen `Regions` (`compute(area, side_visible, side_width, panel_height)`: the bottom panel under the editor groups only, the side panel keeping its height; clamped so the editor keeps `MIN_EDITOR_HEIGHT` and the panel gets `MIN_PANEL_HEIGHT` when that fits), `PanelTab` (`Problems`, `Locations` (its tab only while there's a list); M12 adds task runs), `SplitTree` of editor groups, `HitMap`/`Hit` for mouse hit-testing (`PanelBorder` (resize drag), `PanelTab`, `Panel` + `HitMap::panel_list` (the shown tab's list: `ListHit`, list rect + each row's `RowKey`), `Hover` (`HitMap::hover`, the popup's rect: checked first, nothing under it gets the event), `QuickDiff` (`HitMap::quick_diff`: the gutter's peek, `QuickDiffHit { rect, stage, close }`, checked after the hover), `StatusProblems` (the status bar's counts, `HitMap::status_problems`), `HitMap::scm` (the Source Control view: `ScmHit { list, rows: Vec<scm::RowKey>, buttons: (rect, key, unstage) }`; its clicks arrive as `Hit::SidePanel`), `Banner(group, Option<BannerAction>)` (the changed-on-disk banner over a group's editor, `GroupHit::banner`: `BannerHit { row, actions }`), `GroupHit::diff` (a diff tab: `DiffHit { rows, buttons: (rect, hunk) }`; its clicks arrive as `Hit::Editor(group)`))
- `ui/` — ratatui drawing, `ui::render(f, &mut App)`; colours only via `Theme` (see `src/ui/CLAUDE.md`)
- `theme.rs` — `Theme::dark_plus(truecolor)`: named keys (`"editor.selection"`, `"statusBar.error"`, …) → `Style`, 256-colour fallback; syntax token keys are bare capture names (`keyword`, `keyword.control`, `string`, `comment`, `type.builtin`, … = `syntax::KEYS`) with Dark+'s token colours, incl. `markup.{heading,list,quote,raw,link}` (Markdown; heading bold, link underlined) and `tag` / `tag.attribute` / `punctuation.tag` (XML; YAML keys are `tag`); `editor.bracketMatch` (matched brackets' background); `editorError.foreground` / `editorWarning.foreground` / `editorInfo.foreground` / `editorHint.foreground` (diagnostics' squiggles: `Modifier::UNDERLINED` + `underline_color`, no fg / bg — ratatui has no undercurl; terminals without SGR 58 underline in the text colour); the bottom panel's `panel`, `panel.border`, `panel.dim`, `panelTitle.active` / `panelTitle.inactive`, `panel.badge`, `panel.fileName` and `problems{Error,Warning,Info,Hint}Icon.foreground`; the changed-on-disk banner's `banner`, `banner.icon`, `banner.action`; the hover popup's `editorHoverWidget.background` / `.foreground` / `.border` / `.heading` (bold) and `textPreformat.foreground` (code in it); the gutter's markers `editorGutter.{added,modified,deleted}Background` (foregrounds: the glyph's colour) and its peek's `diffEditor.removedLineBackground` / `diffEditor.insertedLineBackground`, `quickDiff.title`, `quickDiff.action`; the Source Control view's `scm.count` (section badges), `scm.action` (its `+` / `−` buttons), `scm.deleted` (struck through)
- `diagnostics.rs` — diagnostics as the editor shows them (no LSP, no drawing): `Severity` (`Error` < `Warning` < `Info` < `Hint`; `from_lsp` (missing = error), `theme_key`, `icon` `⊗ ⚠ ⓘ …`, `icon_key` (the Problems list's icon colours)), `Diagnostic` (severity, message, source, code; shared as `Arc` between the LSP store and buffers), `Mark { start, end, server, diag }` and `Marks` (on every `Buffer` as `buf.diagnostics`: sorted by (start, end) with a prefix max of ends; `replace(server, marks)` (one server's set), `clear(server)`, `map(&ChangeSet)` (called by `Buffer::apply`: start `Assoc::After`, end `Before`, so text typed at a range's edges stays outside and a deleted range becomes empty), `overlapping(from, to)` (binary search both ends: thousands of marks, few on screen), `for_line(start, end, head)` (the status bar's: most severe touching the line, the one under the cursor first)), `runs(marks, extent)` (flattened, non-overlapping, most severe wins: what the editor draws)
- `explorer.rs` — explorer tree model (no drawing), `list_dir`, `walk_files` (quick open) and workspace search over one shared `ignore` walker (`walker(dir, excludes)`: `.gitignore`, excludes, never `HIDDEN_DIRS` `.git/` or `.red/`), `excludes`, blocking `ops::{new_file,new_folder,rename,delete}`
- `palette.rs` — palette model (no drawing): `Palette` (a `TextField` + `Row`s; `Picker::QuickOpen` switches `Mode` by first char: `>` commands, `:` go to line, else files; `Picker::LogLevel`; `Picker::History { restore }`: a file's history entries, `Action::History(Snapshot)`), `command_rows` / `log_level_rows` / `history_rows` (entries in order, "3 min ago · 12 KB" + the UTC time, filtered on either) (sync `nucleo` `Pattern`), `parse_line`, `file_query` (drops a `:line[:col]`, also half-typed), `FileMatcher` (a `nucleo::Nucleo` fed by the walk, matching on its own threads)
- `field.rs` — `TextField`: one-line input (text + byte cursor) used by `Input` prompts, the palette and the find widget; `key()` returns `Outcome::{Ignored, Moved, Edited}`; `select_all()` (`all_selected`: typing/paste replaces the text, Backspace/Delete clear it)
- `find.rs` — `FindWidget`, the find / replace widget's model (no drawing): `visible`, `query` / `replace` `TextField`s, `replace_visible`, `field` (`Field::{Find, Replace}`), and a cache of `find_all` keyed on (buffer, `Buffer::revision()`, query, options) — `refresh` re-searches only when one changes; `matches()`, `matches_in(range)` (visible slice by binary search), `index_of`, `count_label` ("3 of 41" / "? of 41" / "No results"), `error()` (`SearchError`), `matcher()`, `replacement_for`
- `search.rs` — the one matcher for find, Cmd+D and workspace search: `Matcher::new(pattern, Options { regex, case_sensitive, whole_word })` (`SearchError` is a one-line message for an invalid regex; an empty pattern matches nothing), then `find_next(rope, from, wrap)` / `find_prev(rope, before, wrap)` / `find_all` / `find_in(rope, range)` → `Match { start, end }` in `ByteIdx`; `replace_in(rope, range, &Replacement, f)` gives each match with its replacement (`Replacement::new(template, regex)`: VS Code's `$1`/`$12`/`$&`/`$0`/`$$`, `\n`/`\t`/`\\`; groups via `captures_at` on the match's line; `literal()` when it names no group). Searches line by line over `pos::each_line` (zero-copy per chunk); matches never span lines unless the pattern names a line break (newline, `\n`, `\r`, `\W` — VS Code's rule), which searches a copy of the whole text. Whole word = VS Code's boundary rule with `pos::is_word_char`. Also `impl grep_matcher::Matcher` so `grep-searcher` uses the same matcher on files. `Matcher::new_single_line` never goes multi-line (workspace search: a pattern naming a line break is searched per line, so `\n` matches nothing); `each_in_line(line, f)` gives one line's matches in linear time (`grep_matcher`'s own `find_iter` rescans to the line start per match: quadratic on long lines).
- `workspace_search.rs` — workspace search, no drawing: `matcher(&Query { pattern, options })` (`Err` = invalid regex, nothing runs), `start(Job { root, excludes, matcher, dirty, generation }, send) -> Handle` (cancels on drop / `cancel()`) runs the blocking `run` in `spawn_blocking`: `explorer::walker` in parallel, each file read whole, skipped when `file::looks_binary`, BOM dropped, lossy UTF-8, searched with `grep-searcher` (`search_slice` + a `Sink` using `each_in_line`); a file with a lone CR, and dirty-buffer rope snapshots (`dirty`, relative path → `Rope`, replacing the disk file; one with no file on disk is searched if in scope), go through `Matcher::find_all` instead — same lines and matches either way (the empty line after a final line break isn't searched, as `rg`). Results: `FileMatches { path (relative), lines: Vec<LineMatch { line (0-based), ranges (byte ranges in the line), text (a ≤ `PREVIEW_LEN` piece of a long line), text_start }> }`, sent in `Batch { generation, files, done, truncated }` at most every 50 ms plus a last `done` one (none when cancelled); stops at `MAX_MATCHES` (20,000) with `truncated`. `Results` (files sorted by path, `total`, `done`, `truncated`, `query`) is the app's model; `add(batch)` drops other generations. `#[cfg(test)] reference::{reference, hits}`: an independent slow search (what `rg` reports) and the same `path:line:start-end` list from `Results`, shared by 7a's unit tests and M7's end-to-end ones
- `grouped.rs` — a list grouped by file (the Search view's results, the Problems list): `Group` (`path`, `items`; groups sorted by path, each a row followed by its item rows), `RowKey` (path, row in file: 0 = the file's row), `row_count` / `index_of` / `key_at` / `group` (binary search) / `rows(groups, from, n)` (only the rows asked for), `ListState` (scroll and selection both kept as `RowKey`s, so groups arriving or going above don't move them: `scroll` / `set_scroll` / `scroll_by` / `clamp`, `height` set by drawing; `selected`, `selected_row`, `select`, `select_key`, `move_selection` (false = Up from the top), `reveal_selected` (scrolls the least), `reset`). Also the Locations list's; reuse it for any new file-grouped list
- `search_view.rs` — `SearchView`, the Search view's model (no drawing): `query` (`TextField`), its own `options` (case / regex; whole word stays off in v1; separate from the find widget's), `error` (invalid regex), the debounce (`edited(now)` → `DEBOUNCE` 150 ms later, `deadline()`, `take_due(now)`, `started()`), the list's scroll and selection (`list`, a `grouped::ListState` over `results.files`; `FileMatches` is a `grouped::Group`) behind its own `scroll` / `set_scroll` / `scroll_by`, `selected_row`, `select`, `select_key`, `move_selection` (false = Up from the top: back to the query), all scrolling the least to show the selection; cleared by `started`; plus which match on the selected line F4 is on, `list_focused` (the list, not the query, has the keys), `step(results, forward)` (F4 / Shift+F4: next / previous match — several on a line one by one — wrapping, selected) and `target` (what Enter opens; a file row's first match) → `Target { path, line, range }`; `rows(results, from, n)` (`Shown { file, offset }` → `row()` = `Row::{File, Line}`, `key()`; only visible rows), `preview(line, width)` (leading whitespace dropped, cut with `cut` = "…" so the first match fits) and `cells`
- `clipboard.rs` — `Clipboard`: arboard (lazy) / OSC 52 (SSH or arboard failure, tmux-wrapped) / `memory()` in tests; `write(Copied { text, whole_line, pieces })` remembers the last copy, `copied(text)` returns it while a paste's text still matches (newlines normalized)
- `workspace/` — `Workspace` (root, `.workspace` config, `user_settings` (the user's `settings.toml`, set once via `with_user_settings`; reloads of `.workspace` keep it), `settings()` = `config::settings::layer(user, .workspace)`), `config.rs` (`WorkspaceConfig` TOML: `[settings]` (`SettingsOverrides`, re-exported from `config::settings`), `[files]` `exclude` / `associations`, `[lsp.*]`, `[tasks.*]`, `[history]` (`HistoryConfig`: `enabled` true, `max_entries` 50, `max_file_size` 5 MB)), `trust.rs` (`TrustStore`, `Trust`)
- `syntax/` — `Language` (`PlainText`, `C`, `Cpp`, `Python`, `Rust`, `Markdown`, `Yaml`, `Json`, `Jsonc`, `Xml`, `Toml`, `ShellScript`, `CMake`, `Makefile`, `Dockerfile`; `id()` = VS Code / LSP language id, `name()` = status bar text, `grammar()` (one tree-sitter grammar crate each), `highlight_queries()` (the grammar's `highlights.scm` + red's `syntax/queries/*.scm`), `config()`: the `LanguageConfig` for comment line, pairs, brackets), `detect` (`.workspace` associations, then name / extension, then shebang) and `Syntax` (on every `Buffer`: language + tree-sitter tree, kept current from each applied `ChangeSet`; first parse and big re-parses off-thread; `spans(rope, lines)`: cached highlight spans for any line range, the last ones kept while a re-parse runs; `scope_before` / `scope_of`: string / comment / code across the grammars' node kinds; `token_tree()`: the tree when its leaves are tokens, not Markdown's). ## Data flow

1. `App::run` (`app/mod.rs`): `tokio::select!` over crossterm `EventStream`, the `AppEvent` channel (`rx`), and one timer (`App::next_timer`: the earliest of the fs-event debounce, the Search view's debounce, the mouse's hover rest, the quick-suggestion delay, the gutter markers' delay and the diff tabs' delay, run by `on_timer`); then drains queued input so a burst becomes one frame; then `sync_syntax` (once per turn: every buffer's tree re-parsed incrementally, or a background parse started), `sync_quick_diff` (once per turn: starts the gutter markers' computations due, O(buffers) when none is), `sync_diffs` (the same for diff tabs' loads) and `sync_servers` (starts / stops language servers when `servers_dirty`, then `lsp::Manager::sync_documents`: `didOpen` / `didClose` to match the buffers and one `didChange` per document with the turn's edits), and redraws only when `needs_redraw`.
2. `handle_event`: any key first closes the hover popup (`close_hover`; Esc in the editor then does nothing else) and the gutter's peek (except Enter — stage — and Esc in the editor, which it takes); an open `prompt` gets every key; else `keymap.lookup(&key, self.context())` → `Command` (`context()` is `Palette` while the palette is open, `Diff` while the editor has the keys and its active tab is a diff, `Find`/`Replace` while `Focus::Find`, `Problems` / `Locations` (by `ui.panel_tab`) while `Focus::Panel`, `Scm` while the side panel has the keys and shows Source Control: unbound keys and paste do nothing there); else an open palette's `TextField` gets the key; else the find widget's focused input (`find_key`, incremental search); else an unbound plain/Shift char in the editor is typed via `edit::insert_char` (a commit character of the selected completion inserts it first; then `completion_typed`: trigger characters ask, word chars start the quick-suggestion timer). The context is `Suggest` while the completion list is shown. `Event::Paste` (bracketed paste) → the prompt input, the palette, the find input, or `App::paste`. After `sync_views`, `refresh_find` keeps the open widget's match cache current (also after background events), `check_requests` cancels language server requests whose place moved on and `check_hover` closes a popup whose buffer was edited or view scrolled (`check_peek` likewise the peek). Mouse events go to `hover_mouse` first (the popup takes events over it; moves start the hover rest timer), then `peek_mouse`.
3. `execute(cmd)`: any command except `Palette(_)` / `ShowCommands` / `QuickOpen` / `GoToLine` first closes an open palette. App-level commands (save, tabs, splits, focus, explorer, copy/cut/paste, find) are handled in `App` (Esc's `CancelSelection` in the editor closes an open find widget first); on a diff tab `diff_command` takes the rest (movement keys move its cursor, next / previous change; anything else does nothing); everything else falls to `edit::run(cmd, buf, view, &settings)` on the active tab, after a read-only check if `edit::is_edit(cmd)`.
4. `edit` builds a `ChangeSet` over all selections and calls `Buffer::edit(changes, before, after, kind)` — one undo transaction.
5. `sync_views` (after every event) drains `Buffer::take_applied()` and maps every *other* view on that buffer through the changes, then `track_selections` records the active view's selection change for Cmd+U and ends the Cmd+D session if something else changed the selections or the editor lost focus.
6. Background results come back as `AppEvent` variants (`SaveDone`, `HistoryDone` (a file history snapshot or move, `app/history.rs`), `HistoryListed` / `HistoryRestore` (File History's picker entries, an entry diffed for a restore), `Opened`, `Listed`, `FsChanged`, `ConfigLoaded`, `FileOpDone`, `FilesMatched`, `FilesWalked`, `LogFileFound`, `SearchResults`, `Parsed`, `LocationsRead` (the Locations list's previews), `GitRefreshed` (a git status refresh, `app/git.rs`), `DiskChecked` (an open file read after file system events naming it, `app/disk.rs`), `QuickDiff` (a buffer's gutter markers), `Staged` (a change staged / unstaged, `app/quick_diff.rs`), `DiffLoaded` (a diff tab's texts read and diffed), `DiffStaged` (a stage from a diff tab or of a whole file, `app/diff_view.rs`), `Lsp` (every language server task's `lsp::Event`, through the `Sink` closure `start` gives `lsp::Manager`)) → `handle_app_event`. On quit `run` awaits `shutdown_servers` (bounded: `lsp::SHUTDOWN_TIMEOUT` + 1 s) before returning.
7. `ui::render(f, &mut app)` draws and writes back render-time state: `view.height/width`, scroll for `reveal_cursor`, `explorer.height`, the lists' heights (`search_view.list`, `problems.list`), and `app.hits` (used by the *next* mouse event).

## Invariants and conventions

- **Positions:** `ByteIdx` (UTF-8 byte offset, char boundary; cursors on grapheme boundaries) is the canonical unit; `DisplayCol` for screen columns. Line/column/grapheme/word conversions live only in `buffer::pos` (`line_of`, `line_start`, `line_end`, `display_col`, `byte_at_col`, `next_grapheme`, `word_left`, …). Other modules hold `&Rope` but only call `len()`, `slice(..)`, `to_string()`, `clone()`, `floor_char_boundary()` on it. No raw `usize` byte offsets across modules (line indices are plain 0-based `usize`).
- **Text only changes through `Buffer::edit` / `undo` / `redo`** (the sole `rope.insert/remove` is in `ChangeSet::apply`, called only from `Buffer::apply`, which also feeds each change set to `Syntax::edit` and, while a language server has the document open, records it with the rope from before it for `take_tracked`). Bypassing it breaks undo, other views' cursors, the parse tree and the servers' copies.
- **Parse trees:** `buf.syntax.tree()` is `Some` only while the tree matches the text exactly (never a stale one); between an edit and the next `sync_syntax`, and while a background parse runs, it is `None`. Drawing never reads the tree: it asks `buf.syntax.spans(rope, lines)`, which keeps the last colours (mapped through the edits) until the new tree arrives. tree-sitter `Point`s come from `pos::ts_point` (rows count LF only, as tree-sitter does).
- **Selection list everywhere:** every command works on `view.selections` (a `Selections`, never a single cursor). Build new lists with `Selections::new`/`single`/`transform` so they stay sorted and merged.
- **Undo grouping:** `EditKind::Insert`/`Delete` join consecutive same-kind edits (<1 s, selections continuous); `EditKind::Other` (paste, cut, comment line, wrapping a selection) is always its own step; an auto-close seals before itself, so it starts a step that later typing joins (VS Code). Non-edit actions (moves, clicks, tab/group switches, select-all) call `buf.seal_undo()`.
- **Files changed on disk:** every `Buffer` keeps the `Stamp` (length + SHA-256 of the bytes) of its file as it last knew it (`disk()`: loaded, saved, reloaded, or accepted by "keep mine"); never compare times. `flush_fs_changes` → `disk_paths_changed` checks each buffer whose file (or a folder above it) changed, off-thread, one check per buffer at a time and none while it saves (`save_epoch`: a check overlapping a save is redone after it). Unchanged = nothing (our own saves); missing → `deleted` (tab "(deleted)", struck through; a save recreates); changed and no edits (`has_edits`) → `Buffer::reload` (one `EditKind::Other` step through `Buffer::edit`, ends clean, undoable; every view's selections via `rename::follow`); changed with edits → `disk_conflict` (the banner: `file.reloadFromDisk` / `file.keepMine`, unbound, in the palette); binary / not UTF-8 → no silent reload, a message and the banner. A save refuses (`SaveError::Conflict`, nothing written) when the file holds neither the known stamp nor what it would write. Files outside the workspace root aren't watched (the save check still guards them).
- **Read-only buffers:** `App::active_writable()` gates edits, cut and paste; copy still works.
- **Tabs:** a tab is a text editor or a diff view (`group::Tab`). Code acting on "the active editor" uses `Group::active_tab()` / `App::active_mut()` / `active_buffer()`, which are `None` on a diff tab — so editor commands, find, completion, hover, LSP requests and the gutter do nothing there without checks of their own. What a diff tab should still do goes through `App::active_file_buffer()` (a text tab's buffer, or the open buffer of a diff tab's file: Save, Reload, Keep Mine, Compare with Disk) or the diff's own arms in `execute` (`diff_command`, `diff_stage`). A new tab kind adds a `Tab` variant, its drawing in `ui::mod` and `ui::tabs`, its `split` copy and its context.
- **Keymaps are data:** commands never look at keys. Default bindings live in `keymap::defaults` (a `Vec<Binding>`; list order decides which key the palette shows), per platform (`cmd` = Super on macOS, Ctrl on Linux; `word` = Alt on macOS, Ctrl on Linux). A context binding wins over a global (`None`) one. `keybindings.toml` (`[[binding]]` with `key`, `command`, optional `context` = `editor`/`explorer`/`palette`/`find`/`replace`/`search`/`searchResults`/`problems`/`locations`/`suggest`/`diff`/`scm`) is loaded once at startup in `main` (`App::set_keymap` reports errors): every command it names loses all its default keys; a user key also overrides whatever was on it in that context. `Command` must stay `Copy + Hash` (no owned payloads).
- **Settings layer per key:** `edit::Settings::default()` ← `~/.config/red/settings.toml` ← `.workspace` `[settings]`, only in `config::settings::layer` (via `Workspace::settings()`, stored in `App::settings`, recomputed on a `.workspace` reload). `settings.toml` is read once at startup (live reload is M14). Adding a setting: a field in `edit::Settings` (+ default), an `Option` field in `SettingsOverrides` and a line in its `apply`, a row in `config/settings.rs`'s doc table and a line in its `TEMPLATE` (`template_lists_every_key_at_its_default` names every field without `..`, so it won't compile until the new one is added there, and then fails if `TEMPLATE` lacks it); it then works from both files.
- **Colours:** no `Color::`/`Modifier::` outside `theme.rs`; widgets call `theme.get("key")` (a missing key logs `missing theme key`). Add new keys to `Theme::dark_plus`.
- **Never block the UI thread:** file reads, saves, listings, file ops, config reloads, workspace search, first parses and every `git2` call go through `tokio::task::spawn_blocking` and report back with an `AppEvent`; language servers are async tokio tasks (process spawn included) reporting via `AppEvent::Lsp`. Blocking functions are documented `/// Blocking: call from spawn_blocking`. `App::new` must not spawn anything (it can run before the runtime is entered); `App::start` does.
- **Language server requests:** `App::send_request(group, buffer, at, method, supported, Request)` (`app/lsp.rs`) sends through `lsp::Manager::request_at` (`send_doc_request` / `Manager::request_doc`: no `position`, for whole-document requests like formatting) and keeps a `Pending` (request kind, group, buffer, revision, position, encoding) in `App::requests` by (server, id); a newer request of the same kind cancels the older (`$/cancelRequest`), `check_requests` after each input event cancels ones whose place moved on (buffer edited; the cursor — the active view of the active group — or, for a mouse hover, the pointer elsewhere), answers are taken only for pending and still current requests (else dropped as stale) and go to their kind's handler (`hover_answer`, `definition_answer`, `completion_answer`, `references_answer`, `rename_answer`, `format_answer`, …); `Failed` / `Exited` drop that server's pending ones. A new request kind adds a `Request` variant and an arm in `App::answer`.
- **Edits from background results** (a rename's `WorkspaceEdit`) go through `Buffer::edit` like any other; the code sets the active view's selections itself when it shows the buffer, then calls `App::follow_edits` (`sync_views` without the Cmd+U / Cmd+D tracking) so every other view follows at once. A file not open is loaded through the `opening` map (`OpenRequest { background, edits }`), never on the UI thread.
- **File history:** `App::save` takes a `history::Job` (`App::history_job`: `[history] enabled` and `history::relative`) into the save's task; `SaveJob::write` returns the bytes written and, after `SaveDone { history: true }` is sent, `history::record` runs in a second `spawn_blocking` → `AppEvent::HistoryDone(Result<(), String>)` (an error: a warning message; the save already succeeded). An explorer rename moves the history in the file op's blocking task after the rename (`history_rename`), also ending with `HistoryDone`; a delete keeps it. Watcher events under `<root>/.red/` are dropped in `fs_changed` before `fs_pending`, so history writes cause no listings, git refreshes or disk checks. "File History: Show" / "Restore" (`fileHistory.show` / `.restore`, unbound): the entries are read off-thread (`AppEvent::HistoryListed`) before the palette opens (`Picker::History { restore }`, rows from `app.file_history.picker`); a restore reads + decodes + diffs the entry off-thread (`AppEvent::HistoryRestore`) and applies it with `apply_changes` (one `EditKind::Other` step, `rename::follow` selections), re-diffed if the buffer changed meanwhile.
- **Logging:** `tracing` only — never print while the UI is up. Targets are module paths (`red::app`, `red::buffer`, …) except explicit `target: "input"` (key/mouse/paste at trace), `target: "panic"`, `"lsp::wire"` (every JSON-RPC message in / out at trace, with `server`) and `"lsp::stderr"` (server stderr lines at debug; a crash logs the last 20 at warn). Each `execute` runs in a `command` span with the command name. User-visible messages go through `App::notify(Level, text)`, which also logs. `RED_LOG=input=trace` / `--log-level` set the filter.
- **Many selections:** Cmd+Shift+L can make 60k+ selections. Anything per edit or per frame must stay O(selections · log n): map positions with `ChangeSet::mapper()` (not `map` in a loop, and in order), no rope lookup or allocation per selection (build changes with `ChangeSet::push`, borrow the text), draw only `Selections::overlapping` the viewport, and don't scan the selection list per cell. `ChangeSet::apply` rebuilds the rope in one pass from 256 changes up. A rope line lookup costs a few hundred ns: commands that need each selection's line (add cursor, box select, line commands) visit them through `pos::LineWalker` in order instead of `line_of`/`display_col` per selection.
- Slow-work warnings: frames > 16 ms (`SLOW_FRAME`), saves and parses > 500 ms (`SLOW_TASK`).

## Adding a command end to end

1. `command.rs`: add a variant to `Command` (or `ExplorerCommand` / `PaletteCommand`), its name in `Command::name()` (`area.camelCase`), its `title()` (both matches are exhaustive) and add it to `Command::all()` (not checked by the compiler; the palette and `keybindings.toml` only know commands listed there).
2. Behaviour: text/cursor work goes in `edit.rs` — add an arm in `edit::run`, and to `edit::is_edit` if it changes text; build changes per selection with `replace_each`/`replace_each_landing`; seal undo if it's not an edit. App-level work gets an arm in `App::execute` (`app/mod.rs`), with helpers in the right `app/` submodule.
3. Binding: add to the `editor`, `explorer`, `palette`, `find`, `replace`, `search` or `global` list in `keymap::defaults`, for both platforms (`cmd`, `word`, `if mac { … }`). Don't bind plain characters in the editor, find, replace or search contexts (they'd stop typing).
4. If it uses Cmd on macOS: add a row to `docs/terminals/README.md` and the key to every snippet.
5. Tests: a unit test next to the code, plus the end-to-end case in the milestone's test file through `press`.
6. PLAN.md's Milestones entry (✅, "Deferred", hand checks) is updated in the milestone's own commit.

## Commits

Look at `git log`. Milestone work: subject `Milestone N: <short summary>` (whole milestone) or `Milestone N (Na): <short summary>` (one task), blank line, `- ` bullets of user-visible behaviour and notable internals (wrapped ~75 cols). Smaller changes: short imperative subject (`Mark milestone 4 done in the plan`, `Fix crash opening a file inside its workspace; add .workspace`) with a prose body explaining the why when non-obvious. Plan-only edits go in their own commit. End with the `Co-Authored-By:` trailer.

## Keeping these files current

When a change adds a module, a convention, a test helper or a new way of doing background work, update this file (and the nested `CLAUDE.md` for that directory) in the same change. Keep them short and only state what the code actually does.
