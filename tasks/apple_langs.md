See [Syntax highlighting](../PLAN.md#syntax-highlighting), [LSP](../PLAN.md#lsp).

  - Languages: `Language::ObjC` (id `objective-c`, name "Objective-C") and `Language::ObjCpp` (id `objective-cpp`, "Objective-C++"), `Language::Swift` (id `swift`, "Swift"); VS Code's language ids. Detection: `.m` → Objective-C, `.mm` → Objective-C++, `.swift` → Swift (case-insensitive like the other extensions), shebang `swift` for scripts; `.workspace` associations work as for any language. `.h` stays C / C++ as today (it is ambiguous): check how detection treats it and, if cheap, pick Objective-C when the header's first lines hold `@interface` / `@import` / `#import` (say what was decided in the task's notes)
  - Grammars: the `tree-sitter-objc` crate and the `tree-sitter-swift` crate (alex-pinkus; check licences, crate versions on `tree-sitter-language`, and the clean-build time and size each `parser.c` adds — Swift's is large). Objective-C++ has no grammar of its own: use the Objective-C one, or the C++ one if it parses `.mm` better (try both on a sample and say which). Check each query's captures map to `highlight::KEYS` / `ALIASES` (the every-capture test), add `queries/objc.scm` / `queries/swift.scm` for Dark+'s colours (`@interface` / `@property` style at-keywords, `self` / `super`, types and protocols, string and `@"..."` literals, attributes `@objc` / `@MainActor`, `///` doc comments, `#if` conditionals); `scope_of` must know their string / comment kinds (`scopes_in_every_language`)
  - Language config (VS Code's `language-configuration.json` for each): Objective-C / ++ as C++ (`//`, `/* */`, brackets `() [] {}`, auto-closing quotes; `@"` closes like `"`); Swift `//` line comments, `/* */` nestable block comments, brackets `() [] {}`, `"` and `"""` strings, `\(` interpolation not auto-closed; indent after `{` and outdent on `}` as for C-family languages
  - Servers: Objective-C and Objective-C++ use the existing built-in `clangd` (`lsp::config` `Builtins` maps `ObjC` / `ObjCpp` as it does `C` / `Cpp`; language ids `objective-c` / `objective-cpp` in `textDocument/didOpen`). Swift gets a new built-in `sourcekit-lsp` (no args, the workspace root; it reads `Package.swift` / `compile_commands.json` / `buildServer.json` under it; `.workspace` `[lsp.swift]` wins only when trusted). Check what it does without a package (single files get no cross-file results: say so in the server docs), its indexing progress (`$/progress`, shown like rust-analyzer's), pull vs push diagnostics, and that format and rename work or are cleanly refused
  - Install: `sourcekit-lsp` ships with the Swift toolchain (on macOS with Xcode / the command line tools, found through `xcrun --find sourcekit-lsp` when it isn't on PATH — resolve it that way as a fallback; on Linux from swift.org / swiftly). It is not installed on the Linux dev box (clangd is): ask before installing anything. A missing binary gives the usual "couldn't start sourcekit-lsp" message with its stderr line
  - Tests: unit tests for detection, config and highlight spans for a snippet each (an `@interface` / `@implementation` with a message send `[obj foo:bar]`, a `@"..."` string; a Swift `struct` / `func` with a `\(x)` interpolation, an attribute, a `///` comment); a fake-server test for the built-in being picked for `.m` (clangd) and `.swift` (sourcekit-lsp); real-server tests (like clangd's and rust-analyzer's) on a tiny temp `.m` file with clangd and on a tiny SwiftPM package with sourcekit-lsp — diagnostics for an error, hover, definition, completion — each skipped with a note when the binary isn't runnable
  - Needs: `syntax::Language` and its queries, `lsp::config` `Builtins`, the real-server test helpers (`REAL_SERVERS`, `children_named`), Tools view rows for missing servers if they exist
  - Done when: `.m`, `.mm` and `.swift` files open coloured with comment toggling and auto-closed pairs; a `.m` file shows clangd diagnostics, hover and go to definition; with `sourcekit-lsp` installed a SwiftPM package's `.swift` files show diagnostics, hover, go to definition across files and completion; the tests above pass
