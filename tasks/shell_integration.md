  - Replaces `Run::watch_foreground` and the `/proc` reads it did (`foreground`, `foreground_group`, `tpgid_from_stat`, `process_name`, macOS's `proc_pidinfo` / `proc_name`): the title now comes from OSC codes the shell and its programs send, so there is no polling and no per-platform proc reads. `session_members` (leftover detection) stays. A shell without the integration keeps its base name, as `shell_title` did at a prompt
  - Capture (`run.rs`, `shell_integration-a`): `TitleCallback` — a `vt100::callbacks::Callbacks` on `Parser<TitleCallback>` (the parser is `Mutex<vt100::Parser<TitleCallback>>`), `set_window_title` (OSC 0/2) stores the shown title and `unhandled_osc` reads the FinalTerm semantic-prompt markers (OSC 133): `133;B` (preexec) → running, title cleared for the `OSC 0 <first word>` the snippet sends next; `133;D;<code>` (precmd) → idle, `error` when `<code>` is present and not `0`; a program's OSC 0/2 title shows in place of the first word until `133;D` resets it. `Event::Foreground { id, name, idle, error }` (name always concrete: the title, else `base` from `spec.name`), `ShellTab` gains `error`, `ui/tabs.rs` draws `●` (running) / `○` (idle) / red `○` (`tab.shellError`, 0xF48771); `sanitized` (control chars dropped) reused for titles. The `/proc` reads and `watch_foreground` are gone; `session_members` (leftover detection) stays. `shell::title(base, number, state)` still takes `(name, idle)` — the red glyph is the same `○` in a different theme key
  - Emit (`shell_integration.rs`, `shell_integration-b`): three embedded snippets (zsh / bash / fish) written to the state dir as `shell-integration.zsh` / `.bash` / `.fish` (`write_snippets`, blocking, from `spawn_blocking`), each opening with the `JED_IPC` guard so sourcing anywhere outside jed is a no-op (`[ -n "$JED_IPC" ] || return`; fish `set -q JED_IPC; or return` — fish's `test -n "$x"` is true for an unset var, so `set -q` is the idiom). preexec sends `\e]133;B` then `\e]0;<first word>`; precmd sends `\e]133;D;$?` (fish `$status`); the bash snippet sets `PROMPT_COMMAND` before the `DEBUG` trap and skips `_jed_precmd` / `PROMPT_COMMAND=*` in preexec so the prompt itself doesn't flash a title
  - The wizard ("Terminal: Install Shell Integration", `terminal.installShellIntegration`, palette, unbound, single-file mode off): `install_shell_integration` (needs a state dir and a snippet shell) writes the snippets off-thread and opens `Prompt::InstallShellIntegration` showing the snippet path, the source line (`source '<snippet>'`, single-quoted) and the init file, with `[C]opy` (clipboard + notify) and `[A]ppend to <init>` (one `O_APPEND` write, newline-first, off-thread, reported via `App::notify`; never runs the shell). Detection: `shell_integration::init_for(home, config_home, state_dir, shell_base)` (pure) — zsh `~/.zshrc`, bash `~/.bashrc`, fish `~/.config/fish/config.fish`, `None` for `sh` / anything without a snippet; `paths::config_home()` added (the `xdg_base` refactor keeps `config_dir()`'s `is_absolute` filter)
  - Also: two `AppEvent`s (`ShellIntegrationWritten` reports only a failed snippet write; `ShellIntegrationInstalled` reports the append), both through `App::notify` with the `~`-shortened path
  - Tests: `shell_integration.rs` unit tests (snippets' guard + OSC content, `init_for` for zsh/bash/fish and `None` for `sh`/`/bin/zsh`/`""`, `write_snippets`, `append_line` including the newline-first case), and `shell_tests.rs` end to end — the wizard's paths + Copy (`shell_install_wizard_shows_the_paths_and_copies_the_line`) and append (`shell_install_wizard_appends_the_line`), a real `bash --norc --noprofile` over a PTY sourcing the snippet (`shell_bash_snippet_titles_a_real_shell`: command title, program `file.rs — VIM ●` override, the red error glyph), and the no-`JED_IPC` no-op (`shell_bash_snippet_does_nothing_without_jed_ipc`)
  - Deferred: none
  - Still to check by hand: the fish snippet on a machine with fish (not installed here; checked against fish's docs), sourcing in the user's real `~/.zshrc` / `~/.bashrc` / `~/.config/fish/config.fish`, and the wizard's real `~/.zshrc` append (the code path is tested against a temp init)
  - Done when: with the source line in the init, a shell at its prompt shows `zsh ○`; `sleep 30` turns the tab to `sleep ●` at once and back; `vim` shows its own title (`file.rs — VIM ●`) until `133;D` resets it; a command that exits non-zero shows the red idle glyph; two shells of one program keep distinct `(2)` titles; without the source line (or without `JED_IPC`) the title stays the base name (the integration does nothing); `/proc` is no longer read for the title
