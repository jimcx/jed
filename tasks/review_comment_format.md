The review comment box (`app.composer`) is plain text, and its only buttons are the ones under it: `[Comment Ctrl+Enter]` (or `[Add to Review]` / `[Start Review]` / `[Save Draft]`), `[Cancel Esc]`, `[Insert Suggestion]`. Writing `**bold**` or a link means typing the Markdown by hand and knowing which forge takes which form (GitHub, GitLab and Gitea all speak a GFM variant, but they differ at the edges, underline above all, which Markdown has no syntax for). This task adds a row of formatting buttons to the box, as the forges' own comment boxes have. A button only edits the box's text: it wraps the selection in (or inserts) the Markdown for its style, in the form the merge request's forge renders. Nothing is rendered in jed (full Markdown rendering in threads stays deferred, as in [mr_review](mr_review.md)).

  - Needs: the composer (`jed/src/app/review_comment.rs` `Composer`, `ComposerKind`, `composer_click`; its text is a scratch `Buffer` + `View` driven through `edit::run`), the box's layout and hit columns (`jed/src/review_blocks.rs` `composer_lines`, `composer_rows`, `composer_byte`, `ComposerButton`, `composer_button_cols`), `review_insert_suggestion` (`jed/src/app/review_suggest.rs`, the model for a button that edits the box's text), the forge kind (`crate::forge::Kind`, the review's `kind` in `jed/src/app/review.rs`), `Context::Composer` (`jed/src/config/keymap.rs`), forge notes in [mr_review](mr_review.md), user docs `docs/forges.md`.
  - **Research first**, recorded in [mr_review](mr_review.md)'s forge differences and in the new module's `//!`: for each forge, which of these it renders in a merge request comment, and in what form — bold, italic, underline, strikethrough, inline code, code block, link, quote, bulleted list, numbered list, task list, heading. Read each forge's own docs (GitHub Flavored Markdown and its HTML allowlist; GitLab Flavored Markdown; Gitea's goldmark extensions and sanitizer policy) and, where they are vague, its comment box's toolbar or sanitizer source. Underline in particular: Markdown has none, so the form is an allowed HTML tag (`<ins>` / `<u>`) where the forge's sanitizer keeps one, and not offered where it keeps neither. Note any form that differs (e.g. `_x_` vs `*x*` for italic, task lists in comments). Forgejo is Gitea's adapter, so note whether it differs.
  - **The model** (a new `jed/src/comment_format.rs`: no app state, draws nothing; its line in [modules.md](../docs/dev/modules.md)):
      - `Style` (`Copy + Hash`, for the command): `Bold`, `Italic`, `Underline`, `Strike`, `Code`, `Link`, `Quote`, `Bullets`, `Numbers`, `Tasks`, `Heading`.
      - `fn styles(kind: forge::Kind) -> &'static [Style]`: what that forge supports, from the research, in toolbar order. `fn markup(kind, style) -> Option<Markup>`: an inline pair (`**`…`**`, `<ins>`…`</ins>`), a line prefix (`> `, `- `, `1. `, `- [ ] `, `### `), or a template (`[`text`](`url`)`, a code fence).
      - `fn apply(text: &str, selections: &Selections, markup) -> (ChangeSet, Selections)`, per selection:
          - inline, with a selection: wraps it and keeps the selection on the same text inside the marks. Already wrapped in exactly those marks (inside or just outside the selection): removes them instead (a toggle, as the forges' toolbars do).
          - inline, empty selection: inserts the pair with the caret between (`**|**`).
          - code: inline backticks on one line; a multi-line selection gets a fence on its own lines around it.
          - line prefix: prefixes every line the selection touches (`1. `, `2. `, … for numbers); all of them already prefixed: removes it.
          - link: `[selected text](url)` with `url` selected, so typing replaces it; with no selection `[text](url)` with `text` selected.
        It builds one `ChangeSet` for all selections (`ChangeSet::push`, positions through `buffer::pos`, a `LineWalker` for line styles) so a many-selection box stays cheap. Unit tests in its `mod tests` for each style × each forge's form, toggling, empty and multi-line selections, several selections at once, and text with multi-byte characters.
  - **The command**: `Command::ReviewFormat(Style)` ("Code Review: Bold", "Code Review: Italic", …, one palette entry per style), active only while a comment box is open (`app/mode.rs`, as `ReviewInsertSuggestion`). It applies to `app.composer`'s buffer through `Buffer::edit` as one `EditKind::Other` undo step, then `composer_changed()` (so the block redraws and the box grows). A style the forge doesn't support says so (`notify`, Info: "Gitea has no underline") and changes nothing. Unbound by default, per [adding a command](../docs/dev/conventions.md#adding-a-command-end-to-end); a user can bind them in `Context::Composer` (Ctrl+B / Ctrl+I there are noted in Deferred, since a Cmd binding means updating `docs/terminals/`).
  - **The toolbar**: a row at the top of the box, under its header, with one short ASCII label per style in `styles(kind)`, in brackets like the buttons below: `[B] [I] [U] [S] [<>] [Link] [>] [-] [1.] [Task] [H]`. A new `BlockLine` kind (`Kind::Toolbar`, its own theme key in `own_entries`), its columns from `composer_tool_cols(kind) -> Vec<(Range<usize>, Style)>` beside `composer_button_cols`, so drawing and clicking agree. `composer_click` maps that row to `ReviewFormat(style)` and shifts the text rows down one (`composer_byte`, the caret's row, the box's height in `sync_review_threads`). A narrow box shows the toolbar's labels that fit and drops the rest from the right (they stay in the palette). It is on every composer kind (draft, reply, edit, conversation comment, review summary): all of them post Markdown.

  - Tests in `jed/src/todo_tests.rs` (`mod review_comment_format`, tests named `review_comment_format_*`) against `forge::fake` per kind: open a comment box with `app.test_execute(Command::Review…)`, select text, click each toolbar label through the hit map and check the box's text and selection; the toolbar on each forge shows exactly `styles(kind)` (no underline where the research found none); a second click toggles off; one undo removes a format; a narrow box drops labels from the right and clicks on the rest still land; clicking the text rows still puts the caret where clicked (the row shift); the command on an unsupported style changes nothing and notifies.
  - Docs: `docs/forges.md` (the toolbar, and the per-forge table of what each button inserts), PLAN.md's Code review feature line, `docs/dev/app.md`'s composer section, [modules.md](../docs/dev/modules.md). No real hostnames.
  - Done when: the comment box shows a formatting toolbar listing only the styles the merge request's forge renders; each button wraps, toggles or prefixes the selection (or inserts the marks at the caret) in that forge's form, for every selection, as one undo step; underline is offered only where the forge's sanitizer keeps an underline tag; each style is also a palette command; the research is recorded; and `scripts/check` is green.
