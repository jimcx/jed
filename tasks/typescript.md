See [Syntax highlighting](../PLAN.md#syntax-highlighting), [LSP](../PLAN.md#lsp). Modelled on [Objective-C and Swift](apple_langs.md) (languages, grammars, a new built-in server, subtasks).

  - Languages: VS Code's ids and names — `Language::JavaScript` (`javascript`, "JavaScript"), `JavaScriptReact` (`javascriptreact`, "JavaScript JSX"), `TypeScript` (`typescript`, "TypeScript"), `TypeScriptReact` (`typescriptreact`, "TypeScript JSX"). Detection (case-insensitive): `.js` `.mjs` `.cjs` `.es6` → JavaScript, `.jsx` → JavaScript JSX, `.ts` `.mts` `.cts` → TypeScript, `.tsx` → TypeScript JSX; shebangs `node`, `deno`, `bun` → JavaScript; `.workspace` associations work as for any language. `.d.ts` is TypeScript. Today `.js.map` is JSON (`language.rs`): keep that — multi-dot extensions are matched before single ones, so check `.d.ts.map` and `.js.map` still go to JSON. `.json` / `package.json` stay JSON
  - Grammars: the `tree-sitter-javascript` crate (covers JSX) and the `tree-sitter-typescript` crate (exposes `LANGUAGE_TYPESCRIPT` and `LANGUAGE_TSX`). Check licences, versions against `tree-sitter-language` 0.1.9, and the clean-build time and size each `parser.c` adds (the TypeScript ones are big). JavaScript and JSX share one grammar, TypeScript and TSX use their two. Add `queries/javascript.scm` / `queries/typescript.scm` on top of each crate's `HIGHLIGHTS_QUERY` (TypeScript's is meant to be layered on JavaScript's: concatenate as the crates document) for Dark+'s colours: keywords incl. `async` / `await` / `of` / `type` / `interface` / `enum` / `namespace` / `declare` / `satisfies` / `as`, `this` / `super`, types and type parameters, decorators, regexp literals, template strings with `${}` as code (`scope_of` must treat the substitution as code and know string / template / comment kinds, `scopes_in_every_language`), JSX tags / attributes / text, JSDoc `/** */` comments, shebang. Every capture must map to `highlight::KEYS` / `ALIASES` (the every-capture test)
  - Language config (VS Code's `language-configuration.json` for each): `//` line and `/* */` block comments; brackets `() [] {}`; auto-closing and surrounding pairs for `() [] {} '' "" `` ` ``; `/** */` closes; indent after `{` `(` `[` and outdent on the closers; word pattern includes `$`; JSX files also pair `<` `>`-less (no `<` auto-close, as VS Code). Tab width stays the user's setting (`detect_indentation` already guesses the 2-space convention)
  - Server: a built-in `typescript-language-server --stdio` (npm `typescript-language-server`, which needs `typescript` installed beside it or in the workspace's `node_modules`) for all four languages, language ids as above in `textDocument/didOpen`. Root: the nearest ancestor holding `tsconfig.json` / `jsconfig.json` / `package.json`, else the workspace root. Prefer the workspace's own `node_modules/.bin/typescript-language-server` over PATH when present, and pass `initializationOptions.tsserver.path` of the workspace's `node_modules/typescript/lib` when it exists (the project's TypeScript version, as VS Code does); `.workspace` `[lsp.typescript]` / the user-level `[lsp.<id>]` win as for the other built-ins (trusted workspaces only). Check: diagnostics (it pushes `publishDiagnostics`, semantic and syntactic after a delay), hover, definition / type definition, references, rename, format (`textDocument/formatting`; its defaults ignore jed's tab size, so send `tabSize` / `insertSpaces` from `settings.for_buffer`), completion with `completionItem/resolve`, signature help, code actions / quick fixes, organize imports if the fixes task has a place for it, and the `$/typescriptVersion` / progress notifications (shown like rust-analyzer's, no errors for them). Requests returning `-32801`-style "no project" errors while tsserver loads must be dropped quietly. Say in the server docs what happens for a lone file with no `tsconfig.json` (inferred project, no cross-file results outside imports it can resolve)
  - Alternatives to weigh in the notes, not build: `vtsls` (wraps VS Code's own TypeScript extension; closest to VS Code's behaviour), Deno's `deno lsp` (`deno.json` projects), `biome lsp-proxy` / `eslint` as a second server (needs multi-server support: check whether that exists, otherwise Deferred)
  - Install: Node and npm are on the Linux dev box but `typescript-language-server` and `vtsls` are not: ask before installing anything. A missing binary gives the usual "couldn't start typescript-language-server" message with its stderr line, and the server docs (`docs/typescript-language-server.md`, like `docs/sourcekit-lsp.md`) say `npm i -g typescript typescript-language-server`
