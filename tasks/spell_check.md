See [Syntax highlighting](../PLAN.md#syntax-highlighting), [LSP](../PLAN.md#lsp) (diagnostics and quick fixes), [Settings](../PLAN.md#settings).

  - Goal: like VS Code's Code Spell Checker: unknown words are marked in the editor, a quick fix replaces one with a suggestion or adds it to a dictionary. Runs in every language, on code as well as prose: comments, string literals **and identifiers**, so `recieveMessage` and `max_buffr_size` are caught. No server and no network: a bundled English word list plus the user's own words
  - What is checked: with a parse tree, text inside `Scope::Comment` / `Scope::String` nodes (`Language::scope_of`) and identifier nodes (the kinds a language's `highlight` marks `variable`, `function`, `type`, `property`, `parameter`, … — decide how to find them per language from the highlight captures rather than a second kind list, and say so in the task notes); keywords, numbers, operators, escapes (`\n`, `\x41`, `%s`, `{name}` format fields) and punctuation are not. Languages with no grammar (plain text, Git messages) and Markdown prose check every word; a Markdown code span / fence checks as code. A setting picks the scope: `spell_check.scope` = `"all"` (default) / `"comments_and_strings"` / `"off"`. Off for files over `syntax_max_bytes`, diff / hex / shell tabs, and read-only log tabs
  - Splitting words (pure, in a model module `spellcheck.rs`, no I/O): a token is a run of letters / digits / `_` / `'` (an apostrophe inside a word stays: `don't`); it is then split at `_` and `-`, at lower→upper (`camelCase` → `camel`, `Case`), at an acronym's end (`HTTPServer` → `HTTP`, `Server`; `parseXMLFile` → `parse`, `XML`, `File`), and at letter↔digit (`utf8Decode` → `utf`, `Decode`; digits dropped). Each piece is checked on its own and lower-cased for lookup. Skipped: pieces shorter than a setting `spell_check.min_length` (default 3: `x`, `id`, `io`), ALL-CAPS pieces (acronyms) and pieces that are hex-looking, URLs, e-mail addresses, file paths and anything with a digit run in it. The mark covers just the misspelled piece (`recieve` in `recieveMessage`), not the whole identifier. Possessive `'s` and common contractions are accepted. Tests pin each split above plus Unicode words (`naïve`, `日本語` is skipped as non-Latin: only scripts the dictionary covers are checked)
  - Dictionaries: a bundled en-AU word list, Australian spelling (`colour`, `organise`, `centre`; the US forms `color`, `organize` are misspellings unless the user dictionary adds them) (pick a licence-clean source — SCOWL `en_AU` / Hunspell `en_AU` — say which, and the size it adds to the binary; compress it, e.g. a sorted word list in an `fst` or a `Hunspell` affix expansion done at build time) plus programming terms that keep identifiers quiet (`struct`, `enum`, `impl`, `stdin`, `mutex`, `regex`, `async`, `tokio`, … and each language's keywords / standard library names, one small list per `Language`, loaded only for it). Loaded once, off the UI thread (`spawn_blocking`) at first use, shared by every buffer; checking is a lookup, no allocation per word. Word forms the list lacks (`-ing`, `-ed`, plural) are handled by the list's affix rules or by listing them; test a few (`parsing`, `tokens`, `unparsed` is a miss and is fine)
  - User dictionary: words the user accepts. Two files, both plain text, one word per line, `#` comments, case-insensitive match (a capitalised entry also accepts the lower-case word, as Code Spell Checker does only for ALL-lower entries: say which rule is used): `<config dir>/dictionary.txt` (all workspaces) and `<workspace>/.jed/dictionary.txt` — or a `[spell_check] words = [...]` list in `.workspace` — for a project's own terms (decide, and say why in the notes: a trusted-workspace question does not arise since a word list is inert). Edited by the commands below, or by hand with live reload (the same file watching as `live_reload_settings`); a bad line is skipped and logged. Words are written through `spawn_blocking` (append, sorted, de-duplicated; atomic write as saves do) and the marks refresh when the file is re-read
  - Marks: spelling marks are `diagnostics::Mark`s under their own source key (a pseudo server id `spell`, so `Marks::replace` / `clear` / `map` keep them aligned with edits and `overlapping` keeps drawing cheap), severity Hint-or-Info with a dotted underline's best terminal approximation (the same SGR underline as diagnostics, theme key `editorSpell.foreground`, new in `Theme::dark_plus`, a distinct colour from the error / warning keys); hover shows `Unknown word "recieve"` with the suggestions' "Quick Fix…" row; the Problems panel lists them under a `Spelling` source only when `spell_check.problems` is true (default false, so a big file doesn't flood it)
  - Checking: after an edit, debounced (~300 ms) and incremental: re-check only the lines the edit's `ChangeSet` touched (map the old marks, drop the touched lines', re-scan those) and the full buffer once on open and after a settings / dictionary change; the scan of a big buffer runs in `spawn_blocking` on a snapshot (a rope clone) and a result for an older revision is dropped, as other background results are. The word being typed is not flagged until the caret leaves it or a separator is typed (no `recieve` squiggle under every half-typed word). Slow scans warn over `SLOW_TASK`
  - Suggestions: edit distance ≤ 2 over the dictionary (a BK-tree / the `fst` Levenshtein automaton, or SymSpell-style deletes; pick one and say why), ranked by distance then word frequency if the list has it, then keeping the original's case shape (`Recieve` → `Receive`, `RECIEVE` → `RECEIVE`) and, inside an identifier, the piece only (`recieveMessage` → `receiveMessage`). At most 8, computed on demand for the one word, never per mark
  - Commands (palette; bind none by default except where VS Code has one): "Spelling: Go to Next / Previous Misspelling" (`F8` / `Shift+F8` are Problems', so unbound), "Spelling: Add Word to User Dictionary", "Spelling: Add Word to Workspace Dictionary", "Spelling: Ignore Word in This File" (session only, not saved), "Spelling: Toggle Spell Check" (this buffer, then reverts at close), "Spelling: Open User Dictionary" (opens the file, creating it empty). The word is the mark under the caret, else the word at the caret. Quick fix on a mark (the lightbulb and Cmd+.): the suggestions as `Replace with "receive"`, then "Add "recieve" to user dictionary", "…to workspace dictionary", "Ignore in this file", sorted after server fixes. Fixes go through `Buffer::edit` as one `EditKind::Other` step on that piece, with several selections each handled (a command acting on many selections replaces each selected word's piece)
  - Settings (`config/settings.rs` + `edit::Settings`, per the settings convention): `spell_check.scope`, `spell_check.min_length`, `spell_check.problems`, `spell_check.language` (`"en_AU"` only for now, the default; a field that names the dictionary, so other languages can be added), `spell_check.ignore_words` (extra words in the settings file itself); per-language override via `[spell_check]` in `.workspace` (`off` for a language, e.g. a generated-code or log language)
  - Needs: `diagnostics::Marks` and its source keys, `code_action` quick-fix plumbing and the lightbulb, `hover` diagnostics rows, `syntax::Language::scope_of` and `highlight` captures, `ChangeSet` mapping, the file watcher / live reload, `Theme::dark_plus`, the config dir helpers
  - Tests: `spell_check_*` — splitting (every example above, plus `snake_case`, `SCREAMING_SNAKE`, `kebab-case`, `ID3Tag`, `a_b`, `__init__`, leading / trailing separators, apostrophes); the checker marks only the piece, skips keywords, numbers, URLs and acronyms; Rust / Python / C++ snippets mark a typo in a comment, a string and an identifier but not in a keyword; comment-and-string scope ignores identifiers; user-dictionary load (comments, blank lines, case rules, a bad line), add-word writes the file once, sorted and de-duplicated, and unmarks the word in every open buffer; a workspace word does not leak to another workspace; marks follow edits and a stale background result is dropped; the half-typed word is not flagged; suggestions for `recieve`, `Recieve`, `RECIEVE`, `recieveMessage`; the quick fix replaces just the piece in one undo step, across several selections; commands refuse on a read-only / diff / hex tab; a release budget test (`milestone_spell_check_budget_*`) for a 1 MB source file: full scan within a budget, one-line edit re-check within a few ms, no per-frame work (drawing only reads `Marks::overlapping`)
  - Done when: in a Rust file, a typo in a comment, a string and a variable name is underlined (only the misspelled piece), `camelCase` and `snake_case` names are split and each word checked, keywords and acronyms are left alone; hovering shows the word and its suggestions, the lightbulb / Cmd+. replaces it or adds it to the user or workspace dictionary and the underline disappears in every open file; editing `dictionary.txt` by hand takes effect without a restart; typing a long word does not flicker marks; a 1 MB file scans without blocking the UI; and `scripts/check` passes
  - Deferred: other languages' dictionaries (the setting names one, only en_AU ships), grammar checking, a bundled-dictionary download, per-language ignore regexes (Code Spell Checker's `ignoreRegExpList`), checking file names and the commit message editor's body separately, "add word" from the Problems panel
  - Subtasks (one agent and one commit each):
    - spell_check-a: the model, no app wiring: `spellcheck.rs` word splitting, the bundled dictionary + programming terms (loading, lookup, licence note, binary size), `Checker::check(text, spans) -> Vec<Misspelling>`, suggestions; unit tests for all of the above; docs (`docs/dev/modules.md`)
    - spell_check-b: finding what to check: from a parse tree the comment / string / identifier byte ranges per language (via `scope_of` and the highlight captures), whole-text for plain text and Markdown prose; the user and workspace dictionary files (parse, write, atomic append, watching and reload); settings (`spell_check.*`), `Theme` key; unit tests
    - spell_check-c: in the editor: background checks and incremental re-checks into `diagnostics::Marks` (own source), stale-result drop, the half-typed-word rule, drawing and the status bar / hover rows, the optional Problems entries; end-to-end tests with `settle`; budget test
    - spell_check-d: commands and quick fixes: Next / Previous, Add to user / workspace dictionary, Ignore in file, Toggle, Open User Dictionary, the lightbulb / Cmd+. fixes and suggestions, many-selections behaviour; keymap / cheat sheet / palette docs and tests; docs and hand checks; marks the task ✅
