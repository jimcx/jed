name: Stop idle language servers
summary: language servers stop after jed has had no input for an hour (`[lsp] idle_stop_minutes`) and start again on the next input, so jed instances left in the background hold little memory
status: in-progress

See [LSP](../PLAN.md#lsp). A jed left open in a background terminal keeps its language servers running, and they hold far more memory than jed: rust-analyzer on this workspace sits at ~2 GB while jed itself is ~90 MB. Stop them when jed has been inactive for a while, and start them again, quietly, when the user comes back.

  - Needs: `lsp/mod.rs` (`Manager`: `sync`, `restart`, `stopped`, `take_cleared`), `lsp/server.rs` (`Shutdown`), `lsp/documents.rs` (didOpen again on restart), `app/lsp.rs` (`start_servers`, `sync_documents`, pending requests), `app/mod.rs` (`handle_event`: what counts as input), `app/claude_lsp.rs` (MCP requests), `config/settings.rs` (the `[lsp]` table), `workspace/config.rs`, the Tools view ([conventions: LSP requests](../docs/dev/conventions.md), [adding a setting](../docs/dev/conventions.md#settings))
  - Setting: `[lsp] idle_stop_minutes = 60` (an integer; `0` = never stop), in `settings.toml` and in `.workspace` (a `.workspace` value wins; it runs nothing, so trust doesn't cover it and it stays out of `Commands`). It's a plain key beside the `[lsp.<language id>]` tables: the `[lsp]` parsers accept it instead of reporting "must be a table", and no language id can be named `idle_stop_minutes`. A settings reload applies the new value to the running clock (lowering it below the time already idle stops the servers on the next check).
  - Inactivity: the time since the last user input — a key, mouse event, paste, or focus gained (the terminal window coming back counts as the user returning; losing focus alone stops nothing). Terminal output, file-system events, git refreshes, task output and language server traffic don't reset it. A request from Claude through the MCP server (`app/claude_lsp.rs`, the `claude_ide` tools) counts as input: it restarts the servers and waits for them like a request made during a normal start.
  - Stopping: checked on the event loop's existing timer, not a new task per server (cheap: one `Instant` comparison). Every running server is stopped through the same `Shutdown` path `sync` uses (shutdown → exit → kill after `SHUTDOWN_TIMEOUT`) and remembered as idle-stopped (config, root, languages). It's not a failure or a crash: no notice, an `info` log line (`stopping language servers after 60 min idle`) and a line in each server's tool log. Their diagnostics stay in buffers and Problems (the last word until the server is back, as VS Code keeps them while a server restarts); pending requests are dropped as on `Exited`. A server that is `Starting` is stopped too; a `Failed` one stays as it is (it is never restarted except by "Restart Server"). The Tools view lists idle-stopped servers as "stopped (idle)", not as exited.
  - Restarting: the first input after an idle stop starts every idle-stopped server again with the same config and root (the `restart` path without the old instance), and `sync_documents` sends `didOpen` for every open buffer of their languages at its current text and version. When it publishes, its diagnostics replace the kept ones (they're dropped then, not at the stop). The key that woke it is handled normally: a completion or hover it triggers waits for the server as during startup. If the configuration changed meanwhile (a reload, a new `.workspace`), `sync`'s current answer wins and an idle-stopped server whose languages no longer resolve to it is just forgotten.
  - Memory check by hand: on a big Rust workspace, idle long enough (or set the value to `1`) and confirm rust-analyzer and its proc-macro servers are gone from `ps`, then press a key and see them come back with diagnostics and hover working.
  - Done when: with a fake launcher (`lsp/fake.rs`) and the idle clock driven by the test (an injectable `Instant` / a test hook advancing it, never a sleep): after `idle_stop_minutes` without input each running server got `shutdown` + `exit` and is listed "stopped (idle)", diagnostics still shown; terminal output, a file change and a server notification during the wait don't reset the clock, a key press and a focus-gained do; the next key starts the server again with `didOpen` for each open buffer of its language, and a hover pressed then is answered; a fresh publish replaces the kept diagnostics; an MCP `find_definition` while stopped restarts the server and returns its answer; `0` never stops; a `Failed` server stays failed; `.workspace` beats `settings.toml`; `idle_stop_minutes` beside `[lsp.rust]` parses in both files and a non-integer is reported; the setting is in `TEMPLATE`, the settings table, `docs/dev/lsp.md` and PLAN's LSP section.
  - Deferred: a per-server value (`[lsp.<id>] idle_stop_minutes`: it would join `ServerConfig`'s equality, which decides sharing and restarts); stopping a single server whose languages have no open buffer; freeing jed's own memory while idle (shell scrollback, undo history, closed buffers' caches) — see [Performance pass](performance_pass.md)
