id: term_area
name: Terminal area
summary: interactive terminals (shell tabs) get a full-width area above the status bar that behaves like an editor group, but only terminal tabs dock there
status: open
priority: 0
dependencies: []
---

  - Needs: the shell tab (`Tab::Shell`, `shell.rs`, `app/shell.rs`, `ui::task::render_shell`), the group model (`Groups` + `layout::SplitTree` + `Group`), `layout::compute` / `Regions` and `HitMap`, `ui/splash.rs`, the `Context::Shell` keys and `Focus`, drag-and-drop tabs (`app/tab_drag.rs`)
  - A `terminal area` region: full width, directly above the status bar (below the side panel, the editor groups and the bottom panel — which keeps the throwaway task terminals); its own height (a new `ui` field, resized by dragging its top border as the bottom panel's is, clamped so the editor keeps its minimum). It shows when a terminal opens and hides when the last closes, so an empty editor area shows the Jed splash as it does now
  - The area behaves like an editor group: a tab bar of its terminal tabs and a `SplitTree` of terminal groups, so terminals reorder (drag along the bar, and the move-tab keys) and split right / down (Cmd+\ / Cmd+Alt+\ in the terminal context) into live side-by-side / stacked shells. Dragging a terminal works exactly as dragging an editor tab (`drag_tabs`): along the bar reorders it, onto another terminal group's bar or screen moves it there, and onto a terminal group's edge (within a quarter of its width or height) splits that group on that side and moves the terminal into the new split, the drop zone shaded. Only `Tab::Shell` docks there — a non-terminal tab dropped or moved in is refused, and task runs stay in the bottom panel, never the terminal area — and a split never copies a shell (a shell can't be in two groups), so splitting a terminal group leaves the new group empty
  - New terminals open there by default: `terminal.newShell` (Ctrl+`) opens in the terminal area (showing it) instead of the active editor group; the area has its own focus (a `Focus::Terminal`), the terminal cursor only in its focused group
  - Move a terminal between the area and an editor group: "Terminal: Move Terminal into Editor Area" / "… into Terminal Area" (palette, unbound) and dragging a terminal onto an editor group's bar or editor moves it there (an editor `Tab::Shell`, as today); dragging an editor tab into the area stays refused
  - Sessions: the area's shown / height / splits are not session state; a new session opens one terminal in the area (so it starts shown, one shell), and shells stay unsaved as now
  - Done when: Ctrl+` opens a shell in the terminal area and the editor groups keep their space; a second shell is a tab, reordered by dragging, and split — Cmd+\ or dragging it onto a terminal group's edge — into two live shells side by side; dropping a text tab into the area is refused; a terminal dragged onto an editor group moves there and "Move Terminal into Terminal Area" brings it back; closing the last terminal hides the area and, with no editor tabs, shows the Jed splash; a new session opens one terminal in the area
  - Subtasks (one agent and one commit each):
    - term_area-a: the region and one terminal — `layout::compute` gains the terminal-area region (full width, its height clamped), a `Terminals` model holding the shell tabs, `terminal.newShell` routing there (showing the area), the tab bar + terminal rendering and `Focus::Terminal` / `Context::Shell` keys; closing the last terminal hides the area (the splash shows in an empty editor area)
    - term_area-b: reorder and split — the terminal area's `SplitTree` of terminal groups, split right / down and focus (the group keys), dragging a terminal as an editor tab drags (reorder along the bar, move between terminal groups, drop onto a terminal group's edge to split it there, the drop zone shaded), and the only-terminals-dock rule (a non-terminal tab refused, a split leaves the new group empty)
    - term_area-c: moving a terminal into / out of an editor group ("Move Terminal into Editor Area" / "into Terminal Area" and dragging it onto an editor group), the startup terminal (a new session opens one in the area; nothing about the area is session state), the done-when tests, gaps and hand checks; marks the task ✅
