summary: a shell tab and each task tab keep their last column for a vertical scroll bar, exactly like every other scrolled surface
status: done
priority: 0

---

  - The model (`tasks::run.rs`): `vt100::Screen` exposes the scrollback offset and `set_scrollback` but not the kept-line count the bar needs as `max_top`, so `Run::scrollbar_extent` probes it — `set_scrollback(usize::MAX)`, read `scrollback()`, restore — O(1) under the parser mutex (atomic w.r.t. the reader thread, no vt100 fork). `Run::set_scrollback_from_top(top)` sets `set_scrollback(max - top)` and clears the selection (the rows move, as `scroll` / `scroll_to` already do). `TerminalScroll` is a `Scrollable` on a borrow of the run (not on `Run`, so its `scroll()` doesn't clash with `Run::scroll(&self, isize)`): `scroll()` → `Scroll::rows(max + rows, rows, max - back)` (the live screen is `top == max`, the oldest output `top == 0`, the last page full as a terminal view is always `rows` tall), `set_top` → `set_scrollback_from_top`
  - The wiring (`app/scrollbar.rs`): `with_scrollable` gains the two arms — `ScrollTarget::Group` on a `Tab::Shell` and `ScrollTarget::Panel(PanelTab::Task(id))` — both `TerminalScroll`, reusing the existing `ScrollTarget`s (no new variant); the wheel-over-a-bar remap to `Hit::Editor(g)` / `Hit::Panel` already scrolls a shell / task, so no new wheel code
  - The shell tab (`ui/mod.rs`): the `bar = …` computation drops the `active_shell()` exclusion, so a shell keeps the last column too; the shell branch draws the bar (`scrollbar::render`, base `editor` patched with `terminal.background`, `marks = &[]`) into `GroupHit::scrollbar`. The shell's PTY resize at line 251 already uses the now-narrower `editor_area`, so it shrinks by one column automatically. `render_shell` itself is unchanged
  - The task tab (`layout.rs` + `ui/task.rs` + `ui/panel.rs`): `task_area` now reserves the right column (width `panel.width - 2`) and a new `task_bar` returns the column just right of it (the three callers of `task_area` — `ui/task::render`, `app/tasks::start_task`, `app/mouse::terminal_run` — stay consistent, so no `app/mouse.rs` change). `ui/task::render` draws the screen in the narrower `content`, then the bar (`ScrollTarget::Panel(PanelTab::Task(id))`), and returns `Option<ScrollBarHit>`; `ui/panel.rs` folds it into `hits.scrollbar`
  - In the alternate screen (vim / tmux) the grid has no scrollback, so the probe clamps `max` to 0 and the bar shows no thumb
  - Tests: `tasks::tests::terminal_scroll_bar_extent_and_set_top` (a `seq 1 50` run in a 5-row screen: `max_top` equals the probed `scrollback()`, `top == max_top` live and `0` at the top, `set_top` moves the offset and clears a selection) and `terminal_scroll_bar_without_scrollback_shows_no_thumb` (no scrollback — the alternate screen's case — probes `max == 0` and shows no thumb); `todo_tests::term_scroll_bar` end to end — a shell and a task tab with `COUNT_TO_200`'s output scrolled off the top show a thumb at the bottom, one column before which the terminal ends, Ctrl+Home / Shift+PageUp move it to the top, dragging the bar scrolls the scrollback, the wheel over it scrolls, and a fresh shell shows a reserved track with no thumb. The `term_mouse` / `term_select` / milestone-12 PTY-size tests updated for the one-column-narrower terminal
  - Still to check by hand: hover / drag colours under a real terminal; an ended run whose screen is taller than its area (the bar uses `screen.size().0` as its viewport height, exact while running, approximate for that pre-existing case)
