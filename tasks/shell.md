  - What it changed (for later work): `tasks::run::Run` takes a `scrollback` cap when created (`vt100::Parser::new(rows, cols, scrollback)`), and `Tasks::scrollback` comes from `App::settings.scrollback` at `start_task`; the `scrollback` setting (`Settings`, `SettingsOverrides`, `TEMPLATE`; default `tasks::run::SCROLLBACK` = 5,000) applies to task runs and shells alike. `group::Tab::Shell(Box<ShellTab>)`, boxed like diff and hex: `active_buffer` / `active_mut` are `None`, `same_as` matches nothing, `split` leaves the new group empty, closing drops the run (killing it) and sessions skip it. `shell` (`ShellTab` (`run`, `title`, `base`), `spec` (no `-c` or rc flags, `TERM` / `COLORTERM`, `JED_IPC` when the socket listens), `title`, `base`, `end_note`); `App::new_shell` numbers the title by base and starts the run at the group's editor size (else `tasks::DEFAULT_SIZE`); `Context::Shell` (no parent) plus `Command::Shell(ShellCommand)` scroll commands (Shift+PageUp / PageDown, Ctrl+Shift+Up / Down, Ctrl+Home / End) and keys / pastes through `tasks::keys` with the screen's application-cursor and bracketed-paste modes; `ui::task::render_shell` draws the screen over the whole editor area (no tab strip, info line or scroll-bar column), its run resized by `ui::mod` each frame, the terminal cursor only when focused, running, live and not hidden; `App::shell_event` appends the exit note (kept on screen and in the status bar); `shutdown_shells` SIGHUPs, waits `SHUTDOWN_TIMEOUT`, then SIGKILLs. `render_shell` reads the run's status before taking its screen: the spawn holds the state lock while it takes the screen's, so the reverse order deadlocked a new shell's first frame.   - "Terminal: New Shell" (palette, Ctrl+`) opens a tab in the active group: `$SHELL` (else `/bin/sh`) started as a terminal emulator starts it — interactive on a PTY in the workspace root, no `-c` and no rc-skipping flags (`--norc` / `--noprofile`), so the user's regular init (`.zshrc` / `.bashrc` / `config.fish`) runs — with `JED_IPC` exported when it opens (once the socket listens; none in tests or with IPC off), so `git commit` and `jed <file>` from inside it open in this jed (see [Git editor](../PLAN.md#git-editor-commit-messages))
  - A tab type as diff and hex are: `Tab::Shell`, `active_buffer()` / `active_mut()` are `None` there, so editor commands need no checks; each shell is its own tab (`same_as` matches nothing; splitting on one leaves the new group empty, since a shell can't be in two groups); never dirty, so closing it never prompts; not in sessions and nothing to back up; its title is the shell's file name (`zsh`, `zsh (2)`)
  - Keys: a new `Context::Shell` with no parent — jed's global bindings still work (Cmd+W closes the tab and kills the shell, Ctrl+Q quits, the palette) — plus scrollback bindings (Shift+PageUp / PageDown, Ctrl+Shift+Up / Down, Ctrl+Home / End) and paste; every other key (typing, Enter, arrows, Esc, Ctrl+C) goes to the shell through `tasks::keys`; the PTY is resized to the tab's area each frame; the wheel scrolls its scrollback; on exit its output and status stay until the tab is closed (as a task run); quitting jed hangs up every shell (as tasks)
  - Scrollback: a `scrollback` setting (lines, VS Code's `terminal.integrated.scrollback`; default 5,000, `tasks::run::SCROLLBACK` becoming the default) read when a run is created, for shell tabs and task runs alike — the `vt100` parser's capacity is fixed at creation, so a changed `.workspace` setting applies to the next shell / run
