See [Syntax highlighting](../PLAN.md#syntax-highlighting), [Keybindings](../PLAN.md#keybindings-vs-code-defaults), [Text positions](../PLAN.md#text-positions), [Async and blocking work](../PLAN.md#async-and-blocking-work).

  - What: a command "Markdown: Open Preview to the Side" shows the active Markdown buffer rendered (not as source) in a new read-only editor view in a split to the right of the current group (reuse the group on the right if one exists, as Split Right does; running it again on the same source focuses the existing preview instead of opening another). The preview follows the source: edits to the buffer re-render it (debounced, off the UI thread when the document is large), and the preview scrolls roughly with the source's top line
  - Keybinding: **Cmd+Alt+V** on macOS, **Ctrl+Alt+V** on Linux. Checked free in `keymap::defaults` (Ctrl+Shift+V, VS Code's own key, is the terminal's paste on Linux, so it is not used). Also in the command palette. Add the macOS Cmd binding to the table in `docs/terminals/README.md` and every terminal snippet (`terminal_docs_list_every_cmd_binding` enforces it), and to PLAN.md's keybindings table
  - Tab kind: decide in the notes between a new `group::Tab` variant (as `Diff` / `Hex`: own model in `markdown.rs`, drawing in `ui/markdown.rs`, `Context::Markdown` with movement, selection, copy and scroll only, `active_buffer()` / `active_mut()` `None`) and a read-only text buffer holding the rendered lines with per-span styles; a tab variant is expected because tables and wrapped code blocks do not map to source text. Read-only either way: edits, cut and paste do nothing, copy copies the rendered text. Run `Command::all()` on a preview tab as `milestone_10_editor_commands_on_a_diff_tab_do_nothing` does
  - Parsing: a CommonMark + GFM parser (`pulldown-cmark`, check licence and clean-build cost; tables, strikethrough and task lists enabled), turned into a line-oriented model of styled spans in `markdown.rs` (no app state, draws nothing). Everything is laid out to the view's width and re-laid-out on resize
  - Headings: H1 to H6 visibly different in a terminal, via theme keys (`markdown.h1` … `markdown.h6`, added to `Theme::dark_plus`): H1 bold, brightest colour, full-width underline of `═`; H2 bold with an underline of `─`; H3 bold; H4 bold dim-accent; H5 italic; H6 dim italic. Each is preceded by a blank line and may show its marker (`#` count) in a muted colour. Setext headings render the same as ATX
  - Code blocks: fenced and indented blocks drawn on a distinct background across the full width with a one-column pad, the info string (language) as a muted label on the top row, long lines clipped with horizontal scroll or wrapped (choose, note it), and syntax-highlighted through the existing `syntax` machinery when the info string names a known language (`rust`, `python`, … by `Language` id or extension), plain otherwise. Inline code gets its own background span. No colours outside `theme.rs`
  - Tables: GFM tables as box-drawn grids (`┌ ┬ ┐ │ ├ ┼ ┤ └ ┴ ┘`), column widths from the widest cell using display width (`DisplayCol`, wide characters and tabs handled via `buffer::pos`), per-column alignment (`:--`, `:-:`, `--:`) honoured, header row bold with a separator, cells containing inline emphasis / code / links rendered styled. When the grid is wider than the view, shrink the widest columns and wrap cell text within them (minimum column width stated in the notes); if even that does not fit, the table scrolls horizontally rather than clipping silently
  - Other elements, at least: paragraphs (wrapped to the width), emphasis / strong / strikethrough / inline code, links (text styled, URL shown after it in a muted colour), images (alt text in brackets with the URL), ordered / unordered / nested lists with the right bullets and indent, task lists (`☐` / `☑`), block quotes (`▎` gutter, nested), horizontal rules, hard / soft breaks, HTML blocks shown as muted source. Front matter (`---` YAML at the top) is shown as a muted code block
  - Which files: a buffer whose `Language` is Markdown (by extension, as detection already does); the command does nothing with a notice on any other tab. An untitled buffer set to Markdown works too
  - Sessions and the rest: preview tabs are restored by sessions as the source path (`TabState` variant, session `VERSION` unchanged if serde-tagged as for hex) and re-rendered on open; closing the source leaves the preview showing the last render with "(source closed)" in its title; the title is "Preview <file>"; the status bar names the source. Back / forward entries are path only. Update `docs/dev/modules.md`, `docs/dev/conventions.md#tabs`, `src/ui/CLAUDE.md` as needed
  - Needs: the tab kinds (`group::Tab`, as `Diff` / `Hex`), splits and `SplitRight`, `syntax` for code-block highlighting, `theme.rs`, scroll bars, sessions (M13), `buffer::pos` for widths, the keymap and terminal-docs table
  - Deferred: clicking links to open them, scroll sync from preview back to source, images drawn as graphics, Mermaid / math, an HTML-in-Markdown renderer, a "Lock Preview" toggle, exporting to HTML
  - Tests: unit tests in `markdown.rs` for each heading level's styling being distinct, a fenced block with and without a language, an indented block, tables (aligned columns, wide characters, narrower than natural width, wider than the view, inline code in a cell, an empty cell, a ragged row), nested lists, a task list, a block quote around a list, and an unclosed fence; the keymap test for the new binding on both platforms; end-to-end tests in `src/todo_tests.rs` (`mod markdown_preview`): open a `.md` file, press the key, a second group exists on the right holding a read-only preview, typing in the source updates it, edits on the preview do nothing, a non-Markdown tab gives a notice, pressing again focuses the same preview, session round trip
  - Done when: opening a README-style `.md` with H1–H6, a fenced Rust block, an indented block, a table with mixed alignment and a task list and pressing Cmd+Alt+V (Ctrl+Alt+V on Linux) opens a split to the right where the six heading levels are visually distinguishable, the Rust block is on its own background and highlighted, the table is a correctly aligned box-drawn grid (also with a wide-character cell, and after narrowing the window), the preview cannot be edited, and typing in the source updates it; the tests above pass
