See [Git](../PLAN.md#git-view-and-stage-only) and [Selection and editing in diff tabs](diff_edit.md).

  - Goal: a diff tab of any two texts, each a file on disk or an open buffer, saved or not (a dirty file's unsaved text, an untitled buffer), as VS Code's "Compare Active File With…" does; both sides can be edited by hand in the tab and a change can be moved from either side to the other. The tab is transient: not kept in sessions
  - Sides: a side is a file (`diff_view::Text::File(path)`: the open buffer's text when open, else the disk) or an open buffer by identity (`Text::Open(BufferId)`: its live text, saved or not; the only way to name an untitled buffer, which has no path). Not in `Text::Disk`: a dirty file compared with its own saved text stays "Compare with Saved". A side that is an open buffer is writable (a file side that isn't open is opened as a buffer behind the diff on the first edit or move, as `diff_edit` does for a diff of a file that isn't open)
  - Commands (palette, unbound): "File: Compare Active File With…" opens a picker listing the open buffers first (untitled ones by their title, dirty ones marked) then quick open's file list, and opens a diff tab of the picked text on the left ↔ the active buffer on the right; "File: Compare Open Editors…" picks two open buffers in turn. Comparing a text with itself says so and opens nothing. No Explorer commands, no "select for compare" pair
  - Tab: titled `a.rs ↔ b.rs` (an untitled buffer by its title, a dirty side marked), no staging; follows edits on either side as the buffer changes (`Later` reloads as now) and a closed buffer's side freezes to its last text (read-only from then on) rather than closing the tab; next / previous change; binary files say "binary" as now. Selecting text on a side first compares just the selections, as `diff_tab_selected_lines` does, if that task has landed
  - Moving a change: each hunk shows "Apply to Left" / "Apply to Right" buttons (the arrows between the sides), and the commands "Diff: Apply Change to Left / Right" (palette, unbound) act on the hunk at the cursor. The hunk's text on the source side replaces its range on the target side, through `Buffer::edit` as one `EditKind::Other` step (undoable in the target's buffer, unsaved); a read-only or frozen target refuses with a notification, as `diff_revert` does; the diff re-aligns after (the hunk disappears). Modelled on `diff_revert` / `revert_edit`
  - Hand editing: typing, deleting, paste, cut, undo / redo and save on either writable side, through the side's buffer, with the caret kept across the re-read. This is `diff_edit`'s machinery generalised from "the right side" to "any side that is an open buffer"
  - Needs: the git diff view (`diff_view`, `DiffTab`) and quick open's file list; reads of unopened files go through `spawn_blocking` as for other diff sides; hand editing needs `diff_edit` landed (at least `diff_edit-b`)
  - Tests: `compare_files_*`: file ↔ file; file ↔ dirty buffer (the unsaved text shows, the disk's doesn't); untitled ↔ file and untitled ↔ untitled; typing in either buffer updates the diff; closing a side's buffer freezes it; same text twice refused; apply a hunk left and right (text, one undo step, hunk gone, buffer dirty); refuse into a read-only / frozen side; typing in the diff's left and right side edits that buffer; side-by-side and inline layouts draw
  - Done when: any two files, dirty buffers or untitled buffers can be compared in a diff tab from the palette or picker, the diff follows edits on both sides, a hunk can be moved to either side, both sides can be edited by hand in the tab; and `scripts/check` passes
