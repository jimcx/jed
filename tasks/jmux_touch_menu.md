See [jmux's plan](../jmux/PLAN.md): [Attach and detach](../jmux/PLAN.md#attach-and-detach), [Terminals, tabs and splits](../jmux/PLAN.md#terminals-tabs-and-splits); [jmux_touch](jmux_touch.md) (the 3-row padded bars this replaces) and [jmux_touch_gestures](jmux_touch_gestures.md) (tap, swipe and hold, which the menu uses).

On a phone the 3-row tab bar of `jmux_touch` takes rows from every group, and its tabs are still small targets once there are several of them. In the touch layout the groups drop their tab bars entirely, and one button on the status bar, `☰`, opens a menu: a vertical list of the tabs, each a big padded row to tap, then "New Tab", then any further actions. The terminal gets the bar's rows back.

  - Needs: `jmux_touch` (`App::touch`, `App::tab_metrics()`, `jtui::tabs::TabMetrics`), `jmux_touch_gestures` (`app/touch.rs`: pending `Drag::Press`, tap / swipe / hold, `SLOP`, `HOLD`); `jmux/src/ui.rs` (`bar_and_term`, `term_area`, `status_bar`, `STATUS_ROWS`), `jmux/src/hit.rs` (`Hit`, `HitMap`), `jmux/src/app.rs` (`pointer_event`, `term_size`, key context), `jmux/src/command.rs` (`Context`, commands), `jmux/src/keymap.rs`, `jmux/src/theme.rs`.
  - **No tab bars in the touch layout.** With `App::touch`, `ui::bar_and_term` gives each group no bar rect and the whole group to its terminal (`TabMetrics` gains a "no bar" form, or `bar_and_term` checks the layout; one place either way, so `App::term_size` and the frame still agree). Attaching with `--touch` therefore makes each shell taller by the bar's rows, and the shells get a resize; a plain client taking over gets its bars back on its first frame. `tabs_at_bottom` has nothing to move in the touch layout. A plain client is unchanged.
  - **The `☰` button.** The status bar starts with a `☰` button (theme key `statusBar.menu`, highlighted while the menu is open) as a target 3 cells wide (`☰` and a cell each side) — the status bar stays 1 row. The rest of the status bar follows it as today. `Hit::Menu` in the `HitMap`; a tap on it opens the menu, a tap while open closes it. In the touch layout only.
  - **The menu.** An overlay opened from the status bar, its bottom edge on the row above the status bar, full width on a narrow screen (a phone in portrait) and at most ~40 cells wide otherwise, kept inside the screen. It lists, top to bottom:
    - the focused group's tabs, in tab order, each `  title  ` on one row with one empty row of padding between rows (and one above the first and below the last), so each item is a 3-row target: its text row and half the padding each side. The active tab is drawn highlighted (`menu.active`), a tab with a running command marked as the side bar marks it;
    - a separator, then **New Tab** (opens a terminal in the focused group, as the `+` did);
    - then further actions, each an item of the same height. The list after New Tab is data — a `Vec` of (label, `Command`) built in one function — so adding an action is one line there. This task ships New Tab only; candidates are in Deferred.
    The rows use `menu.*` theme keys added to `own_entries`; no `Color::` outside `theme.rs`.
  - **Picking.** A tap on a tab item focuses that tab and closes the menu; a tap on New Tab or an action runs its command and closes the menu. A tap outside the menu (on a terminal or the status bar outside `☰`) closes it and does nothing else. A swipe on the menu scrolls it when it is taller than the space above the status bar (the items follow the finger, as a swipe on the bar did) and picks nothing. A hold does nothing. A press–release with a plain client's mouse (a desktop terminal) picks too, so the menu can be tested and used either way.
  - **Keys.** A `menu.toggle` command (in the palette / side bar list as "Toggle Tab Menu", no default key) opens and closes it. While it is open a `Context::Menu` takes the keys: Up / Down move the highlight over the items (skipping the separator), Enter picks, Escape closes; unbound keys are swallowed, as the side bar does. Add the context to `Context::parse` / `names` and the default keymap, and check `command_driven_tests.rs` still covers every context.
  - **What the tab bar did that goes with it.** In the touch layout there is no `×` (a tab closes when its shell exits or with the close-terminal key, with the running-command confirmation as today), no `‹` / `›`, no tab drag to another group or a terminal half. With splits, the menu lists only the focused group's tabs: tap a group's terminal to focus it, then open the menu.

Tests in `jmux/src/jmux_touch_menu_tests.rs`, named `jmux_touch_menu_*` (a `//!` doc, a `#[cfg(test)] mod` line in `main.rs`), driven by `run(Command::..)` and taps through the touch gesture path: the layout and the shells' size on a `TestBackend`, the menu drawn at a phone's width and a wide one, hits on each row of each item, picking a tab, New Tab, outside tap, scrolling, the keys, the takeover.

- ✅ Done. With `--touch` the groups draw no tab bars (each shell is the bar's rows taller), the status bar starts with a 3-cell `☰` button, and the button opens a menu above the status bar: the focused group's tabs as padded rows, a separator, then New Tab. Tap, swipe (scroll), hold (nothing), a plain client's click, and `menu.toggle` with Up / Down / Enter / Escape in `Context::Menu` all work.
  - `App::tab_metrics()` gives a 0-row bar in the touch layout, so `ui::bar_and_term` / `App::term_size` agree. The model is `jmux/src/menu.rs` (`actions()` is the one list after the tabs; `rows()`, `area()`, `Menu`), driven by `jmux/src/app/menu.rs` and drawn by `jmux/src/ui_menu.rs`. Hits are `Hit::{Menu, MenuItem, MenuDead, MenuOutside}`; `App.menu_actions` starts from `actions()`. Theme keys `statusBar.menu(.active)` and `menu.*`. `hello` / `detach` close the menu.
  - A shared padding row between two items goes to the lower item: the first item owns the row above it and the last of each section the row below, so inner items are 2-row targets.
  - Removed the touch tab bar that this replaces: `jmux_touch_gestures_tests.rs`, the touch-bar tests in `jmux_touch_tests.rs`, `Hit::NewTab` and the `+`, the bar swipe, tab lift and tap paths in `app/touch.rs`, `tabbar::max_offset`, `Marks.lifted`, `Group::shift` / `scroll_offset` / `set_scroll_offset`, and `tab.lifted`. `jtui::tabs::TabMetrics::TOUCH` stays because jed uses it. `app/touch.rs` now handles terminals and the menu only.
  - Deferred: as listed above (more actions, close from the menu, every group's tabs, reordering, jed's touch layout).
  - Still to check by hand: as listed above. Also: `☰` (U+2630) is two cells wide under `unicode-width`, so it covers the button's right pad cell; check that it looks right, or fall back to `≡`.
