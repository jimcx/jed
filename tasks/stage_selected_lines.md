See [Git](../PLAN.md#git-view-and-stage-only). VS Code's "Git: Stage Selected Ranges" / "Unstage Selected Ranges" / "Revert Selected Ranges" (palette, unbound; ids `git.stageSelectedRanges` / `git.unstageSelectedRanges` / `git.revertSelectedRanges`), from a text tab and from a git diff tab. (This task took in the former `diff_tab_selected_lines`.)

  - Needs: `git::diff` (context-0 hunks, `apply` / `revert`, `touches`, `old_lines`), `git::stage` (`stage_hunk` / `unstage_hunk` / `revert_hunk`, `Stale` checks, `stage_line` / `unstage_line`), the gutter's stage flow in `app/quick_diff.rs` (`stage_at`, save-first prompt, waiting for a save in flight, `spawn_stage` / `staged`), the diff tab's stage / revert in `app/diff_view.rs` (`diff_stage`, `diff_revert`, `revert_edit`) and its caret / selection (`diff_caret`, from `diff_edit`).
  - The lines picked: every changed line in them, nothing else. A pick is two sets of line ranges: old lines (removed lines to take) and new lines (added lines to take). Each context-0 hunk of the pair's diff takes only the picked lines: an added line picked = added, a removed line picked = removed, the rest of the hunk left as it was (`git add -p`'s `e`dit result). A hunk none of whose lines are picked is untouched.
    - From a text tab: the lines its selections touch (every selection; an empty cursor = its line; a selection ending at column 0 of a line doesn't take that line) are the new lines; a hunk's removed lines are taken when the hunk touches them (`diff::touches`: a pure deletion at the boundary of a picked range counts).
    - From a diff tab: the rows the selection covers (anchor row to head row; no selection = the caret's row), in either layout and from either side; each row contributes its left line (old) and its right line (new).
  - Stage applies the pick to the index blob from the index → disk diff (checked against `Stale` as `stage_hunk`; a file gone from disk whose whole deletion is picked leaves the index); a text tab's dirty buffer is saved first as hunk staging does (asking; a save in flight is waited for). Unstage likewise on HEAD → index (a text tab's lines go to the index's through the index → buffer diff, as `unstage_line`; no save needed). Revert puts the index's lines back for the picked changes in the work tree: an open file's buffer through `Buffer::edit` (one `EditKind::Other` undo step, left unsaved, refused when read-only), a file not open (from a diff tab) rewritten on disk off-thread, refused on `Stale`, its text before kept in the file history as `diff_revert` does.
  - Refusals as hunk staging: binary, conflicted, untracked (revert), symlink (revert), a diff tab of the wrong pair ("These changes aren't staged" / "… already staged"; revert only on Index ↔ Working Tree), a non-git diff tab. Nothing picked: "No changes in the selection".
  - Messages: "Staged 3 changed lines" / "Unstaged …" / "Reverted … (not saved)"; the gutter, Source Control and open diff tabs refresh as after a hunk stage.
  - Done when: in a repo with a file of several hunks, selecting part of one hunk (some added lines, some removed under them) and part of another in a text tab and running Stage Selected Ranges stages exactly those lines (the index blob equals `git apply --cached` of the hand-edited patch), with a dirty buffer saved first; Unstage Selected Ranges on the staged result takes back a subset of them; Revert Selected Ranges undoes only the picked lines in the buffer in one undo step; the same three from an unstaged / staged diff tab's row selection (both layouts, a selection on the left side), including a revert of a file not open; refusals are messages and change nothing.
