  - What it changed (for later work): `wrap.rs` (new) — `Layout::compute(text, width, tab_width)` breaks one line into `Row`s and `Wrap` caches them per view by (revision, width, tab width), mapped through edits, with a printable-ASCII fast path in `row_end` (a 1 MB line lays out within the typing budget); `View` carries `wrap` + `top_row` (its top is a (line, sub-row) pair, `set_top`; `wrapping`/`revision`/`tab_width` written by drawing) and scrolls / reveals on rows; sessions store the top's sub-row (`top_row`, `#[serde(default)]` so older files read the line's first row)
  - Also: `row_end`'s ASCII fast path (a combining mark after an ASCII byte falls back to the grapheme walk, so `e` + combining accent is never split); the lightbulb maps its line to a screen row via `ui::mod::line_screen_row`
  - Deferred: toggling wrap reinterprets a within-row `goal` column for one move (VS Code does too; noted in soft_wrap-e)
  - Still to check by hand: typing in the 1 MB line in a real terminal within the frame budget; a popup / hover anchored on a continuation row near the bottom of the screen; wide / CJK glyphs wrapping in a real terminal
  - Needs: the editor view and drawing (`ui::editor`), its scroll bar, mouse hits, sessions (the view's top)
  - The view stops assuming one screen row per line: a wrap layout per view (rows per line, byte ↔ (row, column)), used by drawing, scrolling, the scroll bar, mouse hits, popups and the find widget
  - `word_wrap` setting and "View: Toggle Word Wrap" (Alt+Z)
  - Done when: with wrap on, a Markdown file of long paragraphs and a 1 MB minified JSON file show every character without horizontal scrolling; Up / Down / Home / End / PageDown, click, drag and the scroll bar work on wrapped rows; resizing a split rewraps it with the cursor kept in view; typing in the 1 MB line stays within the frame budget; toggling off returns to the unwrapped view at the same cursor
