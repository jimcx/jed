Make a file's location easy to find and use from where it is open. Hovering a tab shows where the file lives; right-clicking a tab or the editor opens a small context menu with copy-path and reveal actions. The first context menu in jed, so it is built as a reusable widget.

  - Needs: `app/mouse.rs` (`right_click`, `HitMap` hits for tabs and the editor), `ui/tabs.rs`, `explorer_path_commands` (the copy-path / reveal commands and their `Clipboard::write` and `open -R` / `xdg-open` plumbing, reused as they are), `workspace` root handling, a new `ui/context_menu.rs` + `app/context_menu.rs` ([adding a command](../docs/dev/conventions.md#adding-a-command-end-to-end))
  - Tab tooltip: pointer resting on a tab (a short delay, ~500 ms, driven by the existing tick; cleared by any move off the tab, click, key or scroll) draws a one-line tooltip under it with the file's path relative to the workspace root, `/`-separated; a file outside the workspace shows its full path; an untitled buffer shows nothing; a diff / commit / hex tab shows its file's path as for a file, a shell or task tab nothing. Path text comes from one helper shared with the copy commands, so tooltip and clipboard agree.
  - Context menu widget: a list of labelled items with an optional keybinding hint, opened at the pointer (kept inside the screen), closed by Escape, a click outside, a scroll or focus change; Up / Down / Enter and mouse hover / click choose an item; a disabled item is drawn dimmed and skipped. Items are `Command`s (`Copy + Hash` stays), so each runs through `execute` and is also in the palette. It takes the keys while open (a `Context`), and a `HitMap` entry per item.
  - Items, for a tab and for the editor alike: "Copy Relative Path" (to the workspace root; the full path when outside it, as the tooltip), "Copy Path" (the full path), "Reveal in File Manager" (macOS "Reveal in Finder", Linux "Open Containing Folder"; the label follows the platform). All three go to the system clipboard / file manager through the `explorer_path_commands` commands acting on the right-clicked file, which a tab right-click activates first (as its "File History: Show" does today). Nothing for an untitled buffer (items disabled). The tab menu keeps "File History: Show" as an extra item, and the editor menu is the place later items (cut / copy / paste) can join.
  - Done when: resting on a tab of a workspace file shows its repo-relative path and on a file outside the workspace its full path, gone on moving away; right-clicking a tab opens the menu at the pointer, "Copy Relative Path" / "Copy Path" put the right text on the system clipboard (checked through the `Clipboard` test double) and "Reveal in File Manager" runs the platform opener off the UI thread, failures reported with `notify`; right-clicking inside the editor opens the same menu for the active file, without moving the selection; Escape / outside click dismisses; an untitled buffer's items are disabled; the new commands are in the palette and keymap `defaults` (unbound) with `terminal_docs_list_every_cmd_binding` still passing. Tests drive it headlessly (`mouse`, `press`, `settle`, `TestBackend` drawing).
  - Deferred: tooltips on other widgets (explorer rows, status bar), file size / modified time / encoding in the tooltip, cut / copy / paste and other editor menu items, context menus for the explorer, Source Control and panel rows, a right-click menu on a diff view's body
