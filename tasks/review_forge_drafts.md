Today a saved comment is a local draft (`review_drafts::DraftStore`, `review-drafts.json` in the state directory). Nothing reaches the forge until Submit Review posts every draft at once (`Forge::submit_review`). Each forge has its own pending review: GitHub's PENDING review, GitLab's draft notes and Gitea's PENDING review. A draft kept there survives on another machine, is visible on the merge request's web page ("Finish your review" / "N pending comments") and can be finished from either side. This task makes the forge's pending review the place a saved comment goes. The local store stays as jed's record of each draft's lines and text (drift checks, held back drafts) and as the fallback when the forge can't be reached. Three subtasks in order, one commit each.

  - Needs: the forge layer (`jed/src/forge/mod.rs` `Forge`, `DraftComment`, `DraftReview`, `SubmitOutcome`, the three adapters, `fake.rs`), writes (`jed/src/review_write.rs` `Job`, `jed/src/app/review_write.rs`), the draft store (`jed/src/review_drafts.rs` `Draft`, `DraftStore`), the composer and PENDING (`jed/src/app/review_comment.rs`, `jed/src/review_blocks.rs` `COMMENT_LABEL` / `ComposerButton`, `jed/src/ui/review.rs`), the lookup (`jed/src/review.rs` `lookup`, `Drafts`), Claude's review tools (`jed/src/app/claude_review.rs`), settings ([adding a setting](../docs/dev/conventions.md#settings)), user docs `docs/forges.md`, forge notes in [mr_review](mr_review.md)

  - **Claude never posts** ([conventions](../docs/dev/conventions.md)) stays true. A draft with `by_claude` set is never pushed to the forge when it is made. It stays local, tagged `claude` in PENDING, and reaches the forge only through a user action: the user's Submit Review, or the user editing and saving it. `claude_ide_no_query_or_tool_writes_to_the_forge` must still pass unchanged.
  - Setting: `review.draftsOnForge` (bool, default `true`). `false` keeps today's behaviour exactly (local drafts, posted all at once by Submit Review), and the existing tests run with it off where they assert local-only behaviour.
  - API research first (subtask a), recorded in [mr_review](mr_review.md)'s forge differences and each adapter's `//!`:
    - GitHub: a review created with no `event` is PENDING, one per user per pull request, and may already exist (started on the website): find it in `GET …/pulls/{n}/reviews` (state `PENDING`, the token's user). Add a line comment to an existing one with GraphQL `addPullRequestReviewThread` (`pullRequestReviewId`), and a reply with `addPullRequestReviewThreadReply`. Check which commit a thread added to an older pending review is anchored on. Edit and delete with `updatePullRequestReviewComment` / `deletePullRequestReviewComment`. Submit with `POST …/reviews/{id}/events` (`event`, `body`), discard with `DELETE …/reviews/{id}`. The pending comments come from `GET …/reviews/{id}/comments`.
    - GitLab: draft notes (`POST / PUT / DELETE …/draft_notes[/{id}]`, `GET …/draft_notes`), replies with `in_reply_to_discussion_id`, resolve with `resolve_discussion`, publish with `bulk_publish`. Approve stays a separate request after the publish.
    - Gitea: check whether `POST …/pulls/{n}/reviews` with `event: "PENDING"` adds to the user's existing pending review or refuses a second one (the server's `CreateCodeComment` reuses the current pending review). Submit with `POST …/reviews/{id}` (`event`, `body`), discard with `DELETE …/reviews/{id}`, list with `GET …/reviews/{id}/comments`, and edit or delete one comment through the issue comment endpoints. If Gitea has no way to add a reply to a pending review, reply drafts stay local there and post after the submit as today. Write down the oldest Gitea version that works.
    - A forge that can't do one of these returns an error that says so. The draft then stays local (`local only` in PENDING) and Submit Review posts it the old way.
  - Done when: with `review.draftsOnForge` on, saving a comment in a review diff makes a draft in the user's pending review on each of the Gitea, GitHub and GitLab fakes (and it is listed as pending there); editing or deleting it in jed edits or deletes it there; a draft made on the website appears in PENDING after a refresh and can be edited, deleted and submitted from jed; Submit Review (Comment, Approve, Request Changes, with or without a summary) submits the pending review in one step; Discard Review deletes it; a forge failure leaves the draft local and says why; Claude's drafts never reach the forge until the user submits; with the setting off nothing changes; and `scripts/check` is green.
